# 项目接手指南

这份文件用于让新的开发者或新的 Codex 线程快速接手本项目。

## 一句话目标

做一个长期可维护的工厂 ERP，用审批后的真实需求替代金蝶云星辰全量复刻，先保证业务能跑，再逐步补深。

## 仓库定位

本仓库是 `JDY-复刻-local`（/Users/linzhenyue/Projects/JDY-复刻-local）的**落地实现**。

- `JDY-复刻-local` = 规格层：金蝶云星辰逆向调研，1880 张截图、277 入口、像素级布局、交互组件规范、字段字典、B0-B6 批次、组件复用矩阵、RA/RB/RC 风险台账。**做什么、长什么样、怎么交互、95% 验收以它为准。**
- 本仓库 = 实现层：用什么技术、架构、数据一致性、库存资金底线。**不复述规格，只指向。**
- 目标：功能/前端/操作手感 95% 接近金蝶。

## 当前已确定

- 技术路线：`Java Spring Boot 模块化单体 + Vue 3 + PostgreSQL`。
- 第一版不使用 Java 微服务，但架构必须保留未来拆分服务的可能。
- Redis 第一版只用于登录态/会话，不缓存库存、单据、资金等业务结果。
- 正式前端必须自定义，不能用后台管理页冒充产品 UI。
- 用户原始审批结果保存在 `config/approved-feature-scope.json`；当前执行范围只认由它与 `config/implementation-overrides.json` 推导出的 `config/effective-feature-scope.json`。交付等级见 `config/feature-delivery-status.json`，不能从菜单或历史批次猜测完成度。

## 不要做的事

- 不要重新追求金蝶云星辰 100% 功能。
- 不要把 Django admin、Spring Boot 管理后台或低代码后台当正式产品前台。
- 不要缓存库存余额、单据列表、应收应付余额、审核状态。
- 不要让销售、采购、生产模块直接改库存表。
- 不要把业务规则写在 Controller 或前端页面里。
- 不要在第一版上 Spring Cloud 微服务。

## 当前产物状态

- `outputs/jdy-feature-approval/JDY复刻功能审批表.xlsx`：用户已审批。
- `config/approved-feature-scope.json`：原始审批结构化快照。
- `config/effective-feature-scope.json`：原始审批与实施 override 推导出的当前有效范围。
- `config/feature-delivery-status.json`：按 scope ID 记录 A0-A4、证据和已知缺口。
- `config/regression-manifest.json`：受版本控制的 smoke / area / full 回归清单。
- `docs/01-审批结果复刻范围.md` 到 `docs/03-开发执行顺序.md`：已根据审批结果生成。
- `app/`：静态范围工作台，只用于查看审批范围。
- `backend/`、`frontend/`、`infra/`：正式工程已经存在并持续实现，不能再按“待搭骨架”接手。

## 下一位接手者的第一件事

1. 读取 `docs/09-交接清单.md` 的当前实测快照。
2. 读取 `docs/12-当前批次验收清单.md` 的唯一任务包。
3. 确认 base commit、scope IDs、允许路径、明确不做事项和待决项后再改代码。
4. 先运行 scope/status/manifest 静态门禁；业务改动再按 `docs/11` 选择 smoke、area 或 full。

如果 `pendingUserDecisions` 非空，只允许完成与该决策无关的治理、诊断或缺陷修复，不得继续扩大对应业务功能。
