## 目标

根据用户本次明确决策，完成三个相互独立但可追溯的业务层：

1. 生产计划每条分录可选择是否递归展开 BOM 并生成多层生产任务；自制子件使用其当前已审核、启用 BOM 形成独立任务及直接用料快照。
2. 生产计划每条分录可选择是否为展开范围内的非自制物料生成采购申请；选择状态和来源层级必须可审计，未选行不得生成对应下游。
3. 重构采购申请单为可维护草稿：按物料资料带出默认供应商，允许删除行、修改数量和补录/修改供应商；已审核申请下推时按供应商生成独立采购计划单，缺少供应商的行必须阻断下推。

用户本次要求构成对 F031《采购申请》和 F032《采购计划》的显式范围批准。A170 通过 `implementation-overrides` 记录该决策并重建有效范围；JDY 只作为单据层级、术语和录单效率参考，具体生命周期、tenant、快照和一致性遵守当前 ERP 规则。

## 允许路径

- 生产计划分录选择字段、表单交互、下推 API、递归 BOM 展开和生产任务来源/层级快照。
- 采购申请数据库、应用服务、列表/详情/编辑页面、供应商解析、数量与行维护、生命周期及来源占用。
- 独立采购计划单的编号、数据库、应用服务、列表/详情页面，以及采购申请按供应商分组下推。
- F031/F032 的 scope override、生成范围、目录、权限、交付状态、业务规则、迁移、回归、验收报告与交接文档。
- 复用现有物料/供应商选择器、分录减行、生命周期守卫、BOM 当前版本解析、任务用料快照和 tenant 约束。

## 明确不做

- 不实现库存净需求、库存抵扣、提前期、批量策略、安全库存、工序排程、产能或完整 MRP 运算。
- 不把采购计划偷换为采购订单；A170 不自动生成采购订单、采购入库、应付或库存事实。
- 不改生产领料和产品入库的既有任务快照边界，不让领料运行时直接读取标准 BOM。
- 不自动审核生产任务、采购申请或采购计划；保存仍为草稿，正式下推只允许已审核源单。
- 不混入原 `main` 工作区 A166 未提交改动，不 push；范围外失败按 `record-and-stop` 记录。

## 验收与结论

- 三型号生产计划已逐行验证“多层任务/采购申请”开关；生成三张根任务和一张自制子件任务，父任务、根任务、BOM 层级、来源路径、任务数量与冻结用料均可追溯。
- 非自制叶子汇入一张草稿采购申请；默认供应商回填、删行、改数量、供应商联想/补录、缺供应商阻断及按两家供应商拆分采购计划均通过 API 与真实页面验收。
- V111 已通过升级路径、全新建库、既有 tenant、未来 tenant 和备份 schema 回归；89 张 tenant 托管表及约束拓扑一致。
- A170、A116、A116b、A167 兼容回归、后端定向测试、前端构建、smoke 10/10、scope/status/manifest/docs 门禁与真实浏览器验收均通过。
