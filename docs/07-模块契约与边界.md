# 模块契约与边界

本文用于避免模块化单体后期变成“大泥球”。

## 总原则

- 模块之间通过应用服务或领域事件协作。
- 一个模块不能直接修改另一个模块的数据表。
- 跨模块查询如果只是展示，可以通过只读查询服务；如果会改变状态，必须调用目标模块的应用服务。

## 模块归属

| 模块 | 负责 |
| --- | --- |
| master-data | 商品、客户、供应商、仓库、部门、员工、账户、计量单位、BOM 基础定义 |
| inventory | 库存余额、库存流水、其他出入库、调拨、盘点、库存预警 |
| sales | 销售订单、销售出库、销售退货、销售报表 |
| purchase | 采购订单、采购入库、采购退货、采购报表 |
| production | 生产任务、领料、退料、产品入库、材料报废、齐套、足缺料、MRP |
| outsourcing | 委外加工、发料、入库、退货、委外 BOM、委外费用 |
| finance | 收款、付款、退款、预收预付、核销、对账、资金转账 |
| system | 用户、角色、权限、编码规则、系统参数、操作日志 |
| reports | 跨模块报表和导出 |

## 平台公开与身份恢复边界

A135 固化登录前公开面与认证后路由边界：

- 匿名 `GET /api/system/session` 的响应必须精确为 `{"authenticated":false}`，不得附带用户、角色、账套或路由字段。
- 匿名 `GET /api/system/account-sets` 只返回 `accountSets`，每项只允许 `code/name`；数据库、schema、附件前缀、Redis 前缀、环境和初始化状态等路由信息不得进入公开 DTO。
- 认证后才按当前用户的账套授权返回可选账套和路由信息。公开账套选择项不等于授权，后端路由必须再次校验当前用户与目标账套的授权关系。

请求解析和 username/contact 长度校验通过后，密码找回的所有账号与门禁分支都恒定返回 HTTP 200 与 `{"ok":true,"message":"已提交找回申请，请联系管理员完成身份核验和密码重置。"}`，不得通过状态码、响应字段、响应头或文案暴露账号是否存在、是否命中限流；非法输入仍按参数合同返回 400。内部处理顺序固定为：

```text
POST /api/system/password-reset-requests
  -> Redis Lua 原子检查并计数 global/source/account
  -> 查询启用状态的 sys_user
  -> 同一数据库事务写 sys_password_reset_request 和 PASSWORD_RESET_REQUEST 操作日志
```

- Redis 拒绝或 Redis 不可用必须在进入 JDBC 业务路径前 fail-closed，仍返回恒定公开响应，不得写 request/log。
- 未找到启用用户时数据库零写入；不得为了记录未知账号而创建 request、操作日志或通知数据。
- `source` 只取服务端连接的 `remoteAddr`，不信任 `X-Forwarded-For` 等客户端可伪造头。
- 密码找回发生在账套选择之前，其 Redis key 使用平台级安全前缀，不得套用 tenant/account-set Redis 前缀。
- 公开 Controller 不得直接插入 `sys_password_reset_request`，不得用进程内 Map 代替跨实例门禁，也不得在 Redis 故障时降级为数据库落库。

## 员工主档、登录账号与财务账户边界

A140 固化 tenant 主数据与 platform 身份域的分界：

- `md_employee`、`md_financial_account` 属于 tenant-owned `master-data`；`sys_user`、`sys_user_account_set` 仍属于 platform `system`。
- tenant 表不得外键到平台用户或账套表。员工与登录账号只通过 `sys_user_account_set.employee_code` 显式关联，并在当前 tenant 中校验员工存在。
- 同一用户在一个账套最多关联一个员工，同一员工在该账套最多关联一个用户；员工与账号允许独立存在，员工禁用不级联禁用账号或账套授权。
- 关联与解除只能作用于已认证的当前会话账套。客户端不得提交 `accountSetCode`，必须提交当前 grant 的非负整数 `version` 和随登录/切换账套轮换的 opaque `scopeToken`；`version` 必须是 JSON 整数且能无损转换为 64 位整数，小数、高精度伪整数和越界值一律拒绝。平台库 session-scope 行是唯一安全权威，关联以 `FOR UPDATE` 串行，切换事务提交后才发布 session 快照。旧版本、旧 token、跨账套字段或无当前账套授权都必须零写入失败。
- 撤销某账套授权时，若该 grant 已关联员工，必须在同一平台事务内清空 `employee_code` 并向原 tenant 写 `UNLINK_EMPLOYEE_ACCOUNT`；禁用 grant 不得继续占用员工唯一关联，日志失败必须使授权撤销与解除关联一并回滚。
- 员工 `department` 首版是可空文本，不外键到只表示生产车间的 `md_production_department`，也不伪造公司组织树。
- 财务账户类型限定为 `CASH/BANK/DEPOSIT`，每条记录固定选择 `CNY` 或 `USD`；账号按字符串保存以保留前导零。
- A140 不维护余额、期初余额、汇率、币种换算、多币种账户或跨币种结算；账户被收付款业务消费的闭环属于 roadmap 6B。
- 两类主数据统一走白名单稀疏 PATCH、审核/反审核和启停生命周期，不开放 PUT 或 DELETE；选择器只返回已审核且启用的数据。

## 正式收付款与结算边界

A141 固化 sales/purchase 入口与 finance 事实域的分界：

- F026 销售收款、F036 采购付款只是从销售出库/采购入库预填并打开 finance 正式单据；F080 收款单、F082 付款单的保存、审核、反审核和核销全部属于 finance。
- 收款单/付款单由单据头、资金账户行、核销来源行组成。同一单据可以核销同一往来单位的多张 AR/AP 并使用多条账户行，但资金合计、核销合计和头金额必须相等。
- 保存草稿不修改 AR/AP；审核在同一 tenant 事务内锁定单据和全部来源后才更新 `received_amount/paid_amount`；反审核按本单明细原子释放并回 `DRAFT`。
- CNY/USD 都是原币事实。销售出库/采购入库把明确币种传给 AR/AP；单据头、来源和账户必须同币种，不允许 finance、sales 或 purchase 私自换算。
- `FinanceSettlementController` 只声明 HTTP/权限合同；结算规则集中在 `FinanceSettlementAppService`。sales/purchase 不得直接 UPDATE `ar_receivable`、`ap_payable` 或收付款表。
- V5 旧立即结算记录只读保留，不伪造账户或操作人；旧“调用即结算”入口退役，不能作为兼容后门继续写正式事实。
- 账户余额、期初、汇率、换算、跨币种核销、退款和预收预付仍不属于 A141。

## 典型调用关系

销售出库审核：

```text
sales.application.approveOutbound
  -> inventory.application.issueStock
  -> finance.application.createReceivable
  -> system.application.writeOperationLog
  -> outbox.record(SalesOutboundApproved)
```

采购入库审核：

```text
purchase.application.approveInbound
  -> inventory.application.receiveStock
  -> finance.application.createPayable
  -> system.application.writeOperationLog
  -> outbox.record(PurchaseInboundApproved)
```

生产领料审核：

```text
production.application.approveMaterialIssue
  -> inventory.application.issueStock
  -> system.application.writeOperationLog
  -> outbox.record(ProductionMaterialIssued)
```

产品入库审核：

```text
production.application.approveProductInbound
  -> inventory.application.receiveStock
  -> system.application.writeOperationLog
  -> outbox.record(ProductInboundApproved)
```

## 禁止关系

禁止：

```text
sales.repository 直接 UPDATE inv_stock_balance
production.repository 直接 INSERT inv_stock_txn
frontend 直接决定审核后库存变化
controller 直接拼库存扣减 SQL
sales/purchase controller 或 repository 直接修改 AR/AP 核销金额
收付款 controller 调用即写核销事实
用 USD 账户核销 CNY 来源或做隐式汇率换算
匿名 DTO 返回数据库/schema/附件/Redis 前缀
公开 Controller 直接 INSERT sys_password_reset_request
Redis 门禁故障后继续进入密码找回 JDBC 写路径
```

允许：

```text
sales 调用 inventory 的应用服务
sales/purchase 打开 finance 正式单据或调用 finance application service
reports 做跨模块只读查询
system 统一写操作日志
```

## 事件命名

事件使用过去式，表示事实已经发生：

```text
SalesOutboundApproved
SalesReturnApproved
PurchaseInboundApproved
PurchaseReturnApproved
ProductionTaskApproved
ProductionMaterialIssued
ProductInboundApproved
PaymentApproved
ReceiptApproved
```

事件不应该承载页面字段全集，只传下游需要的业务事实和主键。
