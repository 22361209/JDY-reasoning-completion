# 验收报告-A68-重复登录单一活动会话

- 日期：2026-06-24
- 批次：A68 重复登录单一活动会话
- 范围：登录页、后端 session 校验、系统设置/用户角色、系统设置/操作日志

## 本批目标

正式登录后，同一账号在第二个浏览器上下文再次登录时，旧会话必须被后端判定失效，不能继续调用受保护 API；管理员需要能看到账号活动会话和替换痕迹，操作日志需要留下 `LOGIN_REPLACED`。

## 实现摘要

- `sys_user` 增加 `active_session_token`、`active_session_started_at`、`last_session_replaced_at`。
- 登录成功生成新的 session token，写入用户表和 HttpSession。
- 每次受保护 API 和 `/api/system/session` 校验 HttpSession token 是否仍是当前活动 token。
- 重复登录替换旧 token，并写入 `LOGIN_REPLACED` 操作日志。
- 退出只清理与当前 HttpSession token 匹配的活动会话，避免旧页面退出误清新会话。
- 修改密码清空活动 token，使其他浏览器会话后续请求失效。
- 用户维护页显示当前会话状态和上次替换时间。

## 验收结果

结构化结果：`verification/a68-single-active-session-regression.json`

关键断言：

- 第一个浏览器上下文登录后 `authenticated = true`。
- 第二个浏览器上下文同账号登录后 `authenticated = true`。
- 第二次登录后，第一个浏览器上下文 `/api/system/session` 返回 `authenticated = false`。
- 第二次登录后，第一个浏览器上下文访问 `/api/system/managed-users` 返回 `401`。
- 第一个浏览器上下文回到登录页，提示：`登录已过期，请重新登录。`
- 操作日志存在 `LOGIN_REPLACED` 成功记录：1 条。
- 用户维护页显示该账号当前在线，并显示上次替换时间。

## 风险与后续

- 当前策略为默认单一活动会话：后登录踢旧登录。
- 后续如需要“允许并发/踢下线/管理员配置”三态策略，可在本批 token 基础上增加系统设置项，不需要推翻本批实现。
