# 验收报告 A4：销售订单新增可用化

- 日期：2026-06-24
- 范围：销售订单直达新增、保存、审核、列表回显、已审核状态保护
- 结论：通过。销售订单从首页入口到新增、保存、审核已具备本机员工试用的最小闭环。

## 实现结果

1. 首页“销售订单 / 直达新增”现在会自动生成新草稿单号，不再复用默认 `XSDD-00001`。
2. 表单内“新增”按钮可生成新草稿，默认填入客户、业务日期、部门、经办人和一行商品明细。
3. 表单状态徽标改为真实状态：草稿保存后保持 `草稿`，审核成功后显示 `已审核`。
4. 审核成功后 `保存 / 审核 / 删除` 置灰，保留 `引出 / 打印`。
5. 后端禁止覆盖或删除已审核销售订单，禁止重复审核非草稿销售订单。
6. `/error` 已放行，业务异常返回真实 HTTP 状态码，避免 409 被误显示成 403。

## 验收证据

- 前端：`cd frontend && npm run build` 通过。
- 后端：`cd backend && ./mvnw test` 通过。
- Playwright：
  - 从首页点击 `销售管理 / 销售订单 / 直达新增`。
  - 自动生成单号 `XSDD-20260624-095543633-ZP0`。
  - 点击 `保存` 后成功保存草稿。
  - 点击 `审核` 后页面显示 `已审核` 和 `审核成功`。
  - 截图：`verification/playwright/a4-sales-new-save-audit-1366.png`。
- API：
  - `GET /api/lists/sales-order-form-list?keyword=XSDD-20260624-095543633-ZP0&page=1&pageSize=200` 返回 1 条。
  - 返回行状态为 `已审核`，出库状态为 `未出库`，金额为 `86.00`。
  - 再次 `POST /api/sales-orders/draft` 覆盖该单号返回 `409 Conflict`。

## 剩余风险

- 销售订单详情仍主要依赖当前前端表单对象，尚未做“列表点击打开后端单据详情”。
- 销售订单还未下推销售出库，下一批应打通订单到出库的前端闭环。
- 销售订单 Controller 中仍有 SQL 和业务规则，后续需要下沉到 application/domain。
