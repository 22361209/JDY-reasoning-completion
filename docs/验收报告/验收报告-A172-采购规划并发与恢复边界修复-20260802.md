# 验收报告：A172 采购规划并发与恢复边界修复

## 结论

A172 已关闭本轮 review 指出的五项问题，并在独立复审中额外关闭了“已审核采购订单被并发草稿保存改回草稿”和“采购计划草稿删除无日志/不可恢复提示”两项缺口。采购申请—计划—订单的审核占用、反审核释放、草稿取消、账套恢复及 BOM 仓库有效性现在有一致的事务边界。

## 实现范围

- `PurchaseOrderAppService`：订单审核先锁自身，再按来源申请 UUID、来源分录 UUID 的确定顺序锁定；获锁后重新汇总已审核订单、校验剩余量并回写 `ordered_qty`。草稿 upsert 仅允许命中当前 `DRAFT`，等待审核后重新判定失败时明确返回 409。
- `PurchaseRequisitionAppService`：审核、反审核、保存和下推共用申请头→分录锁序；反审核获锁后查已审核计划/订单权威事实，不再依赖未锁定的缓存占用。重新下推仅选取还没有采购计划分录的来源行。
- `PurchasePlanAppService`/采购计划页：审核占用、反审核释放和草稿删除统一锁序；新增草稿 DELETE API。页面只在已保存 `DRAFT` 启用删除，确认框说明物理删除不可恢复、编号不复用，成功后清空已删文档并同事务写操作日志。
- `AccountSetMaintenanceService`/V113：所有管理表恢复完成后，按已审核采购计划重算目标 tenant 的 `planned_qty`；V113 对已登记 backup schema 做同样的幂等校正，不改写 V112。
- `ProductionTaskAppService`：采购需求优先继承 BOM 行发料仓，并用共享锁确认仓库仍为已审核且启用；校验失败使整次生产计划下推回滚。
