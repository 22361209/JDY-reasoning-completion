# A127 销售订单关闭口径重定版验收报告

## 目标边界

本轮只收口销售订单关闭口径，不全局废弃行关闭，不删除 `line_close_status` 字段，也不扩展到采购、生产、委外；销售订单行关闭 API 先禁用。

销售订单新业务只暴露整单关闭/反关闭：

- 未关闭：`close_status=OPEN`
- 自动关闭：`close_status=CLOSED` 且 `close_mode=AUTO`
- 手动关闭：`close_status=CLOSED` 且 `close_mode=MANUAL`
- 历史已关闭：`close_status=CLOSED` 但 `close_mode` 为空或未知

## 本轮改动

1. 数据字段
   - 新增迁移 `V81__sales_order_close_mode.sql`，为 `sales_order` 增加 `close_mode`。
   - 未删除任何已有字段，`line_close_status` 保留兼容。

2. 后端规则
   - 销售订单手动关闭写入 `close_mode=MANUAL`、关闭原因、关闭人和关闭时间。
   - 销售订单手动反关闭仅允许 `close_mode=MANUAL`。
   - 全部出库后由执行数量刷新自动写入 `close_mode=AUTO` 和原因 `全部出库，系统自动关闭`。
   - 销售出库反审核/红冲导致未出库数量回升时，`close_mode=AUTO` 的销售订单自动恢复为未关闭。
   - 发货通知可通知量按已审核发货通知占用；草稿发货通知不产生业务事实，不扣减可通知量。
   - 发货通知审核按源销售订单行汇总本单数量，合计超量时审核失败。
   - 本轮追加将“审核按源单行汇总校验”提升为生命周期层通用守卫，销售出库、采购入库、采购退货审核同步接入同一 `BillLifecycleService.guardSourceLineQuantities`。

3. 前端展示
   - 销售订单详情状态章按未关闭/自动关闭/手动关闭/历史已关闭展示。
   - 销售订单列表增加关闭状态、冻结状态列。
   - 销售订单分录表不再突出展示行关闭状态。
   - 销售订单详情下推按钮不再依赖 `lineCloseStatus`。
   - 销售订单列表批量反关闭只允许手动关闭订单。

4. 兼容残留
   - `line_close_status` 字段暂保留。
   - 销售订单行关闭 API 已禁用，其他单据行关闭是否保留另开任务。
   - `BillLifecycleService.guardExecutableSourceLine`、`ConversionService`、`SalesOrderAppService.selectableLines` 中仍保留 `line_close_status` 守卫，作为历史兼容残留。
   - 前端不再暴露销售订单行关闭/反关闭入口；是否全局移除行关闭另开任务。
