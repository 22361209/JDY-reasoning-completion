# 验收报告：A163 P1-3 资金账户与同币种转账发布闭环

## 结论

F087 已达到 `verified / published / A3`。当前 ERP 支持 CNY/USD 资金账户主档及启停，并提供同币种资金转账的草稿—审核—反审核闭环；没有扩展余额初始化、汇率、跨币种转账、预收预付、退款、对账或银行直连。

## 直接证据

- `V109__cash_transfer_document.sql` 建立 `cash_transfer` 与 `cash_transfer_fact`，纳入 tenant 受管表、备份与同步拓扑。最新 public/tenant 分别为 86 个受管表；租户同步约束为 `86 PK / 81 UNIQUE / 180 FK / 105 CHECK`。
- 转账草稿允许金额为零但不产生资金事实；审核要求金额大于零、转出转入账户不同、均已启用且币种相同。审核以 `-12.50/+12.50` 双边事实入账，反审核后的净额为 `0.00`；重复审核得到 409，CNY→USD 得到 409；两条并发审核请求精确得到一个 200、一个 409，且只写入两条审核资金事实。
- `finance.cash_transfer.audit` 保护草稿、审核和反审核写入；无权限用户三类写入均返回 403。审核及反审核写入 `cash_transfer` 精确操作日志。
- A163 自动化创建唯一 CNY 源/目标及 USD 测试账户，完成双视口浏览器取证后通过正式主数据接口禁用三个夹具账户；转账凭证与生命周期日志保留为审计事实。
- A163 以第二账套的真实账户与转账直接验证审核事实只写入该 tenant schema、转账 ID 不会泄露到 public，并在结束时禁用该账套夹具账户；多账套受管表创建、备份/恢复与 A136 操作日志回归均在当前构建下通过。A163 实现没有绕过 tenant、version、生命周期或操作日志协议。

## 门禁例外与最终有效性

首次四次 full 分别暴露并修复了 V109 引入后的历史兼容断言遗漏、未重启的旧后端构建、已关闭 A153 历史编号证据与新增编号规则的精确测试覆盖。每次均记录失败原因、完成定向验证，并取得用户明确授权后再运行替代 full。第五次 full 在当前构建中达到 137/137、`badCount=0`，是本报告用于 A3 收口的最终有效全量证据。
