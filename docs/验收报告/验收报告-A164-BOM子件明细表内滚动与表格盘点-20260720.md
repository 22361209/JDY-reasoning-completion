# 验收报告：A164 BOM 子件明细表内滚动与表格盘点

## 结论

BOM 维护页的子件明细已改为表体内部纵向滚动。实现只为 `.bom-entry-table` 设置视口关联的最大高度，继续使用既有 `TableCore` 的表头/表体分离与 `overflow-y: auto`；未改业务逻辑、共享表格协议或后端。

## 真实页面证据

- 127.0.0.1:5173 的运行中 Vite 服务已读取新组件；无需重启后端。
- 已登录页面的 BOM 表格实测为总高 `360px`、表体可视高 `318px`、表体内容高 `363px`，因此纵向滚动归属于 `.table-core-body-wrapper`，不是页面。
- 页面总高度为 `799px`，低于变更前实测的 `822px`；表头位于独立 `.table-core-header-wrapper`，滚动时保持可见。

## 表格盘点

- 已修复：BOM 维护的“子件明细”。
- 建议下一批实际页面复验后再决定：材料报废单“材料报废分录”。它与 BOM 一样不是 `form-layout` 表单主干的一部分，静态结构上可能让内容高度向页面扩张；本批未改。
- 保持现状：销售、采购、库存通用分录表，生产任务的子件/材料表，委外子件需求，库存期初，来源选择、报表、编号规则及导入预览；这些页面已有受限容器或分页/固定预览区，代码结构不显示 BOM 同类问题。

## 保留边界

本批不把“全站统一最大高度”作为规则。不同页面的头部高度与连续操作需求不同，后续应按候选入口逐页确认后再决定统一或保留页面滚动。
