## Redis 与密码找回持久化

### 固定外部响应

所有账号与门禁分支都精确返回：

```json
{
  "ok": true,
  "message": "已提交找回申请，请联系管理员完成身份核验和密码重置。"
}
```

- HTTP 状态恒为 200；不返回 `matched`、`accepted`、`retryAfter`、限流原因或 `Retry-After`。
- username 最长 80，contact note 最长 240；超长输入由参数合同返回 400，不进入数据库 500。

### 三层原子门禁

- 一段 Redis Lua 同时检查 global/source/account 三类 TTL key；任何一层超限时三类计数都不递增。
- 生产默认：global `100/1m`、source `10/10m`、account `1/15m`。
- source 只取 servlet `getRemoteAddr()`，不信任 `X-Forwarded-For`；source/account 只以 SHA-256 摘要出现在 key 中，contact note 不进入 key 或健康日志。
- 只有 active profiles 全部属于 local/test/regression 才能放宽额度；default、production 与 `local,production` 混合 profile 的放宽配置均在 health 前拒绝启动。
- Redis 超时、断连或 Lua 异常时，在 JDBC 和事务之前 fail-closed；对外仍返回固定 body，只写不含 username/contact/source 的 WARN。

### 数据库状态与并发

- Redis 通过后才查找 platform 用户；未知或禁用账号对 request/log/outbox 零写。
- 已知启用用户在 transaction advisory lock 下重检账号状态、过期、全库 PENDING 上限、数据库冷却和唯一性。
- 同一 `requested_user_id` 最多一条 PENDING；重复申请保留最早 `contact_note/requested_at/version`。
- 全库 PENDING 默认最多 50；72 小时旧 PENDING 转 `EXPIRED`，90 天前终态每批最多删除 500 条。
- 管理员处理使用单条 `UPDATE ... WHERE status='PENDING' RETURNING`；两个管理员并发只有一个状态转换、一个通知和一条成功日志。
- 历史 `requested_user_id IS NULL` 申请不能发送通知。

### Redis 部署限制

`PasswordResetRateLimiter` 当前使用 raw RESP 直接连接 standalone Redis host/port，只支持 DB 0，不支持 AUTH、TLS、Sentinel、Cluster/MOVED 重定向或连接池。这不等于 Spring Session Redis 的能力限制。拓扑不兼容时密码找回 fail-closed，不会形成安全绕过，但会影响生产可用性；高可用与认证加密适配必须另立任务。
