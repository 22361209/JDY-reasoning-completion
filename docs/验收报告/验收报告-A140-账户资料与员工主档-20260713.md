## 数据模型与生命周期

### 员工主档

`md_employee` 保存 `code/name/position/department/phone/email/remark`、启用状态、审核状态、版本与时间戳。编码 tenant 内唯一且创建后不可修改；部门为可选文本，不错误外键到仅表示生产车间的资料。

员工创建默认为草稿；PATCH 只接受 `version + changes` 且区分 absent 与显式 null；审核态编辑、旧版本、重复编码和整体验证失败均 fail-closed。审核、反审核、启用与禁用使用正式动作，不开放删除。

### 财务账户

`md_financial_account` 保存 `code/name/account_type/bank_name/account_no/account_holder/currency/remark`、启用状态、审核状态、版本与时间戳。

- `account_type` 只允许 `CASH/BANK/DEPOSIT`。
- `currency` 只允许 `CNY/USD`，每条记录只能选择一种币种。
- CASH 禁止银行字段；BANK/DEPOSIT 必须填写开户行、账号和户名。
- `account_no` 为字符串，API 与 UI 均保留前导零。
- 不包含余额、期初余额、汇率、换算、多币种明细或结算流水。

生命周期、CAS、PUT/DELETE 405 和失败零副作用与员工主档保持统一。

## 账套员工—登录账号关联

关联接口仅作用于已认证 current session 的当前账套，不接受客户端 `accountSetCode`。请求字段严格且只能是：

```text
employeeCode + version + scopeToken
```

- `employeeCode: null` 表示显式解除；空白字符串拒绝。
- `version` 对平台 grant 做 CAS，且必须是非负 JSON 整数并可无损转换为 64 位整数；小数、高精度伪整数和越界值在进入 service 前返回 400。重复员工、旧版本、草稿/禁用员工和无当前账套 grant 均拒绝。
- `scopeToken` 绑定 session 与当前账套，并在登录及每次账套切换时轮换；A→B、A→B→A 即使两边 grant version 相同也不能重放旧请求。
- 平台库 `sys_session_account_scope` 是 session token、当前账套与 scopeToken 的唯一安全权威；session attributes 只发布当前请求快照，不能充当跨请求锁。
- 关联更新在平台事务内 `FOR UPDATE` 锁住权威行后再校验 token、更新 grant 和写 tenant 操作日志；切换账套更新同一行，因此不同 wrapper 和不同实例也只能串行。
- 权威行更新与 `SWITCH_ACCOUNT_SET` 日志在同一个显式平台事务提交，提交成功后才发布 session id/code/scopeToken；注入日志失败时数据库与 session 都保持旧账套。
- 注入日志写入失败时 grant 与 tenant 日志都保持零写入；session 快照与数据库权威不一致时一律 fail-closed。
- 撤销某账套 grant 时，已关联的 `employee_code` 与授权状态在同一平台事务内更新，并向原 tenant 写带 `source=grant_revoked` 的解除审计；禁用 grant 不再占用员工唯一关联，另一账号可立即复用该员工。
- 日志只记录关系和版本，不记录密码、Cookie、scope token、手机号、邮箱或银行账号原值。

### `allowedPaths` 范围扩展说明

独立 review 指出 scope token 只能在真实登录/切换点可靠轮换，不能由员工关联 service 事后推断；JVM `synchronized(session)` 也不能覆盖不同 Spring Session wrapper 或不同实例。因此 A140 在冻结合同后明确扩展了：

- `backend/src/main/java/com/jdy/erp/system/security/CurrentSessionService.java`
- `backend/src/test/java/com/jdy/erp/system/security/CurrentSessionServiceAccountSetAuthorizationTest.java`

扩展只用于持久化、轮换并锁定账套 scope 及其回归覆盖，没有夹带其他 session 功能。测试用两个不同 `MockHttpSession` wrapper 模拟同一逻辑会话，证明 switch/link 在数据库行锁上确定性串行；同时覆盖每次切换轮换、A→B→A 旧 token、缺 token、严格 version、撤销授权释放关联、原始 session/fallback 不一致和切换事务回滚均 fail-closed。`EmployeeAccountLinkServiceIntegrationTest` 最终 `11/11` 通过。

| 能力 | 读取 | 写入 |
| --- | --- | --- |
| 员工主档/selector | `master.data.manage` 或 `system.role_permission.manage` | 仅 `master.data.manage` |

## 独立 review

V101 修正后的最终结论：**APPROVE，无剩余 A140 范围内 P0/P1/P2。**

独立 review 期间发现并完成以下修正：

- 财务只读角色的前端写动作必须与后端一致禁用；
- A→B→A 直接返回原账套时旧 scope token 仍必须失效；
- session 账套 id/code/token 必须原子发布；
- 员工/账户创建的超长字段必须返回明确 400，不能误映射为编码 409；
- UI 关联请求必须携带 scopeToken 且只能包含三个合同字段。
- 普通 session monitor 不能作为跨 wrapper/跨实例锁，必须使用平台数据库权威行与 `FOR UPDATE` 串行。
- 撤销已关联 grant 必须原子释放员工唯一槽并写原 tenant 审计，不能由禁用 grant 永久占用。
- `version` 必须按 JSON 整数类型和 64 位范围精确校验，不能经 `doubleValue()` 丢失精度后接受高精度小数。
- 权限矩阵必须同时证明独立基础资料管理员、财务只读动作和仓库菜单隐藏，不能只用 API 或管理员截图代替。

最终 review 确认两类主数据、权限矩阵、日志隐私、tenant 隔离、迁移拓扑、数据库权威 scope 和前端通用 registry 路径符合合同。员工关联 `11/11`、当前会话 `7/7`、财务账户 `4/4` 定向测试均通过。

## 已识别的独立架构债

当前运行态仍是 A70 已明确记录的本地 `HttpSession`（cookie 为 `JSESSIONID`），并未达到高层架构文档中的 Redis session 目标。A140 不把该目标伪装成已完成，也不在本批夹带依赖和部署改造。V101 使账套 scope 的并发安全以平台数据库为权威，不依赖本地 session monitor 或 Redis wrapper 身份；自然 timeout/`ALLOW_CONCURRENT` 的过期权威行回收，以及并发 switch 的版本化/CAS session 发布仍是平台 session 专项 P2。它们只能使请求 fail-closed，不能恢复认证或导致 A140 跨账套误写。本批按已确认的自动化 session token 精确清理，最终权威行、A140 switch/405 残留、孤儿 actor 和临时探测日志均为 0；生产多实例 session failover 前，须单独完成 Spring Session/Redis、过期行回收、版本化发布，并以 `SESSION` cookie 和双实例真实并发 HTTP 验收。

最终门禁曾有一轮把 Maven 全测与登录型 area 回归并发执行，`SINGLE_ACTIVE` 互相替换静态账号会话，产生 401 与全局日志快照变化；该轮证据已作废。最终结果全部来自无并发登录干扰的独占串行重跑，两个 area 浏览器偶发也各自重跑至完整绿，不用 full 结果替代 area 门禁。
