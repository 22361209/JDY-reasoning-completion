## 目标

把正式单据的保存、审核、反审核、作废、关闭、冻结、红冲、选源、下推统一到“主状态 + 关闭状态 + 冻结状态”的生命周期协议，避免销售模块打磨出的动作规则在后续模块继续分叉。

本批不新增业务页面，不改库存/财务过账口径，不重跑 `build-jdy-feature-approval.mjs`，不手改生成物。

## 完成内容

1. 后端 `BillLifecyclePolicy` 登记单据能力：
   - 销售订单、发货通知单、采购订单：支持关闭/冻结与行关闭/行冻结。
   - 销售出库、采购入库、生产领料、产品入库：支持红冲，不支持关闭/冻结。
   - 销售报价、采购退货、其他出入库、调拨、盘点、盘盈、盘亏：第一版不支持关闭/冻结/红冲。
   - 作废能力显式登记为 `voidAllowed`，当前已接入正式单据均允许草稿作废；未知或未登记单据默认不允许作废。
2. `BillLifecycleService` 统一守卫：
   - 草稿不能关闭/冻结。
   - 事实类单据不能关闭/行关闭。
   - 源单必须已审核、未关闭、未冻结，源单行也必须未关闭、未冻结，才允许下游执行。
   - `voidBill()` 先按后端策略强校验 `voidAllowed`，不再只依赖前端按钮隐藏。
3. 前端新增 `documentLifecyclePolicy.ts`：
   - 统一状态归一化。
   - 统一状态章显示。
   - 统一关闭/冻结/红冲能力。
4. `DocumentForm`/`StandardDocument` 入口接入：
   - 不支持关闭/冻结的单据不再显示关闭/反关闭、冻结/解冻。
   - 红冲不再跟随反审核能力；只有策略允许红冲的事实类单据显示。
5. `DataListPage` 接入同一生命周期策略：
   - 列表批量关闭/冻结只在连续执行单据显示。
   - 列表作废只允许草稿状态。
   - 批量审核不再是确认后占位提示，而是真实调用对应单据审核 API，成功后刷新列表并显示成功/失败数量。
   - 销售订单/采购订单下推改用统一已审核状态和 `remainingQty` 等数量事实判断，不再依赖 `outStatus` / `inStatus` 中文展示状态。
   - 发货通知单列表补回 `closeStatus` / `frozenStatus`，批量关闭、反关闭、冻结、解冻可按真实行状态判断。
6. 文档更新：

7. A124-L review 补修明确收紧：

   - `REVERSED` 只作为历史兼容/旧数据展示状态，不作为新反审核目标状态。
   - 委外链路新反审核路径已改为回 `DRAFT`。
   - 前端反审核成功提示统一说明“状态回到草稿”。

## 边界

- BOM、生产计划、生产任务、采购申请、委外链路尚未全部接入共享 `BillLifecycleController`，不能表述为“全 ERP 生命周期 100% 完成”。它们后续必须继续按同一协议补齐动作按钮、状态字段、后端守卫和测试。
- 本批没有新增 `execution_status`；`outStatus`、`inStatus`、出库状态、入库状态等继续作为执行事实/展示值，不作为生命周期合法性或按钮可用性的来源。
- 红冲仍只开放给已有红冲服务的执行事实类单据，未新增红冲业务。
- `REVERSED` 仍保留在枚举、列表展示和旧数据兼容里，原因是历史数据可能存在；新反审核逻辑不得再写入该状态。

## 结论

A124-L 已把正式单据生命周期从页面散写推进到前后端统一策略，并在 review 补修中堵住批量审核假按钮、发货通知单状态字段缺失、作废策略前后端不一致、反审核目标不统一、下推依赖展示状态等问题。下一轮 review 可以继续查未完整接入的 BOM、生产计划、生产任务、采购申请、委外链路。
