# 验收报告 A124 BLD 页面协议表头与动作规则收口

日期：2026-06-30

## 目标

继续沿着“BLD 页面统一协议 + 动作按钮注册表 + 表格/表体硬约束”推进，不做泛泛 UI 重构，不改变业务规则。

本批只收两件事：

- 把 `DocumentForm` 单据表头字段接入 FieldRenderer。
- 把 `StandardDocument` 动作状态规则从组件内联判断集中到 `documentActionRules`。

## 完成内容

### 单据表头字段协议

- `DocumentForm` 的客户/供应商编码、名称、业务日期、报价有效期、单据编号、部门、录入人、价格口径、单据备注已改为通过 `FieldRenderer` 渲染。
- `FieldRenderer` 新增 `document` 变体，支持单据表头下划线式字段、查找按钮、原生键盘事件透传和显式 test id。
- `FieldRenderer` 的 lookup 菜单保留旧 `master-selector__menu` / `selected` class，兼容既有 A26 键盘选择回归。
- 新增 `fieldOptions.ts`，把字段选项的 value/label 拆开处理，避免 select 显示文案和提交值混用。

### 动作规则协议

- 新增 `frontend/src/components/actions/documentActionRules.ts`。
- `StandardDocument` 改为通过 `buildDocumentActions(...)` 生成单据动作列表。
- `documentActionRules` 当前集中处理动作可见性、禁用态、危险态入口和旧 test id 映射。
- 保存、审核、反审核、关闭、反关闭、作废、冻结、下推、删除、打印、引出等业务 handler 未改变，仍由当前单据页面/服务承担。

### 协议断言

- `scripts/a115-metadata-definition-regression.mjs` 已增加对 `DocumentForm`、`FieldRenderer`、`documentActionRules` 的扫描断言。
- 新断言覆盖：DocumentForm 必须通过 FieldRenderer 渲染表头字段；FieldRenderer 必须支持 document 变体、原生键盘事件和查找按钮事件；StandardDocument 必须通过 documentActionRules 生成生命周期动作。
