# A126 销售链路日常可用性验收报告

生成时间：2026-07-01

## 验收目标

本轮目标不是新增页面，而是验证销售链路能否按日常业务真实使用：

- 销售报价 -> 销售订单 -> 发货通知 -> 销售出库闭环可走通。
- 销售、仓库职责边界明确：销售单据由销售侧处理，仓库侧可以处理销售出库但不能直接改销售订单。
- 库存即时数、预留数、可用数随发货通知和出库正确变化。
- 部分发货、关闭剩余、冻结暂停、红冲纠错、作废、源单追溯均可用。
- 列表整单/明细视图能看到状态、客户、数量、金额和源单字段。

## 本轮修复

1. 修复发货通知可通知量重复扣减问题。
   原逻辑按“销售订单数量 - 已出库数量 - 已审核发货通知数量”计算，部分出库后第二次发货通知会被误判超量。现改为“销售订单数量 - 已审核发货通知数量”，出库只影响已出库/未出库事实，不重复扣减可通知量。

2. 修复发货通知审核绕过源单关闭/冻结的问题。
   发货通知审核现在会强制校验源销售订单及源行：已审核、未关闭、未冻结、行未关闭、行未冻结。

3. 修复销售出库详情来源字段混淆。
   销售出库分录现在同时保留两层来源：`sourceOrderNo/sourceLineNo` 为原销售订单，`sourceDeliveryNoticeNo/sourceDeliveryLineNo` 为直接来源发货通知。

4. 修复销售出库旧作废入口绕过统一作废确认的问题。
   `/api/sales-outs/{billNo}/void` 已改为走统一生命周期作废，必须提交账号、密码和原因。

5. 收紧销售订单/销售报价草稿保存权限。
   仓库账号不能直接保存或审核销售订单/报价，避免绕过前端按钮直接改核心销售业务数据。

6. 更新旧回归脚本口径。
   A89/A98 改为按新的双来源字段断言；A105 UI 等待顺序改为先确认详情页已切换到目标单据，再等待动作按钮。

## 当前边界

- 当前系统尚无独立 `SALES` 角色/账号，本轮以 `admin/系统管理员` 模拟销售人员，以 `warehouse/仓库员` 模拟仓库人员。
- 本轮不改变销售报价取价规则、打印模板、应收应付或财务核算口径。
- 本轮只收销售链路日常可用性，不把采购、生产、委外链路一起扩展到同等深度。
