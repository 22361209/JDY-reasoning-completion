# 验收报告 A89 销售流修复

## 结论

通过。A89 已修复销售订单详情下推销售出库、销售订单反审核和 A2-A7 销售出库列表导航回归；未改财务口径、未改单据编号、未回退 A88 盘点链。

## 修复内容

- 销售订单详情工具栏新增“下推销售出库”按钮：仅 `已审核` 且分录仍有剩余可出数量时显示，点击复用既有 `openOutboundFromSalesOrder` 下推确认流程生成销售出库草稿。
- 销售订单反审核恢复：前端销售订单模块启用 `reversible`，后端新增 `/api/sales-orders/{billNo}/reverse`，反审核用 `BillLifecycleService.transition(sales_order, AUDITED, REVERSED)`；有已审核销售出库下游单据时返回 409 阻断。
- 补 Flyway `V38__sales_order_reverse_timestamps.sql`，为 `sales_order` 增加 `reversed_at`/`voided_at`，匹配 `BillLifecycleService` 对 `REVERSED` 状态的时间戳语义。
- 新增 `scripts/a89-sales-order-detail-pushdown-regression.mjs` 和聚合 runner `scripts/run-a2-a89-regression.mjs`。

## 根因

销售订单反审核异常不是 `BillLifecycleService` 状态机失效，而是销售订单迁入通用文档模块后缺了两段接线：

- 前端 `useSalesOrderDocument` 未设置 `reversible: true`，详情页反审核按钮不可用。
- 后端 `SalesOrderController` 没有 `/reverse` 端点，`SalesOrderAppService` 也没有调用骨架生命周期服务执行 `AUDITED -> REVERSED`。

补齐后，销售订单反审核保持骨架语义，并在应用服务中先检查已审核下游销售出库，避免源单在已有执行单据时被反审核。
