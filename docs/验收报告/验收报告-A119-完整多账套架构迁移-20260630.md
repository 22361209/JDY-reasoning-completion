# 验收报告 A119：完整多账套架构迁移

- 日期：2026-06-30
- 范围：平台账套层、请求级账套上下文、tenant 路由、账套初始化、业务模块隔离、前端账套切换、账套运维、总回归。
- 结论：通过。A119 已完成从单账套上下文过渡到 schema-first 多账套架构；共享前端/后端/Redis/PostgreSQL 容器不随账套切换启动或停止，业务请求按当前账套上下文进入独立 `tenant_*` schema。

## 已完成

1. 平台层与登录授权：
   - 平台侧维护账套、用户到账套授权、默认账套和启停状态。
   - 登录页和登录 API 均显式选择账套；无授权账套无法进入业务 API。
   - 回归脚本公共登录 helper 已显式绑定 `BLD-TEST`，避免多账套后 API 造数和浏览器登录进入不同账套。
2. TenantContext 与数据路由：
   - 业务接口必须带登录账套上下文。
   - 默认业务 `JdbcTemplate` 按账套路由；平台用户、账套、授权、登录入口走平台连接。
   - Redis key 和附件路径已有统一账套前缀入口。
3. 账套初始化和运维：
   - 支持新建账套、初始化当前账套、清空当前账套业务数据。
   - 支持当前账套 schema-first 备份/恢复、启用/禁用和资源前缀查看。
   - 操作日志记录账套编码和账套名称。
4. 业务隔离：
   - 主数据/BOM/编号、库存、销售、采购、生产、委外、报表/打印/导出/模板均已补两账套同码同单号不串账断言。
   - 两个账套可存在相同物料编码、客户/供应商编码、BOM 编码和单据编号流水，库存、选源、下推、汇总互不影响。
5. 前端体验：
   - 登录页可选择账套。
   - 右上角账号菜单和工作台账套区可切换授权账套。
   - 切账套前发现未保存业务页签会提示；确认后关闭/刷新业务页签并回到目标账套首页。

## 当前边界

- A119 当前为 schema-first 过渡：平台表在 `public`，业务数据进入独立 `tenant_*` schema；最终 `platform_db + tenant_* database` 的 Flyway 拆分仍是后续架构演进，不在本批假装完成。
- 本批不做每账套一套应用容器；容器只负责部署和扩容，不负责账套隔离。
- 本批不做外部对象存储，只建立附件路径按账套前缀的统一入口。
- 本批不新增应收应付、成本核算、MRP 深化、工序派工等新业务。
