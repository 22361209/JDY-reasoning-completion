## 正式事实与生命周期

V103 新增 `sales_return`、`sales_return_line`、`sales_return_receivable_allocation`，并为 `ar_receivable` 增加 `return_offset_amount`。退货头、来源快照、财务分配与原应收保持可追溯关系，不创建负应收掩盖未收余额。

- 新增草稿由 `NumberingService` 生成 `XSTH` 单号；修改草稿使用 64 位 version CAS，旧版本 409 且页面保留未保存输入。
- 每行只接收 `sourceOutNo/sourceLineNo/qty/lineRemark`；数量必须大于 0、最多 4 位小数，同一来源行不得重复。
- 审核事务按稳定顺序锁退货头、来源出库头/行与 AR，并重新计算正式可退量；重复审核幂等。
- 草稿可删除和受控作废；关闭、冻结、红冲、换货与退款动作不属于销售退货单能力。
- 已有非 `VOID` 销售退货时，来源销售出库不得反审核或创建红字；已有非 `VOID` 红字时不得保存或审核销售退货。
- A126 暴露的反审核提示回退已修复：保留来源头排他锁与竞态保护，同时恢复“不能反审核”的既有业务原因；辅助守卫单测、服务集成测试和 A126 真实 API/UI 流程均通过。

## 财务与库存验收

财务副作用集中于 `SalesReturnFinanceAppService`，sales 不直接写应收、收款或待退款关系。

| 场景 | 验收结果 |
| --- | --- |
| 未收 CNY | 退货金额全部写入 `return_offset_amount`，AR 进入部分/全部结清状态 |
| 部分收款 | 退货先冲未收，本次实测 `169.50 = 113.00 offset + 56.50 pending refund` |
| 全额收款 USD | 退货全额形成待退款事实，币种保持 USD，未生成实际退款单 |
| 收款选择器 | `unsettled = amount - received - return_offset`，不再重复暴露已冲销余额 |
| 收款反审核 | 有有效退货分配时 409；先反审核退货后才可继续 |
| 退货反审核 | 精确恢复 AR、待退款与库存；较早分配不能越过较晚分配释放 |

库存审核只增加原出库仓现存量和可用量，不恢复销售预留；反审核精确扣回。库存不足和财务下游守卫均在事务内失败，单据状态、库存、AR、待退款和成功日志保持不变。

## 并发与失败安全

- 两张竞争草稿各退 `0.75`、来源仅可退 `1.00`：实测响应为 `200/409`，胜者 AUDITED、败者 DRAFT，只有胜者库存与财务副作用生效。
- 收款审核与退货审核竞争同一 AR：使用同一排他锁顺序串行，最终 `received + return_offset = amount`。
- 保存退货与来源反审核竞争：退货草稿胜出后来源反审核 409。
- 保存退货与创建红字竞争：红字草稿胜出后退货保存 409；不存在双重反向事实。
- 零金额审核、超退、重复来源、混客户、混币种、库存不足、已退款下游和 LIFO 违反均验证失败回滚。

## 权限、日志与 tenant 隔离

第一版按项目既定粗粒度权限复用 `sales.out.audit`：管理员和仓库角色可维护，无权角色 403，匿名 401。CSV、HTML 打印和 PDF 均在 JDBC 业务读取前执行相同权限校验；菜单隐藏不代替后端拒绝。

成功日志覆盖创建/修改、审核、反审核、删除和作废，记录真实 actor、账套、状态、币种、数量、金额、冲应收与待退款摘要；权限、状态和业务失败进入统一失败审计，不伪造成功日志。

public `BLD-TEST` 与 tenant `A119UI` 使用完全相同退货单号验证：public 为 CNY/0.25，tenant 为 USD/0.5，详情、列表、来源和日志均只命中各自 schema。
