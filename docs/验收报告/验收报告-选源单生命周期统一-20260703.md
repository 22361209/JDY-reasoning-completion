# 选源单生命周期统一验收报告（2026-07-03）

## 项目边界

- 正式源单剩余量仍由后端 `ListQueryService -> ListQueryAdapter` 计算，负责已审核、关闭/冻结、正式执行量、跨单超量阻断。
- 保存草稿不产生正式全局占用。
- 当前单据未保存前，已从源单拉入的分录属于当前单据本地分配量；同一单据再次打开选源单时，必须扣减这部分数量，避免重复选择同一可用数量。

## 落地方案

- 新增 `frontend/src/app/sourceSelectorLifecycle.ts`，统一管理选源单打开、查询、加载并发、已选篮子、全选语义、底部汇总和本单分配量扣减。
- 销售订单、发货通知、销售出库、采购订单、采购入库、采购退货、委外单据统一接入 `useSourceSelectorLifecycle`。
- 页面只保留四类业务差异：拉取源单函数、源单行唯一键、当前单据已分配量计算、源单行回填当前分录。
- `useSalesOutDocument` 移除弹窗私有状态，只保留“追加发货通知明细到销售出库分录”的业务动作。
- 所有选源单页面关闭、取消和确认成功后统一调用 `sourceSelector.close()`，不再直接改写弹窗 open ref。
- A128 静态扫描新增门禁，禁止页面恢复 `filteredSourceSelectorLines`、页面私有 `sourceLineSearchText`、页面私有已选集合、页面私有全选和 reload 协议。
- A102 回归新增“确认选源后再次打开同一发货通知单不可重复选择已拉入数量”的断言。

## 验收标准

- 选源单候选查询必须走 `fetchSourceSelectorRows` / `ListQueryService`，不得页面私查候选集。
- 弹窗底部“当前明细、剩余合计、已选数量”按最终可见行和已选篮子计算。
- 查询条件变化保留已选篮子；列头取消全选清空全部已选。
- 再次打开弹窗时清空篮子，并按当前单据分录扣减已拉入源单行数量。
- 已拉入数量等于正式剩余量时，该源单行在当前单据再次打开选源单时不展示。
- 初始加载和后续查询存在并发时，新查询结果不得被旧加载结果覆盖。
- 关闭、取消和确认成功后的收口必须经过 `sourceSelector.close()`，确保 pending 查询被废弃、loading 和 message 由生命周期统一清理。
