# 验收报告-A69-重复登录策略配置

- 日期：2026-06-25
- 批次：A69 重复登录策略配置
- 范围：系统设置/安全设置、登录页、后端 session 校验、系统设置/操作日志

## 本批目标

在 A68 默认“后登录踢下线旧会话”的基础上，补齐管理员可配置的重复登录策略：允许同账号多端同时在线，或切回单一活动会话。策略切换必须真实影响后端会话校验，并保留操作日志。

## 实现摘要

- 新增 `sys_setting` 系统设置表，写入 `security.repeated_login_policy`。
- 新增 `system.security.manage` 权限，默认授予 ADMIN。
- 新增 `/api/system/security-settings` 查询和保存接口。
- 系统设置新增“安全设置”入口，管理员可切换重复登录策略。
- `SINGLE_ACTIVE`：保持 A68 行为，后登录替换旧 token，旧会话后续请求失效。
- `ALLOW_CONCURRENT`：重复登录不踢旧会话，旧会话继续可用。
- 新增 `session_generation`，改密和管理员重置密码会递增代次，使所有旧会话失效，不受重复登录策略影响。
- 安全设置保存写入 `UPDATE_SECURITY_SETTING` 操作日志。

## 验收结果

结构化结果：`verification/a69-security-settings-policy-regression.json`

关键断言：

- 切换到 `ALLOW_CONCURRENT` 后，同账号第二次登录不踢旧会话。
- `ALLOW_CONCURRENT` 下旧上下文 `/api/system/session` 仍为 `authenticated=true`。
- `ALLOW_CONCURRENT` 下旧上下文访问 `/api/system/period` 返回 `200`。
- 切回 `SINGLE_ACTIVE` 后，旧上下文 `/api/system/session` 返回 `authenticated=false`。
- `SINGLE_ACTIVE` 下旧上下文访问 `/api/system/period` 返回 `401`。
- `SINGLE_ACTIVE` 下最新上下文访问 `/api/system/period` 返回 `200`。
- 操作日志存在 `UPDATE_SECURITY_SETTING` 成功记录。
- 回归结束后策略已恢复为 `SINGLE_ACTIVE`。
