## Fail-Closed 执行顺序

列表读取统一维持以下顺序：

1. 既有全局安全链完成会话认证。
2. `ListQueryContractRegistry` 对完整 listKey 做精确注册校验；未知立即 404。
3. `ListStubStateGuard` 对已注册 key 执行真实 list-specific 权限；缺权限返回 403。
4. 只有前两层通过后才进入 query service、adapter/provider 和 JDBC。
5. query 与 export 使用同一顺序，不存在导出绕过。

Controller 的职责边界没有重写。Registry、provider、selector 均独立 fail-fast：即使未来前置门禁被误改，也不会恢复销售订单或空集 fallback。

后端 mock 测试进一步证明未知普通 key、伪 master、伪 selector 和三个退役后门在 404 后没有触发权限查询、query service、adapter 或 provider。
