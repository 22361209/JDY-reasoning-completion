# 验收报告-A128-列表查询协议统一-20260701

## 范围

A128 将普通高密度列表的查询入口、参数协议、预设迁移、整单/明细视图搜索语义、视觉按钮和生命周期边界收成统一协议，避免后续新页面重新写筛选栏。

本批覆盖：

- 列表 API 契约更新。
- 新增 `docs/guides/list-query-unification-protocol.md`。
- `ListQueryBar` 普通列表统一筛选条。
- `ListDefinition` 查询元数据归一化。
- `listApi.ts` 不再无条件生成顶部 `status` 参数。
- 后端 `/api/lists/{listKey}` 统一 `ListQueryRequest/ListQueryContract`，多词关键字、通用日期范围、旧 `status` 兼容。
- 销售订单整单视图使用 `EXISTS` 命中明细字段，但结果仍显示订单行。
- A128 静态门禁和浏览器回归脚本。

## 已完成任务

- [x] `keyword` 支持空白分词后的多词 AND、字段内 OR。
- [x] 普通列表顶部 `状态` 下拉废弃。
- [x] 状态、关闭状态、冻结状态统一通过列头 `columnFilters` 过滤。
- [x] `dateFrom/dateTo` 从操作日志专用提升为通用列表参数。
- [x] 普通列表新增 `常用过滤条件` 和 `日期范围` 两个统一入口。
- [x] `常用过滤条件`、`日期范围` 触发按钮与查询区普通按钮共用视觉样式。
- [x] 普通列表移除旧只读 `日期` / `经办人` 展开占位。
- [x] 列表定义统一获得 `searchFields/dateField/supportsQuickDateFilter/lifecycleColumns` 元数据。
- [x] 后端移除旧 `searchFieldsFor/dateFieldFor` 推断函数，查询入口收敛到 `ListQueryRequest/ListQueryContract`。
- [x] 销售订单整单视图可被物料编码、物料名称、规格、客户物料编码、客户订单号、行备注命中，但不展开明细行。
- [x] 旧 `query.status` 预设应用时迁移为 `columnFilters.status`。
- [x] 导出继续复用同一组查询参数。
- [x] A124 生命周期门禁通过，证明查询协议未污染生命周期能力判断。

## 验收结论

A128 已完成协议文档、统一查询栏、后端查询契约、销售订单整单 `existsLine` 搜索、旧参数兼容、门禁脚本、浏览器回归和验收报告。后续新增普通列表必须通过 `ListQueryBar`、`DataListPage`、列表查询契约和 adapter 接入，不能新增页面私有筛选栏、顶部状态快捷筛选或独立按钮视觉。
