# 验收报告 A83 后端单据骨架 + 销售出库迁移

- 日期：2026-06-25
- 范围：`shared/` 单据骨架抽象 + 038 销售出库后端迁移到 `SalesOutAppService`
- 性质：纯结构重构，零业务行为变更

## 抽象清单

1. `BillStatus`：对齐实际状态串 `DRAFT/AUDITED/REVERSED/VOID/RED_REVERSED`，移除与 DB 脱节的 `UNAUDITED/CLOSED`。
2. `BillLifecycleService`：提供 `transition(table,billNo,from,to)` 守卫式状态转换，`UPDATE ... WHERE status=? RETURNING`，0 行抛 409，`version+1`，并写操作日志。
3. `PostingPipeline`：定义 `PostingHook` / `PostingContext`，通过 `InventoryPostingHook` 接入现有 `InventoryPostingService`；`FinancePosting` 仅定义接口，本批未接入财务行为。
4. `ConversionService`：抽出源单已执行数量增减、超量守卫、源单状态 `NOT_OUT/PART_OUT/ALL_OUT` 刷新，承接销售订单 `shipped_qty/out_status` 回写。
5. 共享基建：`LookupService`、`OperationLogService`、`ValidationService` 抽出 lookupId、操作日志、必填/可选文本处理。

## 销售出库迁移

- `SalesOutController` 从 约 424 行收敛到 62 行，只保留路由、权限注解、HTTP 状态和转发。
- `sales/application/SalesOutAppService` 承接 `detail/draft/audit/reverse/void/red-reverse` 编排。
- 保持约束：不改财务口径；不改单据编号，仍由前端传 `bill_no`；不迁其他 5 张单。
