# 验收报告：A171 多层生产采购计划生命周期修复

## 结论

A171 已关闭 A170 二次 review 的四项问题。采购计划在草稿状态不再占用采购申请；审核时才原子占用来源分录，反审核会释放。显式关联的子 BOM 必须仍为已审核、启用且当前版本；非自制采购需求保留 BOM 分录指定仓库。V112 同步修复了已由旧逻辑写入的来源占用数据。

## 实现范围

- `PurchaseRequisitionAppService`：下推草稿计划不写 `planned_qty`；采购申请反审核允许处理无业务事实的草稿计划，并删除这些派生草稿。
- `PurchasePlanAppService`：审核前锁定已审核来源申请并按来源行汇总校验、占用；反审核按同一来源行释放，占用与状态变化处于同一事务。
- `ProductionTaskAppService`：显式 `child_bom_id` 同样要求 `AUDITED + enabled + is_current`；采购需求仓库改为 `COALESCE(BOM 行发料仓, 物料默认仓)`。
- V112：对 public 和既有 tenant 重算 `purchase_requisition_line.planned_qty`，只汇总已审核采购计划。
- A170/A116b 回归补齐草稿、审核、反审核和仓库/BOM 升版状态；A129 支持通过 `JDY_API_BASE` 指向隔离后端。
