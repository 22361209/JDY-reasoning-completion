# 工程规范

## 代码组织

后端：

```text
backend/src/main/java/...
  module/
    controller/
    application/
    domain/
    repository/
    infrastructure/
    api/
```

前端：

```text
frontend/src/
  app/
  modules/
  components/
  services/
  stores/
  styles/
```

## 命名规范

- 数据库表使用小写蛇形命名，带模块前缀。
- Java 类使用清晰业务名，避免 `CommonService`、`BaseBizService` 这类空泛命名。
- 前端组件按业务语义命名，例如 `SalesOrderList.vue`、`BillLineTable.vue`。
- API 路径按模块组织，例如 `/api/sales/orders`、`/api/inventory/balances`。

## 业务规则位置

| 规则类型 | 放置位置 |
| --- | --- |
| 表单必填、显示隐藏 | 前端 + 后端校验 |
| 审核、反审核、库存影响 | 后端 application/domain |
| 库存扣减和余额更新 | inventory 模块 |
| 单据编号生成 | system 模块 |
| 权限判断 | system 模块 + 后端拦截 |
| 页面筛选和排序 | 前端状态 + 后端查询 |

## 测试要求

第一版至少覆盖：

- 库存扣减并发校验。
- 销售出库审核生成库存流水和应收。
- 采购入库审核生成库存流水和应付。
- 生产领料审核扣材料库存。
- 产品入库审核增成品库存。
- 反审核遇到下游单据时阻断。
- 编码规则生成唯一单据号。

## 文档要求

任何新增模块必须同步更新：

- `docs/02-第一版模块边界.md` 中的模块状态。
- `docs/07-模块契约与边界.md` 中的跨模块调用。
- 如新增关键架构选择，更新 `docs/04-架构决策记录.md`。
- 如改变库存、资金、审核规则，更新 `docs/06-数据一致性与库存原则.md`。

## 数据库迁移要求

- 所有表结构变更必须通过迁移脚本。
- 迁移脚本必须可重复追踪，不能手工改库后不记录。
- 当前已选 Flyway，迁移文件放在 `backend/src/main/resources/db/migration`。

## 前端体验要求

- 员工入口必须是产品化前台，不是后端管理页。
- 列表页要支持筛选、分页、行选择、批量动作。
- 单据页要支持表头、分录、保存、审核、反审核、历史单据。
- 复杂表格优先使用成熟表格组件。
- 移动端不是第一版目标，先保证桌面端高效。
