# A173 当前任务包

## 目标

恢复可重复、可解释的回归执行基线：先阻断权限、会话、端口和脏工作区造成的级联假失败，再把已经被现行业务规则、迁移 head 和日期推进淘汰的历史夹具更新到当前合同，最终在单一后端、隔离身份和干净候选提交上运行一次可信 full。

目标是让失败重新表示真实产品或测试合同问题；不得为了变绿而放宽母件、权限、tenant、迁移、生命周期或安全规则。

JDY 不作为本治理任务的需求或视觉参考；本批只校准当前 ERP 已生效的业务合同与回归执行边界。

## 允许路径

- `scripts/run-regression-tier.mjs`、`scripts/helpers/regression-auth.mjs` 及新增的共享回归 preflight/helper。
- A44、A55、A56、A112、A162、A163 的权限、会话、清理和确定性浏览器夹具。
- A2–A7、A40、A46、A53、A64 的产品入库旧夹具；保持“一张生产任务只允许来源母件入库”，并保留混入其他物料必须拒绝的负向覆盖。
- A141、A142、A143、A146、A151 的迁移 head 与静态合同断言；V105–V111 历史 checksum、单次应用和 V111 拓扑仍保持固定。
- `TenantSalesChainIsolationTest` 的过期日期夹具及 `TenantReportingIsolationTest` 的隔离身份/权限前置条件。
- `BLD-TEST/public` 回归所需权限基线的只读快照、受审计恢复和前后校验；不触碰其他账套。
- manifest、当前任务包、交接、验收报告和必要的回归指南更新。

## 实施阶段

1. 建立只读基线：记录当前服务、前端代理、构建 fingerprint、权限矩阵、会话策略和失败分类。
2. 加入 fail-fast preflight：full 运行前确认前端代理与直连 API 为同一后端、必需权限存在、登录有效、目标 tenant 正确且工作区干净。
3. 隔离可变状态：权限测试使用专用临时账套/身份或等价隔离，不再修改共享 ADMIN；浏览器/API 不再用同一用户名制造 SINGLE_ACTIVE 会话互踢；测试后校验共享权限矩阵未漂移。
4. 更新已证实过期的生产、迁移、静态数量和日期夹具；旧功能测试只断言自身合同，全局 current-head/parity 由共享合同集中校验。
5. 定向门禁全部通过后形成干净候选提交，只运行一次 full；范围外真实产品失败按 `record-and-stop` 单独登记。

## 明确不做

- 不修改生产、采购、销售、库存、财务等产品业务逻辑来迁就旧测试。
- 不放宽产品入库母件约束，不把权限 403 改成成功预期，不增加全局等待时间隐藏会话问题。
- 不删除历史回归脚本，不弱化 A153 的 dirty-worktree fail-closed 规则。
- 不修改非 `BLD-TEST/public` 账套数据，不改权限模型，不开放新的测试后门。
- 不顺手修复 full 暴露的真实产品缺陷；出现时单独立项。
- 不 push。

## 验收

- 修改脚本逐个 `node --check`，`node scripts/validate-regression-manifest.mjs` 通过。
- `TenantSalesChainIsolationTest`、`TenantReportingIsolationTest` 和所有受影响后端测试通过。
- A44/A55/A56/A112/A162/A163 及生产、迁移、静态合同目标脚本通过；每阶段只执行一次对应目标门禁。

## 停止条件

- 任一预算达到 70%，或实际执行时间超过 300 分钟。
- 发现 3 个当前范围外的真实产品失败。
- 同一环境基线问题连续 3 次无法建立。
- 唯一 full 已消耗仍出现系统性失败。
- 需要修改产品业务代码、非测试账套或扩大权限模型才能继续。
