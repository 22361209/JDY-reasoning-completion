# 当前任务包

## 目标

修复现场演练发现的采购链断点：已审核采购计划会占用来源采购申请，但采购订单既不能引用采购计划，也不能再从该申请选择同一行，导致“采购计划 → 采购订单 → 采购入库”无法闭环。

本批将采购计划确立为采购订单的正式来源：

- 已审核采购计划可下推生成同供应商的采购订单草稿，并保留计划、采购申请和生产计划来源追溯。
- 采购订单审核按采购计划剩余可订数量校验并写入计划行已订数量；采购申请的已计划占用不得被重复计入已订购占用。
- 采购订单作废、反审核或其他会撤销已审核订单占用的既有生命周期，必须同步恢复计划行可订数量；已有采购入库时保持既有不可逆边界。
- 采购入库继续只从已审核采购订单选源，审核后正常写库存；生产领料必须在采购入库后才能消耗该采购件。

JDY：不作为本批实现参考；以当前 ERP 的采购生命周期、来源追溯、库存过账和 tenant 隔离规范为准。

## 验收

- 采购计划审核后，计划页存在明确的“下推采购订单”动作；一张计划只带入其所属供应商、计划行、仓库、数量、交期和价格快照，不混入其他供应商或计划。
- 下推产生采购订单草稿。草稿不改变采购申请 `ordered_qty`，也不增加采购计划行已订数量；审核订单后，计划行已订数量增加，且不能超过计划数量。
- 采购申请的 `planned_qty` 与已审核采购计划合计一致；由采购计划生成的已审核订单不对同一申请行重复计入 `ordered_qty`。未计划的申请剩余量仍可保留既有“采购申请 → 采购订单”直选流程。
- 采购计划或订单发生会释放来源占用的既有合法撤销动作时，计划行可订数量和申请占用正确恢复；已有已审核采购入库时，不允许破坏来源和库存一致性的撤销。
- 采购订单审核后，采购入库单只可选择该订单的剩余可入数量；采购入库审核后库存增加。计划来源、订单来源与入库来源在单据明细中可追溯。
- 并发或重复审核不会超订：同一计划行并发下推/审核只有合计不超过计划数量的事务可以成功，失败操作不留下部分占用。
- 在隔离测试账套，用两组 run-owned 单据通过可见 Chrome 界面完成：生产计划生成采购申请和生产任务 → 采购计划审核 → 采购订单 → 采购入库审核 → 生产领料 → 产品完工入库。两组均须先完成采购入库再领料；不把旧的“仅生成采购申请”演练计入通过。
