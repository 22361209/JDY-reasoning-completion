### 已锁定决定

1. **文件格式**：只接受 `.xlsx`；不接受 `.xls`、CSV、压缩包或改扩展名文件。
2. **导入语义**：只新增，不更新、不覆盖、不静默跳过。工作簿内编码重复或当前账套已存在同编码，均使整批不可确认。
3. **单批上限**：原始文件最大 `10 MiB`（10 × 1024 × 1024 bytes），单个工作簿最多 5,000 行非空数据；空行不计数。
4. **模板粒度**：八个业务对象各有一个预置模板；一个文件只能导入一种主数据，不支持用多 sheet 工作簿一次写八类资料。
5. **落库状态**：确认成功的资料全部按现有手工新增语义保存为 `DRAFT`、`version=0`。类别、单位、客户、供应商、仓库、员工、账户的 `status` 为空默认启用，可显式填“启用/禁用”；物料模板不暴露现有公开定义之外的 status 列，固定启用。导入不自动审核。
6. **账户币种**：账户资料模板和校验正式支持 `CNY/USD`，不扩展余额、汇率或其他币种。

### 工作簿合同

每个预置工作簿固定包含：

- `导入数据`：唯一数据 sheet；第 1 行为说明，第 2 行为精确表头，第 3 行起为数据。冻结表头、必填列显著标识、编码/账号列使用文本格式。
- `填写说明`：字段含义、必填/可选、默认值、枚举、数值规则、引用前置条件和示例；该 sheet 不参与数据行计数。
- `__meta`：模板类型与版本元数据，隐藏且受保护；服务端校验 `type=A143 对应类型` 与 `version=1`。

格式规则：

- 文件名不是可信事实；服务端同时校验扩展名、OOXML ZIP 签名、工作簿类型、模板元数据、sheet 名和表头。
- 缺少列、未知列、重复列、错模板、额外数据 sheet、公式、宏、外部链接、加密或损坏工作簿均拒绝。公式不取缓存值。
- 解析必须使用有界流式读取并启用 ZIP bomb 防护；除三个固定 sheet 外不遍历任意部件，最多 64 列、5,000 个非空数据行、单元格最多 32,767 字符、解压后总工作簿内容最多 50 MiB，任一上限触发受控 400/413。
- 单元格字符串去除首尾空白；全空数据行忽略；行号始终返回 Excel 的可见行号。
- 编码、电话、税号、银行账号等按显示文本读取并保留前导零；布尔只接受“是/否”或 `true/false`；枚举按模板给定值精确匹配。
- 数值必须为普通十进制，不接受 NaN、Infinity、科学计数文本、公式或负数；小数精度和字段范围必须与手工新增合同一致。
- 服务端只接收白名单字段；系统 UUID、系统编号、审核状态、版本、创建人、创建时间不能由文件指定。

### 八类模板字段

以下字段名是 API/标准化键；工作簿显示中文列名并由 `MasterDataImportDefinitionRegistry` 维护唯一映射。`*` 为必填，未列字段不得导入。

| 类型 | 字段 | 固定规则 |
| --- | --- | --- |
| `productCategory` | `code*`, `name*`, `parentCode`, `sortNo`, `status`, `remark` | `sortNo` 默认 0 且为非负整数；code/name 均须唯一；上级编码必须是当前账套已存在类别或本文件内唯一类别编码，不能自指或形成环；确认时按父先子后拓扑创建 |
| `unit` | `code*`, `decimalPlaces`, `sortNo`, `status`, `remark` | 名称沿用 code，因此 code/name 均须唯一；`decimalPlaces`、`sortNo` 默认 0 且为非负整数 |
| `customer` | `code*`, `name*`, `contact`, `phone`, `region`, `address`, `status`, `remark` | 不生成信用额度、结算方式等模板外事实，沿用手工新增默认值 |
| `supplier` | `code*`, `name*`, `contact`, `phone`, `address`, `status`, `remark` | 不生成银行账户、结算方式等模板外事实，沿用手工新增默认值 |
| `warehouse` | `code*`, `name*`, `warehouseType`, `manager`, `address`, `status`, `remark` | 类型为空默认“普通仓”，只允许现有六种仓库类型；本批不开放负库存策略 |
| `employee` | `code*`, `name*`, `position`, `department`, `phone`, `email`, `status`, `remark` | 长度和白名单与 A140 手工新增一致；部门仍为普通文本，不创建登录用户或账套员工绑定 |
| `financialAccount` | `code*`, `name*`, `accountType*`, `currency*`, `bankName`, `accountNo`, `accountHolder`, `status`, `remark` | 类型仅 `CASH/BANK/DEPOSIT`；币种仅 `CNY/USD`；CASH 禁填三个银行字段，BANK/DEPOSIT 三者必填 |
| `product` | `code*`, `name*`, `category*`, `unit*`, `spec`, `netWeight`, `grossWeight`, `surfaceTreatment`, `isSale`, `isPurchase`, `isInventory`, `isProduce`, `isSubcontract`, `purchasePrice`, `costPrice`, `minSalePrice`, `taxRate`, `minStockQty`, `safetyStockQty`, `maxStockQty`, `defaultWorkshop`, `defaultWarehouseCode`, `defaultSupplierCode` | 所有引用只按编码解析当前账套已审核且启用资料；数值按现有字段精度且非负；布尔默认依次为是/否/是/是/否，税率默认 13；默认车间/仓库/供应商可空；单位编码还须能写入物料现有 40 字符快照列；固定启用，不导入隐藏字段、备注或附件 |

固定导入顺序建议为：类别 → 单位 → 客户/供应商/仓库/员工/账户 → 人工审核所需引用资料 → 物料。新导入引用资料仍为草稿，不能在同一个物料文件中被当作已审核引用。

### dry-run 与错误合同

1. `POST /api/master-data/import/jobs/{type}/preview` 创建 tenant 内预检任务，上传字段固定为 `file`。
2. 权限和 tenant scope 必须在读取文件字节、解析 ZIP 或查询业务表之前完成；无权限返回 403 且无任务、业务数据或成功日志。
3. 预检只允许写 `md_import_batch` 工作流事实，绝不写八类 `md_*` 业务表，也不占用业务编码或业务系统编号序列。
4. 每行保存标准化白名单 payload 和结构化 errors：`rowNo/field/code/message/value`；不得只返回一段总错误文案。
5. 错误至少区分：必填缺失、未知/重复表头、类型错误、非法枚举、越界、文件内重复编码、账套内既有编码、引用不存在/未审核/已禁用、类别父级环。
6. 任一文件级或行级错误使任务状态为 `INVALID`、`canConfirm=false`；合法任务状态为 `VALIDATED`、`canConfirm=true`。两种结果都可查询和下载 `.xlsx` 错误回执。
7. 响应返回 job id、类型、模板版本、文件名、SHA-256、总行数、有效行数、错误行数、状态、过期时间和分页行结果；前端不得自行推断可确认状态。job 列表、详情、行预览和错误回执均只对同一 tenant 的任务创建者可见。
8. 预检令牌 30 分钟过期。过期任务保留结果摘要但清除可提交 payload，状态为 `EXPIRED`。

### 原子确认、重放与并发合同

1. `POST /api/master-data/import/jobs/{jobId}/confirm` 不重新接收文件，只消费服务端保存的标准化预检事实。
2. 仅任务创建者、同一 tenant、仍有 `master.data.manage` 权限且状态为 `VALIDATED` 时可首次确认；跨 tenant 或非创建者按 404 处理，避免泄露任务存在性。
3. 确认先锁任务并在一个 tenant 事务中重新校验全部编码、引用、枚举与数值，再调用与手工新增相同的 application create service。不得从 import service 直接维护第二套 `md_*` INSERT。
4. 任一行在确认时失效，任务转 `STALE` 并保存新的行错误，HTTP 409，八类业务表零写入；预检成功不保证绕过确认时实时校验。
5. 全部行成功后才把任务置 `COMMITTED`，记录完成时间、创建数量和一条批次操作日志。任一数据库/日志错误使全部主数据和成功状态回滚。
6. 同一 job 并发或重复确认只能有一次写入；后续请求幂等返回同一 `COMMITTED` 结果，不重复建档、不重复成功日志。
7. 不同 job、手工新增和导入确认竞争相同编码时，数据库唯一约束仍是最终防线；失败批次整批回滚并转 `STALE/FAILED`，不能留下前半批资料。
8. 任务行按稳定 `rowNo` 顺序创建和记录，不能由 HashMap/请求顺序产生不稳定结果。

### 持久化、tenant 与审计合同

- V104 新增一张 tenant managed 表 `md_import_batch`；必须进入 tenant catalog、fresh/upgrade/repeat/sync/backup/restore 门禁，不能放宽 A137 的 public FK 豁免或精确计数守卫。
- batch 保存 UUID、当前 account-set/user 快照、类型、模板版本、文件摘要、大小、状态、计数、受限标准化 rows JSON、创建/过期/提交时间和 version；状态只允许 `VALIDATED/INVALID/COMMITTED/STALE/FAILED/EXPIRED`，不接受客户端账套、actor 或 schema。
- 批次表不保存原始工作簿和附件；成功或过期后清空可提交 rows payload，只保留摘要、计数、操作者和结果。恢复备份时未提交批次必须强制 EXPIRED 并清空 payload，不能复活旧确认令牌。
- 所有 JDBC 均使用 routed tenant 数据源；不得通过客户端账套参数拼 schema，不得写 public 或其他 tenant。
- 操作日志 target 固定为 `MASTER_DATA_IMPORT`/batch id，记录批次级 `PREVIEW_MASTER_DATA_IMPORT` 与 `CONFIRM_MASTER_DATA_IMPORT` 成功事实、类型、行数、SHA-256 摘要前缀和最终状态；真实 actor 来自 session。不得记录行 payload、账号、电话、邮箱或银行信息原文。
- 解析失败、确认失败和权限失败不得伪装成功日志；需要失败日志时使用既有 failure service，不在回滚事务里写会丢失的失败日志。

### API 合同

### 前端可见合同

1. 八个目标列表的“导入”动作打开同一个 `master-data-import` shell 工作区，不走通用空壳 fallback，不伪造 `/api/lists/*` key，也不新增 catalog owner；从列表进入时预选对应资料类型，重复进入只聚焦唯一页签。

### 模块边界与共享实现

- `MasterDataImportController` 只声明 multipart/HTTP/权限合同；格式、状态机、事务和确认逻辑集中在 application 层。
- `MasterDataImportDefinitionRegistry` 是八类模板列、默认值、枚举和映射的唯一后端定义；模板构建脚本与自动化必须检查其版本/表头一致性。
- 手工 `POST /api/master-data/{type}` 与导入确认统一委托 `MasterDataCreateService`；导入不得调用 Controller，也不得复制一套更宽松 INSERT。
- `MasterDataImportWorkbookService` 只负责不可信 OOXML 的有界安全解析、单元格标准化和错误回执生成，不查询数据库、不写业务表。
- 前端只渲染后端 template/job contract，不另建一份可决定事实的校验规则；前端预判不能替代服务端验证。

### 模板产物门禁

- 八个 `.xlsx` 必须由 `scripts/build-a143-master-data-import-templates.mjs` 使用项目指定的 spreadsheet artifact runtime 生成，禁止手工不可复现编辑。
- 构建后逐个导入检查 sheet/表头/元数据/数据验证/文本格式，再渲染所有可见 sheet 为 PNG 做视觉检查。
- 公式错误扫描必须为 0；预置模板不得含公式、宏、外链或隐藏业务数据。
- 后端测试必须逐个读取 classpath 模板并与 `MasterDataImportDefinitionRegistry` 比对，防止代码、模板和文档漂移。

### 自动化验收矩阵

必须至少覆盖：

| 场景 | 期望 |
| --- | --- |
| 八类最小合法模板 | preview VALIDATED；confirm 后正确新增 DRAFT/version=0，计数与日志一致；物料固定启用，其余状态按模板 |
| CNY 与 USD 账户 | 均成功；其他币种或银行条件错误按行拒绝 |
| 文件内/数据库重复编码 | preview INVALID 或 confirm STALE；业务零写入 |
| 物料错误类别、单位、仓库、供应商、车间 | 精确行/字段错误；整批不可确认 |
| 非法负数、税率、小数位、布尔、枚举 | 精确行/字段错误；整批不可确认 |
| 第 5,000 行与第 5,001 行 | 前者允许，后者拒绝且业务零写入 |
| 10 MiB 边界、错扩展名、伪 ZIP、损坏/加密、公式/外链 | 受控 400/413，无业务写入和信息泄漏 |
| 任一坏行混入合法行 | preview 有错误，确认不可用，八类业务表零写入 |
| preview 后人工占用编码/禁用引用 | confirm 409 并转 STALE，业务零写入 |
| 同 job 串行/并发双确认 | 只新增一次，只记一次确认成功日志，重复响应一致 |
| 无权限用户 | 模板/上传/任务/确认均 403，前端入口不可绕过；账户只读/结算角色也不能导入账户 |
| tenant A token 在 tenant B 使用 | 404；B 不能读取行、文件名、摘要或确认，两个账套数据不串 |
| 同 tenant 其他用户访问 job | 列表不出现，详情/回执/确认 404，不泄露预览中的个人或账户字段 |
| migration fresh/upgrade/repeat/sync/backup/restore | 批次表及约束一致、未提交 payload 不因恢复复活、无 public/tenant 残留 |
| 既有手工新增/PATCH/审核/列表/选择器 | A140 与主数据回归无退化 |
