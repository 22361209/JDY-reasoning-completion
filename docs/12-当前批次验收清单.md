### 用户已确认的决策

1. USER 日志的 `operated_by` 必须非空并等于当前会话 user UUID，同时保存 immutable username 与操作时 display-name snapshot；页面/CSV 显示 `姓名（username）`。
2. SYSTEM/ANONYMOUS 允许 `operated_by=NULL`，但所有新日志必须有非空 `actor_type`；不得创建伪造的系统或匿名 `sys_user`。
3. SYSTEM 显示“系统任务”，ANONYMOUS 显示“未认证请求”，历史空 actor 显示“历史未知”。公开密码找回和失败登录属于 ANONYMOUS，目标账号不是 actor。
4. 记录所有已认证写操作的权限拒绝与已声明业务动作失败；排除匿名 401、探测型 404、密码找回恒定响应等公开噪音。
5. 操作日志按“当前账套 + 明确的平台 scope”查看，不实现动态跨 schema 总账。平台 scope 内提供 ADMIN-only“历史未归属”子视图，显示账套字段为空的旧日志但不回填存储字段。
6. 创建用户、修改用户和修改本人密码纳入 A136 的高风险审计闭环。

### 数据合同

#### 1. Actor 类型

| actor_type | operated_by | 新日志身份字段 | 显示 |
| --- | --- | --- | --- |
| `USER` | 必须非空 | UUID + immutable username + display snapshot | `姓名（username）` |
| `SYSTEM` | 必须为空 | 无用户快照 | `系统任务` |
| `ANONYMOUS` | 必须为空 | 不保存被尝试账号 | `未认证请求` |
| `HISTORICAL_UNKNOWN` | 必须为空 | 不推断 | `历史未知` |

- V97 新增 `actor_type`、`actor_username`、`actor_display_name`、`target_no`、CHECK 与查询索引。
- 历史 `operated_by IS NULL` 只确定性标为 `HISTORICAL_UNKNOWN`；不按 action/module 猜 SYSTEM/ANONYMOUS，不回填 username/display。
- V97 在 current、published V96 与每个 tenant schema 先扫描 `operated_by IS NOT NULL` 且无法关联 `public.sys_user` 的 orphan；数量必须为 0，否则 migration fail-closed 并输出 schema/日志 ID/UUID 清单，不置空 UUID、不伪造用户或 username。
- 历史 `operated_by IS NOT NULL` 且通过 orphan preflight 后可确定性标为 USER，并保存可证明的 immutable username；不得把当前 display name 伪装成操作时快照。缺少 display snapshot 的历史 USER 只显示 immutable username。
- 新 USER 日志必须在写入时保存 display snapshot；用户以后改名不改变旧日志。
- `HISTORICAL_UNKNOWN` 只允许 V97 migration 标记旧行；typed writer 不暴露该创建模式，合同测试要求 A136 后新产生该类型精确为 0。

#### 2. 单一写入边界

- 所有生产 producer 只调用 typed `OperationLogService`；command 必须显式声明 module/action/target/success/actor mode/state whitelist。
- actor 由服务端 request/session 或显式内部 SYSTEM mode 解析，任何请求体 `ownerName/userName` 都不是审计身份。
- writer 根据 `TenantContext` 写当前 tenant 或 platform；平台 scope 固定 `account_set_code=platform`、`account_set_name=平台`，tenant 三字段必须与当前上下文一致。
- 原始 INSERT 只允许存在于 migration、共享 writer 和测试夹具；合同测试扫描生产源码，发现旁路即失败。

#### 3. 前后状态与失败审计

- 生命周期成功动作至少记录受控 `before_state/after_state`，包含对象状态和必要业务事实，不保存页面请求全集。
- 已认证权限拒绝和已声明业务失败用独立事务保存，业务事务仍整笔回滚；失败日志记录 actor、账套、对象、原状态、失败原因，after 为空或明确 unchanged。
- 同一失败不得由 interceptor/advice/service 重复记录；用请求级 audit marker 或 typed failure command 去重。
- 禁止把密码、password hash、session token、contact、webhook secret、通知凭据、附件数据或完整请求体写入 state/reason。

#### 4. 列表、详情与导出

- operation-log 使用专用 SQL adapter，在数据库完成筛选、排序、分页；不得先载入 13 万行再内存过滤。
- 默认只读当前账套日志；ADMIN 可显式选择 platform scope 及其“历史未归属”子视图。历史未归属只查询 platform 表中 `account_set_code` 为空的旧行，不改变存储值，也不得动态 union 全部 tenant schema。
- GET 与 export 的当前账套 scope 要求 `system.audit_log.view`；platform 与历史未归属额外要求 `system.account_set.manage`。匿名全部 401，WAREHOUSE 全部 403，FINANCE 当前账套 200 但 platform/历史未归属 403，ADMIN 三个 scope 均 200。
- 列表、详情、CSV 共享显式 DTO，至少包含 log ID、时间、module/action、actor type、username/display、账套 ID/code/name、target type/ID/no、before/after、status/reason。
- 相同查询参数下列表和 CSV 的日志 ID 集合、顺序、actor、账套、对象、状态和失败原因逐条一致。

#### 5. 备份恢复

- `sys_operation_log` 可进入备份证据，但不得在 restore 时 TRUNCATE 或回插旧快照；备份后产生的日志必须保留。
- restore 成功或失败都追加新的 typed RESTORE 日志；不得删除、覆盖或倒退既有审计。
