### 只读审计基线

#### 1. 公开 API

- 匿名 GET /api/system/session 当前返回完整 tenant Map，包含 databaseName、schemaName、attachmentPrefix、redisKeyPrefix、id、environment、initialized，同时暴露期间和安全策略。
- 匿名 GET /api/system/account-sets 当前返回全部启用账套的完整路由 Map，实测包含 BLD-TEST、A119UI 和 A119OPS 账套。
- 登录页仅使用账套 code/name；认证工作台才使用 id/environment/initialized/period，管理页才使用 schema、附件和 Redis 前缀。
- 前端先拉匿名全量账套、后拉 session；登录成功后没有按当前用户重拉授权账套。WAREHOUSE/FINANCE 的菜单因此残留无权账套，但后端切换仍会 403。

#### 2. 密码找回

- 已知和未知账号对外已是完全相同的 200 body，不包含 matched。
- 当前每次请求都无条件插入 sys_password_reset_request 和 PASSWORD_RESET_REQUEST 日志；未知账号以 requested_user_id=NULL 进入管理员队列。
- 系统无全局/来源/账号限流、冷却、PENDING 去重、最大待处理数、过期或历史清理。
- 管理员列表只返回最近 50 条；垃圾 PENDING 可挤出真实申请。并发处理同一申请还可重复通知和日志。
- 当前本地库 1013 条：DONE 891、REJECTED 122、PENDING 0；这是回归累积证据，不当作生产事故，但证明增长无界。

#### 3. legacy PERSONAL preset

- BLD-TEST/public 共 138 行：136 行 role_code=ADMIN、user_name=本地管理员；1 行 username=admin 现行 PERSONAL；1 行 ADMIN 角色默认。
- 136 行 created_by 全空，preset 相关操作日志为 0；旧 Controller 在创建窗口内硬编码 ADMIN/本地管理员，没有读取真实 session 身份。
- 当前显示名“本地管理员”虽只对应 admin，但 display_name 可修改且不唯一，不能证明历史作者。
- 严格可自动证明归属为 0 条；136 行全部可证明为回归夹具：134 条 A44、2 条 A45。把它们迁成 admin 会把个人 scope 从 1 条膨胀到 137 条。

### 实施合同

#### 1. 匿名与认证 DTO 分界

- 匿名 GET /api/system/session 必须在查询账套和安全策略之前分支，精确返回 authenticated=false。
- 匿名 GET /api/system/account-sets 只返回 accountSets: [{code,name}]，不返回 current、UUID、环境、数据库、schema、附件/Redis 前缀、期间、状态或初始化字段。
- 有效认证后的两个端点保持现有授权路由 Map；管理员 /api/system/account-sets/manage 保持完整管理字段。
- 本批不改 CurrentSessionService、AccountSetController、TenantContext 或现存 A119 账套数据。
- 前端区分 public choice 与 authenticated account-set 类型；登录成功后在展示 shell 前重拉授权列表，登出/失效后重拉公开列表。

#### 2. Redis 三层限流

- 复用现有 Redis，以单段原子 Lua 同时检查 global/source/account 三个 TTL key；任一层超限时不增加任何 key。
- 生产默认：全局 1 分钟 100 次，单来源 10 分钟 10 次，单账号 15 分钟 1 次。参数可由环境变量收紧，不得默认关闭。
- 来源只取 request.getRemoteAddr()，不直接信任 X-Forwarded-For；代理部署需另行配置可信代理。
- source/account 只以 SHA-256 摘要出现于 key；不保存明文 IP、username 或 contact note。三类 key 使用同一 Redis hash tag。
- Redis 超时、不可用或 Lua 失败时 fail-closed：不写 request/log/outbox，只写不含 username/source 的健康告警，对外仍返回统一 200 body。
- local 回归 profile 可提高额度以保持 full 可重复，但不得关闭 Lua、未知账号不落库、PENDING 唯一和保留规则；快测与隔离运行必须验证生产默认额度。

#### 3. 找回申请持久化与处理

- Controller 只做请求解析和恒定响应；频控、账号匹配、去重、上限、过期和保留放到 PasswordResetRequestService。
- 已知、未知、重复、账号冷却、来源限流、全局限流、PENDING 满额和 Redis 故障必须返回完全相同的 HTTP 200 与 JSON，不返回 matched、accepted、retryAfter、限流原因或 Retry-After。
- 只为真实、启用用户创建申请；未知账号不写 request、operation log 或 outbox。
- 同一 requested_user_id 最多一条 PENDING，由 Flyway 部分唯一索引兜底。重复请求不改变首条 contact note、requested_at 或版本。
- 全库 PENDING 上限默认 50。创建链使用 PostgreSQL transaction advisory lock，并在同一事务内重检过期、上限、账号冷却与唯一性。
- PENDING 72 小时后转 EXPIRED；DONE/REJECTED/EXPIRED 保留 90 天后每批最多删除 500 条。清理使用既有 scheduler，不修改旧 operation log/outbox。
- V96 增加 EXPIRED、PENDING 必须有 user id 约束、单用户 PENDING 部分唯一索引和清理索引；旧未知/重复 PENDING 只标记过期，不在 migration 中删除历史。
- 处理申请改为单条 UPDATE ... WHERE status='PENDING' RETURNING；两个管理员并发时只允许一个成功，只产生一个通知和一条成功日志。
- 历史 requested_user_id=NULL 申请不得生成通知。username 最长 80、contact note 最长 240；超长输入返回可预期 400，不进入数据库 500。

#### 4. preset 来源证据

- A135 不执行 display-name 到 username 的自动迁移；严格可证明数为 0，实际迁移数必须为 0。
- 新建 list preset 必须把当前会话 immutable user UUID 写入 created_by；更新旧行不得把当前修改人伪装成原创者。
- 136 行 legacy 的 ID 集、完整行指纹、created_by、scope 和可见性保持不变。
- 当前基线：ID SHA-256 5a87f5cafd4690d7e88b708d0e1e11494e52efedc6f859ee5d8743b3fd63d89a；完整行 SHA-256 dd2ad764fa86a4a41932471e5d3d8f95cf8fb8b7ff8580bd11066c5fef440b3e。
- 新建 creator 验收使用唯一夹具，通过 API 删除并核对全表指纹；不得删除/回插整个 PERSONAL 或 role scope。

### 禁止事项

- 不用 HTTP 429、不同文案、不同 JSON key 或时间提示暴露账号存在性。
