# 当前任务包：P0-1 最终门禁与 A118 夹具恢复

## 目标

在不改变 P0-1 业务范围、生命周期或交付等级规则的前提下，恢复 A118 失败时 fail-closed 保留的五批专属测试夹具，并为 A160 已完成的六类基础资料能力建立一次新的、可关闭的 `full` 最终门禁证据。A160 是历史任务合同，A161 仅接管其关闭证据，不得借此扩大功能实现。

JDY 不参与本任务的业务决策；仅可作为既有页面术语和交互参考，不得据此新增字段、流程或资料类型。

## 允许路径

1. 仅处理以下固定 A118 token：`23FE74D8B7C8`、`86691A5C4381`、`049D0CA37E6A`、`657B4A24B0AC`、`3D2BCD87C511`；恢复脚本必须逐 token 两次读取稳定快照，验证 run 用户、产品、BOM、委外单据、库存流水/余额、操作日志、角色授权和会话范围均满足该 token 的已知语义，且每条待删记录都由精确 UUID 或完整业务键归属。
2. 恢复脚本只可删除已验证为上述 token 所有且未被外部改写的资源；发现未知关联、重复记录、状态/金额/引用不符、非空锁或无法证明归属时立即 fail-closed，保留数据和证据，不执行该 token 的删除。
3. 恢复完成后，对五个 token 分别证明产品、BOM、单据及行、库存流水/余额、日志、用户/授权/会话范围残留均为零；不得使用 `LIKE 'A118-%'`、全表清空或宽泛级联删除。
4. 仅在恢复验收、定向 A118、`smoke`、`area:master-data` 与相关后端测试均通过后，运行一次 `node scripts/run-regression-tier.mjs full`。本任务只允许这一次 full；任何失败按 `record-and-stop` 处理。
5. full 通过后，复核 A160 的六类入口证据，更新交付状态、验收报告、索引、交接清单和路线图历史引用；每项缺直接证据则保持原等级，不得批量抬升。

## 明确不做

- 不改动采购、销售、库存、资金、生产或委外的业务语义，不新增数据库迁移，不回填生产或历史业务数据。
- 不改变现有 P0-1 范围、F ID、有效范围生成链、权限模型、审核/反审核或启停规则。
- 不手工运行无归属验证的 SQL 删除，不按前缀、用户名、日期或表名通配删除；不以关闭任务为由跳过恢复验收。
- 不因 A118 已单项转绿而把 A160 或六项 F 状态提前标为完成。

## 验收

1. 恢复工具仅接受上述五个 token；未知 token、缺失 token、重复 token 或被篡改的资源均拒绝删除并产生可审计证据。
2. 每个 token 在删除前完成两次稳定快照、完整归属和关联链校验；删除后独立查询证明所有受控资源残留为零，且不触碰测试账套外资源。
3. `node scripts/a118-outsourcing-chain-regression.mjs` 通过，且其本轮清理残留为零；后端主数据定向测试通过。
4. `smoke`（10/10）和 `area:master-data`（其 manifest 期望总数）通过；本任务唯一一次 `full` 完整达到 manifest 期望总数且 `badCount=0`。
5. full 通过后，F010/F012/F013/F014/F015/F018 的入口、后端、权限、日志、自动化、浏览器直接证据齐全，才可提升为 `verified/published/A3`；A160 验收报告、索引、交接清单、状态文件与路线图记录同一批次和证据路径。
6. `docs-governance-check`、有效范围合同、交付状态扫描、manifest 校验、`git diff --check` 通过；独立 review 后以不超过 3 个聚焦提交交付，工作区干净。

## 停止条件

- 任一 token 无法完成精确归属验证、恢复导致范围外写入、或 full 失败时立即停止并报告，不运行第二次 full。
- 发现需要改变业务语义、补写历史数据、添加迁移、扩大 F ID 范围，或出现两个以上无关回归失败时停止等待用户决策。
- 达到 180 分钟、4,000,000 tokens、3 个提交或任一未满足验收条件时，不以部分成功关闭 A161。
