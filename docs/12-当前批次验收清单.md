### A4 验收标准

- 有效范围从固定输入连续生成两次，第二次 Git 零差异。
- 所有有效 scope ID 都有且仅有一条交付状态；无重复、无悬空证据、无不存在的 catalog ID。
- 每个 catalog ID 都有且仅有一个 feature owner 或显式 exception；每个 feature 都有且仅有六类 capability checks。
- Excel 行重排不改变 F ID；重复、新增、删除、重命名身份必须阻断导出，不能静默重绑 override/status。
- 未验证、A0 或未开始功能不能作为已发布入口；例外必须有明确 known gap 和待确认项。
- `docs/09` 只有一个当前批次、一个下一步和当前实测状态。
- 本文件中 `## 当前批次` 恰好一次；base commit、允许路径和实际 diff 一致。
- 所有回归脚本均登记或显式豁免；manifest 路径有效、ID 唯一，full 的 expectedTotal 等于 enabled 数量。
- 干净 checkout 不依赖 `verification/a2-a110-regression-latest.json` 即可解析 full 清单。
- CI 重生成 effective scope 和正式前端 featureScope 后必须零差异；不能让 stale frontend 生成物仅凭可编译而通过。
- 前端构建、后端测试、A124、A128、smoke、full 和 `git diff --check` 有真实结果；失败项必须原样记录，不能把旧绿结果当本批证据。
- 验收报告包含日期、范围、账号/环境、通过、失败、阻塞、证据路径、风险和下一步。
