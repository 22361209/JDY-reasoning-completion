# A186 任务包：A185 全量 UAT 缺陷复现、修复与主链重验

## 目标

以 A185 在独立账套 `UAT20260810 / 全量UAT账套20260810` 得到的 8 个已确认问题和 3 个待独立复现观察为唯一输入：先用 Chrome 可见界面对 `UAT-A185-006/007/008` 各做一次完整同步骤复现；随后修复全部确认问题，逐组 review 和定向验收；最后重跑 A185 失败/阻断项，贯通销售订单—发货通知—销售出库—应收/收款，以及采购、生产、委外、库存和资金相关链路。

完成标准不是“代码已改”或“自动测试通过”，而是问题的业务不变量、真实页面操作、相关单号/余额/来源和权限边界同时成立。发货通知必须作为销售主链的显式节点验收，不得被销售订单直出库路径替代或省略。

## 时间、预算与执行策略

- 墙钟时间不设上限。Codex 活跃执行预计 `8–15 小时`：任务包与取证约 20–40 分钟，三项同步骤复现约 30–60 分钟，定位/实现约 2.5–5 小时，定向门禁与 review 约 1–2 小时，真实页面主链重验约 2–4 小时，唯一 full 约 1–2 小时；总量按分项上取整，不以人类工作日估算。
- Goal token 上限 `15,000,000`；最大提交 `10`，但达到 70% 即第 7 个提交时停止并汇报；最终 full 最多 `1` 次。
- 同时只读子代理最多 `3`，加主执行者共 4 个运行槽位；累计子代理不设上限。共享 docs/config、权限目录、迁移和公共组件只由主执行者写入。
- 计划最多使用 `6` 个提交：任务包 1 个、三组实现各 1 个、集成回归 1 个、最终报告/归档 1 个；为第 7 个提交的 70% 强制停止线留出余量，不 push。
- 每个阶段只运行一次相应定向门禁；代码、review finding 和环境均稳定后才运行唯一 full。full 失败不得无授权重跑。

## 强制停止条件

- Goal token 达到 `10,500,000`、提交达到 `7/10`、full 已使用 `1/1` 后又需要重跑、出现 3 个范围外失败，或本任务累计 3 次上下文压缩时停止并向用户报告。
- 发现需要改变已批准功能范围、跨 tenant 清理、粗暴重置账套、改写历史 append-only 库存事实、操作生产环境或扩大为会计总账/成本核算时停止。
- 真实页面无法确认当前账套、Chrome 持续不可用或测试数据所有权不清时停止 UI 写入；单个业务问题阻断时记录并继续其他独立任务。
- 当前 diff 未引入的既有门禁失败只登记，不在 A186 顺手修复。

## 目标门禁

- 静态：受影响前端类型检查/构建、后端目标测试、脚本语法、`git diff --check`。
- 定向：按实际改动模块各运行一次对应 `area:<module>`；共享核心生命周期、库存、来源数量或权限变更必须有后端快测。
- 浏览器：3 个待复现观察的同步骤证据；11 个问题线索逐项给出结论，仅对 8 个已确认问题和 3 项中复现成立者做修后回归；销售订单—发货通知—出库—退货—应收/收款完整链必须有新单号、数量和余额证据。

- 8 个已确认问题与经同步骤确认的观察项均有根因、自动合同、独立 review 和 Chrome 可见结果；未复现项不得为了扩大修复范围而改代码。
