# A184 当前任务包

## 目标

在不扩大四项原始业务边界的前提下，把资金转账详情权限、账户候选分页一致性、A126 回归夹具清理和 A166 可用性遗留分别修复、验收、review 并归档。JDY 不作为本批实现参考；本批只认当前 ERP 的安全、tenant、生命周期和现行 UI 合同。

## 时间、预算与执行策略

- 墙钟时间不设上限；按当前代码面和一次完整 full 估算，Codex 有效执行时间约 `5–9` 小时。网络或门禁排队不从质量目标中扣减。
- Goal token 上限 `15,000,000`；最大提交 `8`；同时只读子代理最多 `3`，累计子代理不设上限。
- 最多运行一次 full。每个编号任务先完成静态 review 和一次针对性门禁；只有四项均收口后才运行唯一 full。
- 停止条件：达到 Goal token/提交/full 预算的 70%、累计出现 3 个范围外失败或 3 次上下文压缩时，按项目执行策略停止并报告。

## 显性任务目录

### 1. 资金转账详情读取权限

目标：`GET /api/cash-transfers/{billNo}` 必须声明并执行 `finance.cash_transfer.audit`，不能继续依赖“已登录 GET 默认放行”。

验收：

- 仅资金转账权限与管理员可读取同 tenant 转账详情。
- 不含该权限的仓库/普通角色返回 `403`，不存在的单据仍只在授权后按原合同返回。
- tenant 隔离、草稿/审核/反审核权限和账户候选最小读取权限不被放宽。
- 权限集成测试与 A163 真实 HTTP 权限矩阵覆盖详情 GET 的 `200/403`。

### 2. 账户候选多页一致性

目标：`financial-account-settlement-selector` 的多页读取必须使用服务端签发、绑定 tenant/查询条件/候选集合的稳定快照或等价游标；不能只用 `offset + total` 判断一致性。

验收：

- 首屏返回不透明快照标识；后续页必须携带同一标识，参数、tenant 或候选集合变化时 fail closed 并提示重新加载。
- 覆盖页间“删 1、增 1且 total 不变”、更新候选资格、重复/遗漏、伪造或跨查询复用标识。
- 正常单页和多页候选、错误/空态/重试、同币种过滤继续可用；保存和审核的后端复验保持不变。
- 协议只用于最小资金账户候选，不扩展账户资料读取/维护权限，不引入跨币种转账。

### 3. A126 回归夹具清理债务

目标：为 `scripts/a126-sales-daily-usability-regression.mjs` 建立 run-owned、fail-closed、异常也执行的完整清理；对可证明属于历史 A126 的残留使用显式清单和事务守卫恢复。

验收：

- 运行前捕获所有会被测试改变的库存、余额、单据、来源关系和日志边界；运行后按依赖顺序精确恢复，不用前缀模糊删除或简单库存相减。
- 主流程任一点失败时仍执行 cleanup，并聚合主错误与清理错误；所有权、CAS、锁和零残留校验在提交前完成。
- 历史恢复只处理能够由单号、批次、来源、actor/备注及库存流水语义共同证明的 A126 事实；证据不完整即停止，不删除。
- 修后 A126 定向、A136/相关清理门禁和 `area:sales` 通过；不改写 A144–A153 历史报告。

### 4. A166 列表布局与物料—BOM 录入可用性

目标：对已进入当前主线但从未正式归档的 A166 变更重新做现行代码 review、补缺和真实页面验收，而不是假定旧分支已完成。

验收：

- 标准列表的列设置、明细切换和更新库存位于动作栏右侧，原工具行不再额外占高；既有 testid 与行为不变。
- BOM 母件只允许已审核、启用、可自制物料；支持输入联想、键盘选择和 `...` 整列表选择，准确回填名称/规格/单位/默认仓库，后端继续复验。
- 物料名称可从前台维护；未命中时经确认新建，保存并审核后返回来源物料页、刷新并选中新名称。
- 物料列表/选择器在加载期间显示加载态，不误显示业务空数据；库存期初新增行连续输入编码/仓库不丢焦点且保存同步余额。
- 前端构建、`smoke`、`area:master-data`、`area:production`、`area:inventory` 及真实 Chrome 关键路径通过。
