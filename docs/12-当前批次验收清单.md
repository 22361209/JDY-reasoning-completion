## 当前批次：A140 账户资料与员工主档

### 任务坐标

- 本批只处理 roadmap 6A、F016、F017，目标 A3。
- A139/item 6 已达到 A4；开工基线固定为 `20e35248`。
- 账户资料归 master-data；员工主档与 system 平台登录用户分离。
- 6B–6E 只读预审可并行，但不得夹带收付款单、销售退货、Excel 导入或报表实现。

### 已确认现状

1. F016 目前只有 `sys_user`、角色、账套授权和登录闭环，没有独立 tenant 员工主档。
2. F017 尚无独立账户资料表、API、列表、编辑页或选择器。
3. `sys_user` 与 `sys_user_account_set` 属于平台域；tenant 业务表不得直接外键到平台用户，否则未来独立 tenant 数据库无法迁移。
4. 当前受管 tenant schema 为 72 张表；新增两张 master 表后必须同步注册表、provisioner、A137 结构门禁和所有 fresh/upgrade/restore 证据。
5. 现有 `MasterDataController`、`MasterDataPatchService`、`DataListPage`、`MasterDataRecordPage`、字段 registry 和 `ActionBar` 可复用，不允许另写一套 CRUD 页面。
6. `MasterSelectorDialog` 对未知类型仍回退到商品列表；A140 增加员工/账户选择器时必须顺带改为 registry 精确解析并 fail-closed。

### 已确认的三个决定

用户于 2026-07-13 明确确认：

1. **员工—账号关系**：一个用户在一个账套最多关联一个员工，同一员工在该账套最多关联一个用户；员工与账号允许各自独立存在；员工禁用不自动禁用账号。
2. **员工部门**：首版使用可选文本 `department`，不外键到 `md_production_department`，因为后者只代表生产车间，不能承载销售、采购、财务等组织。
3. **财务账户边界**：首版支持 `CASH/BANK/DEPOSIT`，每个账户固定选择 `CNY` 或 `USD`；不维护余额、期初余额、汇率、币种换算或跨币种结算。A140 交付正式选择器，真正被收付款单消费留到 6B。

### 数据模型

#### 员工主档

`md_employee` 为 tenant-owned 主数据，至少包含：

- `id/code/name/position/department/phone/email/remark`
- `enabled/audit_status/version/created_at/updated_at`
- tenant 内 `code` 唯一，编码创建后不可修改
- `audit_status` 只允许 `DRAFT/AUDITED`
- 手机、邮箱均可空，不保存登录密码或平台角色

员工登录关联不放在 tenant 表。平台 `sys_user_account_set` 新增可空 `employee_code`：

- 现有 `(user_id, account_set_id)` 唯一约束保证账号在账套内最多一个关联值
- 新增 `(account_set_id, employee_code)` 非空条件唯一索引，保证同一员工不被多个账号关联
- 不建立跨 schema FK；关联/解除时在当前 tenant 中显式验证员工存在
- 禁用员工不级联修改 `sys_user.enabled` 或 grant enabled
- 关联接口不得接受客户端传入 `accountSetCode`；账套只能从已认证 current session/TenantContext 推导，目标用户必须已拥有当前账套 grant
- 关联更新携带 grant `version` 做 CAS；跨账套参数、会话与 grant 错配、重复员工或旧版本均拒绝且平台/tenant 零写入

#### 财务账户

`md_financial_account` 为 tenant-owned 主数据，至少包含：

- `id/code/name/account_type/bank_name/account_no/account_holder/currency/remark`
- `enabled/audit_status/version/created_at/updated_at`
- `account_type` 只允许 `CASH/BANK/DEPOSIT`，`currency` 只允许 `CNY/USD`，每条账户记录只能选择一种币种
- `account_no` 使用字符串保存，保留前导零
- CASH 不填写银行字段；BANK/DEPOSIT 必须填写开户行、账号和户名
- 不包含余额、可用余额、期初余额、汇率或多币种明细；不允许一个账户同时声明多个币种

### schema 与迁移合同

1. 新建 `V100__employee_financial_account_master_data.sql`，不得修改 V98/V99 或任何已发布 migration。
2. public 与全部已登记 tenant 同步新增两张表；`sys_tenant_managed_table` 的 restore order 必须正确。
3. 受管表预期从 72 增至 74；PK、UK、FK、CHECK 精确数量只能从真实 V100 DDL 重新计算，禁止先抄预估值。
4. `TenantSchemaProvisioner` 与 A137 门禁同步新数量，并覆盖存量升级、新建 tenant、重复同步、备份恢复和拓扑漂移 fail-closed。
5. tenant 表不引用 `sys_user`、`sys_user_account_set` 或 `sys_account_set`；平台关联只保存 tenant 业务码。

### 主数据生命周期合同

员工和财务账户统一支持：

1. 新增：默认 `DRAFT`，重码 409。
2. 更新：只允许带 `version + changes` 的字段白名单 PATCH；旧 PUT 返回 405。
3. 查看：列表和详情返回真实 `version`，敏感字段按权限处置。
4. 审核：DRAFT → AUDITED；只有已审核且启用记录能进入选择器。
5. 反审核：AUDITED → DRAFT；已被正式业务引用后的阻断规则留到首次消费它的业务批次。
6. 启用/禁用：使用正式 status 动作，不允许通过 PATCH 篡改。
7. 不开放删除动作；不得把“删除”实现成未声明的硬删除或跨域级联。
8. PATCH 旧版本 409，审核态编辑 409，任一校验错误整笔回滚且版本不变。
9. `DELETE /api/master-data/employee/{code}` 与 `DELETE /api/master-data/financialAccount/{code}` 固定返回 405，状态、版本和操作日志均不变化；禁用只能走正式 status 动作。

### 权限合同

- 员工与财务账户维护：`master.data.manage`
- 员工列表/选择器：`master.data.manage` 或 `system.role_permission.manage`
- 财务账户列表/选择器：`master.data.manage` 或 `finance.settle`
- 财务角色只读财务账户，不得新增、PATCH、审核、反审核或启停
- 仓库角色不得读取员工或财务账户
- 未知 list/selector key 继续先 404，再做权限；不得破坏 A139 顺序

读取的 OR 权限必须由显式策略实现并测试，不能用角色名特判或给财务角色补 `master.data.manage`。

### 前端与选择器合同

1. catalog 新增“员工”和“账户资料”两个基础资料入口；F016/F017 同步 owner 和交付证据。
2. 两类页面继续由 registry 驱动，复用 `DataListPage`、`MasterDataRecordPage`、`FieldRenderer`、`ActionBar`。
3. `App.vue` 只能增加通用 registry 能力，不增加员工/账户硬编码路由分支。
4. 列表支持新增、查看、编辑、审核、反审核、启用、禁用；不显示删除按钮。
5. 冲突 409 保留输入并展示后端原因；审核态不可进入可保存编辑态。
6. 员工和财务账户 selector 只返回已审核且启用记录；未知 selector 类型明确不可用，不再回退商品。
7. 用户角色页在当前账套显示 employeeCode/employeeName，支持显式关联与解除；员工禁用后关联仍保留并标示状态，不伪造账号禁用。
8. 账户编号在表格和表单按字符串显示；浏览器截图和可提交证据不得泄露测试之外的真实银行账号。

精确 key 固定为：

- 正式列表：`employee-master-list`、`financial-account-master-list`
- 内部选择器：`employee-master-selector`、`financial-account-master-selector`

四个 key 都必须在 Registry 精确注册并有独立后端权限处置；两个 selector key 不进入 catalog。selector 的 `AUDITED + enabled` 条件由服务端 SQL 强制，query/export 均不得返回草稿或禁用记录，不能依赖前端过滤。未知 `*-master-selector` 继续先 404，不允许后缀通配。

### 操作日志与隐私

- 关联日志记录 user、accountSet、employeeCode 的关系变化，不记录密码、session token 或 Cookie。
