## 已完成：A83 后端单据骨架 + 销售出库迁移（纯结构，零行为变更）

依据：`docs/14-单据平台骨架.md` + `docs/04` ADR-010（已签字）。
现状：单据审核/反审核/红冲/下推/过账逻辑全在 Controller、裸 SQL、每单复制；`shared/` 仅 `BillStatus` 枚举且与实际状态串脱节。
本批目标：建共享骨架抽象，并**只把销售出库一张单迁到骨架上证明模式**。**纯结构重构，行为必须完全不变，全量回归绿。**

**本批做（结构）**：
1. `shared/` 建抽象：
   - `BillStatus` 对齐实际状态串 `DRAFT/AUDITED/REVERSED/VOID/RED_REVERSED`。
   - `BillLifecycleService.transition(table, billNo, from, to)`：守卫式状态转换（`UPDATE ... WHERE status=:from RETURNING`，0 行抛冲突，version+1，写操作日志）。
   - `PostingPipeline`：审核/反审核钩子接口；接上已有 `InventoryPostingService` 作库存钩子。**`FinancePosting` 只定义接口、本批不接、不改财务行为。**
   - `ConversionService`：源单已执行/剩余量滚动 + 源单状态 `NOT_OUT/PART_OUT/ALL_OUT`（泛化 `shipped_qty`/`refreshSalesOrderOutStatus`）。
   - 共享基建：`lookupId`、操作日志写入、必填校验工具。
2. 迁销售出库：瘦 `SalesOutController` + 新 `sales/application/SalesOutAppService`，用上述共享服务编排 audit/reverse/void/red-reverse/draft；行为与现状逐字节等价。

**本批不做（留后续批，避免行为变更混入）**：
- 不改财务口径（应收仍按现状，FinancePosting 留接口）→ A85。
- 不改单据编号（仍前端传 `bill_no`）→ A85。
- 不迁其他 5 张单 → A84。
