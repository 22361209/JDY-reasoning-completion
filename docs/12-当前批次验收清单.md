# 当前批次验收清单

本文件一次只保存一个当前任务。A133 的历史事实、命令和结果已固化在 `docs/验收报告/验收报告-A133-G0生产合同阻塞修复-20260712.md`。

## 当前批次：A134 权限 fail-closed、生命周期授权与库存直调收口

### 目标

- 完成路线问题 2：让所有后端写接口都有唯一、显式、可自动检查的访问语义，未声明时由运行时 fail-closed 拒绝。
- 把共享生命周期和单据锁获取按单据类型映射到现有模块权限，禁止低权限用户绕过页面直接改状态或占锁。
- 取消登录前公开员工账号、姓名和角色枚举；登录继续使用账号自由输入，管理员用户维护能力保持不变。
- 生产环境不允许任何角色、包括管理员，绕正式单据直接修改库存；只保留受多重门禁保护的本地测试/回归造数入口。
- 以负向无副作用证据证明：未登录为 401、无权为 403、被拒绝请求不改变状态、版本、库存、资金、预设或成功业务日志。

### 用户已确认的业务决策

- 生产环境不允许库存直调，不提供“生产管理员受控开放”模式，也不保留管理员后门。
- 库存只能由正式业务单据审核动账；本地测试/回归入口不属于生产业务功能。
- A133 已确认的销售订单数量规则继续有效：草稿数量可为 `0` 但不得为负，数量 `0` 不要求原因；审核时每行数量必须大于 `0`。本批不得改写该规则。

### 审计基线

- 基线提交共有 150 个 `POST/PUT/PATCH/DELETE` handler：118 个使用 `@RequirePermission`，32 个没有显式访问语义。
- 32 个缺口精确分为：3 个库存直写、9 个共享生命周期动作、11 个正式单据草稿保存、9 个公共、自助或作用域写操作。
- `/api/system/users` 额外以匿名 GET 公开全部启用员工的 username、displayName 和 role；登录页在认证前把这些数据渲染成候选列表。
- 42 个 full 回归脚本依赖 `/api/inventory/adjustments` 播种 BLD-TEST 库存；内部 `InventoryPostingService` 同时被正式单据审核复用，不能因封 HTTP 入口而停用内部过账。
- `/api/inventory/sales-out` 与 `/api/inventory/purchase-in` 无仓内调用者，却与 adjustment 一样直接改余额和流水，是等价生产旁路。

### 写接口唯一访问语义

所有 `/api/**` 不安全 HTTP handler 必须且只能属于以下一类：

1. 固定权限：`@RequirePermission`，用于有现成权限码的业务和系统动作。
2. 动态单据权限：`@RequireDocumentPermission`，从唯一的单据类型映射中解析权限，在进入业务服务前检查。
3. 请求/资源动态权限：`WriteAccess.Policy.SAVE_LIST_PRESET` / `DELETE_LIST_PRESET`，其 mode 为 `REQUEST_SCOPED_PERMISSION`；只用于同一路由内同时承载个人与管理员作用域的 preset 保存/删除，必须由专用 policy 基于当前 session 与目标资源判定，不能只靠注解放行。
4. 已认证自助写：使用 `CHANGE_OWN_PASSWORD`、`SWITCH_AUTHORIZED_ACCOUNT_SET`、`RELEASE_OWN_DOCUMENT_LOCK` 三个具名 policy，其 mode 为 `AUTHENTICATED`；只用于当前用户本人密码、已授权账套切换和本人锁释放。
5. 明确公开写：使用 `LOGIN`、`LOGOUT`、`REQUEST_PASSWORD_RESET` 三个具名 policy，其 mode 为 `PUBLIC`；只用于登录、登出和提交找回密码申请。

运行时发现不安全方法没有上述唯一语义时必须返回 403，不得沿用“无注解即放行”。具名 policy 是可执行的唯一注册表：启动时自动枚举真实 Spring handler，逐项校验 HTTP method、映射路径、唯一使用者和完整覆盖；Session 公开写边界复用该注册表，不维护第二份测试 URL 清单。动态类别除扫描外还必须有分支集成测试证明低权限路径在进入写服务前被拒绝。

### 固定权限补齐

- 11 个未保护的正式单据草稿保存复用其当前模块权限：

### 公共、自助和预设边界

- Session 公开规则改成“HTTP 方法 + 精确路径”，不得再用会把受保护子路径一起放行的前缀规则。
- PUBLIC 只允许：登录、登出、提交找回密码申请；密码申请的管理员处理接口未登录必须返回 401。
- 找回密码申请对“账号存在/不存在”必须返回相同 HTTP 状态、相同结构和不可区分文案；不得返回 `matched` 或任何可推断账号存在性的字段，前端也不得依赖这类字段。
- AUTHENTICATED 只允许：本人改密、在本人授权集合内切账套和本人锁释放；preset 必须走请求/资源动态权限类别。
- 列表个人预设必须强制使用当前 session 的角色和不可变登录 username，不能信任请求体伪造 userName/roleCode；GET/保存/删除必须使用同一个 username 作用域，不得使用可重复的 display name 隔离个人数据。
- GENERAL/角色预设的保存、覆盖和删除必须要求 `system.role_permission.manage`；A49/A50/A51 的精确快照恢复合同继续保持。
