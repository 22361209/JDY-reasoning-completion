# 当前任务包

## 目标

修复 A174 终局对抗性 review 确认的两项治理缺口：full 中仍有大量脚本通过默认 `admin` 登录，在 `SINGLE_ACTIVE` 下会替换用户现有管理员会话，而 postflight 不检查该漂移；隔离身份跨 schema 操作日志清理失败时，Node helper 会保留仍启用且拥有 ADMIN 角色/账套授权的测试账号。

本批让 full 中指向当前 5173/8080 的默认管理员登录统一映射到一个 suite 专用主体的 run-unique 密码与 session；隔离数据库 migration regression 仍使用自身数据库内的管理员，且子进程不获得主库凭据文件。Preflight/postflight 以不泄露 token/cookie/Redis key 原值的摘要证明共享 `admin` 的数据库 scope 和 Redis session 未变化。

full 会产生持久业务行，其 `created_by`/`updated_by` 外键不得为删除测试用户而改写或清除；因此 suite 主体采用“单一可复用禁用墓碑”，而非每次新增用户或强删引用主体。所有权由固定命名空间、`created_by=id`/`updated_by=id` 自指标记和固定 disabled tombstone hash 联合证明。正常与失败收尾都必须先禁用、旋转为墓碑密码、撤销角色/账套授权、清 scope 与 Redis session；正常收尾后专用用户行总数恒为 1，但可登录 ADMIN 必须为 0。

A174-2 承接 A174-1 已完成的脚本内改造，并按终局对抗 review 结论扩展为受控测试能力：主库 full 运行时拒绝共享 `admin` 新登录；对 suite 专用身份建立后端在途写请求 fence/drain；将脚本内嵌套 detached backend 纳入 runner 进程树闭包。这些能力只在 `local/test/regression`+显式测试开关+本机边界生效，不改变正式产品的登录、tenant、权限和业务语义。JDY 不作为本治理任务的需求、交互或视觉参考。

终局 review 继续把 runner 自身纳入同一可信边界：suite lock 更新使用代际 CAS 与失败毒化；stale recovery 以私有 claim 串行化并在全部共享副作用完成后原子迁走 canonical lock；子进程启动前持久化不可变 artifact baseline，崩溃恢复清除本轮新增/变更的 ignored 产物和私有 credential capability。未取得 suite lock 的并发 runner 不得覆盖共享 latest 结果。

## 验收

- 静态 fail-closed：full 脚本访问当前 5173/8080 的默认 `admin/admin123` 必须映射至 suite 专用主体的 run-unique 凭据；原始 migration/隔离 backend 地址不得映射，且不得继承主库 credential-file 能力。无法识别的主库共享 admin 原始登录必须在 preflight 阻断。
- 共享 admin 不变量：preflight 记录数据库 active-session/scope 与 Redis 主 hash、expires key、expiration member 的非敏感摘要及捕获时到期边界；每个 child 后及 suite postflight 必须一致，仅允许已到达捕获到期边界的自然消失。
- Suite cleanup：父进程无论脚本成功或失败都清理 run-scoped Redis session、scope、跨现存 `sys_operation_log` schema 的 actor 日志、角色和账套授权；专用主体必须收口为带强所有权标记的 disabled tombstone，不得每次新增残留用户。cleanup 错误与脚本/postflight 主错误同时保留，成功 artifact 必须明示 `principalDeleted=false/retainedDisabled=true`，不得伪装为用户行已删除。
- 在途请求与进程树：cleanup 必须先 fence suite 主体、排空已认证写请求，再扫 Redis/日志/授权；嵌套 backend 不得逃出 runner 记录的进程树，崩溃恢复必须能精确终止已证明归属的残留进程。
- Runner 原子恢复：owner 更新不得替换 run/pid/fingerprint/revision，失败后 handle 永久 fail-closed；同一 stale generation 只能有一个 recovery claim，foreign-generation claim 必须隔离，canonical lock 只能在共享恢复和 artifact purge 全部完成后原子迁走。
- 私有能力与产物：credential capability 必须原子发布并在父进程崩溃后按 run/schema 验证清除；artifact baseline 必须在任何 child 启动前以私有不可变 sidecar 持久化，缺失、篡改、非 ignored residue 或目录/非普通文件残留均阻止 stale lock 释放。
- 共享 admin 运行时边界：suite lock 存在时，当前 8080 必须在密码校验/会话写入前拒绝共享 `admin` 新登录；preflight 必须证明 guard 生效，isolated backend 不受影响。
- 失败身份隔离：故意造成 actor 日志 schema 清理失败时，cleanup 必须失败，但残留用户为 disabled，角色/账套授权/scope/Redis session 均为 0；不得遗留可登录 ADMIN。
- `node --check`、身份映射/分类、suite-lock/CAS、process tree、credential capability、artifact/secret channel 单元合同、A44 正常与故障注入、至少一个浏览器默认 admin 脚本、一个 API 默认 admin 脚本、A69–A72 中涉及重复登录/密码确认的必要脚本，以及一个 migration 隔离 backend 门禁通过。
- 独立 review 无 P0–P2 后提交干净候选；最终仅运行一次 full，完整执行 143/143，除 A25/A128 外不得有失败，postflight 共享 admin 不变量和 suite identity cleanup 必须通过。
