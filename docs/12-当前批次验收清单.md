# A185 当前任务包

## 目标

以“完整执行 25 项真实用户验收”为主目标。优先在 Chrome 可见界面确认并新建独立干净测试账套；若产品界面无法新建账套，则按用户授权在独立环境准备阶段重置 `BLD-TEST` 的业务数据、主数据、余额和测试日志。环境准备完成后切换为严格真实用户验收模式，从任务 1 连续执行到任务 25，遇到阻碍记录并继续，最后统一汇总。

## 时间、预算与执行策略

- 墙钟时间不设上限；环境确认与初始化预计 15–45 分钟，25 项逐项操作合计约 7 小时 18 分，计入截图、复现和记录后按 8–10 个 Codex 小时估算。
- Goal token 上限 `15,000,000`，最大提交 `3`，同时只读子代理最多 `3`，累计子代理不设上限。
- 本任务不运行 smoke/area/full，`maxFullGateRuns=0`；自动回归不能代替真实用户验收。
- 提交只用于任务包与最终验收报告/归档；不修改产品代码，不修复缺陷，不 push，不操作生产环境。
- 达到 token/提交预算 70%、出现无法确认的破坏性边界或 Chrome 持续不可用时停止并报告；单个业务阻碍不停止，按规则跳到下一项。

## 停止条件

- Goal token 或提交预算达到 70%、出现 3 个范围外问题、3 次上下文压缩，或环境身份/破坏性目标无法精确确认时，停止并向用户报告。
- `record-and-stop` 只约束任务范围扩张、环境身份不明和破坏性边界；某个编号任务自身失败或阻断时不扩范围修复，而是记录后继续可独立执行的下一项。
- Chrome 连接短时失败先按原页面重连；持续无法恢复或无法确认当前测试账套时停止，禁止盲点操作。

## JDY 参考边界

JDY 只用于业务术语、常用流程与可见交互校准，不作为扩展功能范围或替代当前 ERP 实际行为的依据。本轮验收只判断当前有效范围内的真实可用性。

- 治理与交付文档：`docs/09-交接清单.md`、`docs/12-当前批次验收清单.md`、A185 最终验收报告、归档任务包和报告索引。
- UAT 操作面：Chrome 中 `http://127.0.0.1:5173` 的当前 ERP 可见界面，以及用户授权的新测试账套或 `BLD-TEST`。
- 若新建账套不可用，环境维护仅允许作用于精确识别的 `BLD-TEST` 业务/主数据/余额/测试日志；实际清单、备份与恢复守卫必须先记录，产品代码与其他 tenant 不在允许范围。

## 明确不做

- 不修改产品代码、回归脚本、迁移、权限目录或业务生命周期；发现缺陷只记录，不修复。

## 环境准备边界

### 首选：新建独立测试账套

- 仅通过 Chrome 可见界面检查账套管理入口和“新建账套”能力。
- 若可用，创建名称含 `全量用户验收 20260810` 的独立测试账套；实际编码以界面允许值为准。
- 只保留登录、账套、管理员和必要系统目录；业务主数据由后续 UAT 通过界面创建。
- 创建后退出并重新登录，确认账套切换、菜单和权限来自新账套，而非沿用 `BLD-TEST`。

### 回退：重置 BLD-TEST

仅当 Chrome 现场确认没有可用的新建账套能力时启用。该阶段属于用户明确授权的环境维护，不属于 UAT：

- 先固化当前账套身份、备份/恢复点和待删除集合；无法证明恢复边界时 fail closed。
- 清理范围仅限 `BLD-TEST` 的业务单据及分录、主数据、库存/往来/资金余额和本账套测试日志。
- 保留账套注册、管理员登录、权限目录、安全设置、系统枚举和运行所需基础配置。
- 禁止粗暴 `TRUNCATE public`、模糊前缀删除、破坏其他 tenant、改写迁移历史或删除生产数据。
- 重置后重新登录并用界面确认列表为空、余额归零、必要菜单可用；从此刻再切换为 Chrome-only UAT。
- 清理前必须实际记录精确账套/tenant 身份、可恢复备份、逐表删除清单与预计行数；任一项缺失即不执行重置。

## 真实用户验收统一规则

- UAT 阶段仅使用 Chrome 可见界面、视觉、鼠标和键盘；不得读写代码、运行脚本、调用接口、查看日志或直接操作数据库。
- 测试数据统一使用 `UAT-20260810-序号` 前缀，只在最终选定的测试账套操作。
- 每个问题按相同步骤复现一次；确认后记录，不绕过、不修复、不切开发模式。
- 某项阻断时继续所有可独立执行的后续任务；直到任务 25 完成或逐项给出明确阻断。
- 每项记录实际前置数据、操作、单号/编码、状态、验收点、异常和结论；最终一次性汇总，不在编号任务之间停等。
- 任务 4/5 的“被引用后反审核”在任务 8/10/20/21 建立下游后回访验证；不能因编号已向后推进而漏测。
- 当前有效范围要求交付但界面没有可见入口时必须记为 `FAIL` 或 `BLOCKED`；只有范围真相源明确排除/后置，或条件型可选分支确实不适用时才能记为 `N/A`。不得为了跑链路伪造入口；销售订单与销售出库始终保留不依赖可选报价/发货通知的直接路径。
