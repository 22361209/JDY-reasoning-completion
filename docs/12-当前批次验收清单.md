### 数据与 DDL 合同

1. 参考源固定为 public 的版本化受管表目录与表结构，不从任意 tenant 反推 DDL。
2. 现有 tenant 与新建 tenant 必须调用同一份版本化同步计划；Java provisioning 不复制第二套约束清单。
3. 同步计划只处理注册且名称安全的 tenant schema；缺 schema、缺表、类型不一致、未知额外数据列或孤儿均 fail-closed。
4. 一个非 public tenant schema 只能登记给一个账套；存量重复登记使迁移失败，新建账套复用已登记 schema 或试图收编已存在未登记 schema 均返回 409 且整笔回滚。
5. 缺失列只按 public 的类型、默认值、NULL 语义确定性补齐；现存同名列类型不一致时不自动转换。
6. PK、UK、CHECK 按约束语义比较，已有等价约束不重复创建；FK 的 tenant 业务父表指向同一 tenant，平台父表明确指向 public。`document_number_sequence`、`inv_stock_balance`、`inv_stock_opening`、`inv_stock_txn` 的 `account_set_id` 按 A119 既有合同使用 tenant 派生作用域 UUID，因此显式豁免它们仅适用于 public 过渡模式的 4 个 `sys_account_set` FK，不得扩大豁免。
7. 所有 FK 在创建前全量预检；不得用 `NOT VALID` 留下未验证约束作为完成结果。
8. V86 遗留列只在确认目标表 0 行或列值无待保留语义时按显式清单移除；不做泛化“自动删除额外列”。
9. migration 和 provisioning 可重复执行；第二次运行必须零 DDL 漂移、零重复约束。
10. backup schema 不作为在线 tenant 参与约束同步；restore 只向已经具备完整约束的目标 tenant 回插数据，非法备份必须整笔失败。

5. 重复业务键被 UK 拒绝，非法库存数量/审计主体等数据被 CHECK 拒绝，失败后业务数据零半截变化。
