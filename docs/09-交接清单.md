## A141 已冻结业务决定

1. F026 销售收款、F036 采购付款只打开或下推 finance 域同一套正式收款/付款能力，不在 sales/purchase 复制结算引擎。
2. 一张单据允许同一客户/供应商的多张应收/应付来源和多条资金账户行；不同往来单位不得混单。
3. 正式支持 CNY/USD；单据头、全部来源、全部账户必须同币种，不做汇率、换算、汇兑损益或跨币种核销。无上游来源的销售出库/采购入库可选 USD；有来源但上游尚无币种时只能继承 CNY。
4. 草稿金额可为 0 且不需要原因，但不能为负数；审核总额必须大于 0。草稿零核销影响，重复审核幂等，反审核原子释放并回 DRAFT。
5. 旧立即结算记录必须无损保留；AUDITED legacy 头/明细只读且不可删除，但允许安全反审核，重新审核前必须补真实账户。两个旧“调用即结算”URL 退役为有权 410，匿名/无权仍先 401/403。
6. legacy 数据不得伪造资金账户、交易号或操作人；新正式单据不允许利用 legacy 例外绕过账户、币种或生命周期校验。

## A141 固定技术边界

1. 正式 header + 资金账户行 + 核销来源行；资金合计、核销合计和头金额必须精确相等。
2. 无来源销售出库/采购入库明确保存 CNY/USD，财务过账原样写入 AR/AP；有上游来源且上游无币种时固定 CNY，现有与历史事实回填 CNY，红字/退货继承来源币种。
3. 同源竞争审核必须在 tenant 事务中稳定排序并 `FOR UPDATE`；草稿不占正式余量，审核是最终守卫。
4. Controller 不直接写结算 SQL；正式规则集中于共享 `FinanceSettlementAppService`。sales/purchase 不直接更新 finance 表。
5. `finance.settle` 控制收付款维护和选择器；`finance.report.view` 可只读 AR/AP 及正式收付款列表/详情，但不自动获得结算权限。
6. 页面共用一套 `SettlementDocumentForm`，列表/详情与前后端生命周期能力登记一致；手续费 A141 只允许 0。
