# 验收标准与测试门禁

本文定义“做完”的标准。后续任何模块都必须按这里验收，不能只以代码写完或接口返回成功为完成。

本仓库以当前 ERP 的业务闭环、数据正确性、安全、tenant、可用性和可维护性为首要验收目标。JDY 是术语、信息架构、常用流程、关键交互和视觉基线的高优先级参考；它不能替代用户确认的业务决策，也不是所有入口的像素级硬门禁。任务若使用 JDY 参考，必须在当前任务包说明参考范围与有意差异。

## 验收等级

| 等级 | 含义 |
| --- | --- |
| A0 骨架可见 | 菜单入口、页面结构、权限入口存在 |
| A1 页面可操作 | 列表、表单、选择器、保存/查询能使用 |
| A2 业务闭环 | 保存、审核、库存/资金/状态影响正确 |
| A3 边界可靠 | 反审核、库存不足、权限不足、并发、错误态通过 |
| A4 可交付 | 有自动化测试、截图证据、文档更新、交接说明 |

第一版 P0 模块至少达到 A3；高风险模块达到 A4 后才算可交付。

## 通用验收门禁

每个功能完成前必须通过：

- 有员工可访问入口。
- 有列表页或工作台入口。
- 有新增/编辑/查看路径。
- 有权限控制。
- 有操作日志。
- 有空态、错误态、加载态。
- 有测试数据。
- 有最少一轮浏览器可见验证。

## 前端体验验收

按 `docs/10-前端体验与视觉规范.md` 执行。

必须检查：

- `1366x768` 下核心操作不被遮挡。
- `1920x1080` 下布局不过度拉散。
- 文本不溢出按钮、表头、卡片。
- 表格行、工具栏、分页器稳定，不因数据变化跳动。
- 多页签打开、切换、关闭可用。
- 选择器可搜索、可回填。
- 保存/审核/删除等危险动作有确认和反馈。

## 主数据选择器验收

商品、客户、供应商、仓库、部门等整列表选择弹窗必须按共享选择器协议验收。

必须检查：

- 弹窗复用共享选择弹窗表格能力：列设置、列筛选、列宽拖拽、分页/每页条数、空态、加载态和统一查询事件可用。
- 商品选择器左侧显示真实物料类别，点击类别后由后端查询返回对应结果，总数、分页和表体同步变化。
- `MasterDataDefinition.selectorColumns` 中所有可见列都有数据映射；客户/供应商联系人电话、仓库类型/仓管员等扩展列不得显示成无意义的 `-`。
- `total > pageSize` 时能翻页或继续加载，不允许只显示总数但只能访问第一页。
- 快速切换关键词、类别、页码、选择器类型时，不出现旧候选行覆盖新弹窗。
- 选择候选后能回填目标字段，并保持原有跳格/键盘连续录入体验。
- 列宽拖拽热区 cursor 为 `col-resize`，拖拽后表头和表体同步变化；重新打开同一选择器时列设置/列宽按共享偏好恢复。

涉及主数据选择器协议、`MasterSelectorDialog`、`SourceSelectorDialog` 或共享表格弹窗组件的改动，必须至少验证商品、客户、仓库三类选择器；商品要额外验证类别筛选和分页。

## 基础资料 Excel 导入验收

涉及导入时，唯一专项规则与完整验收矩阵见 `docs/guides/master-data-import-protocol.md`。全局层只要求：按该协议运行相称的安全、tenant、迁移、浏览器与回归验证；不得以 smoke 替代共享导入工作流的专项验收。

### 物料列表与物料选择态验收

物料选择按 `product-master-list` 的列表选择态验收，不按单据局部商品弹窗验收。

必须检查：

- 入口覆盖：销售报价单、销售订单、发货通知单、采购订单、采购入库、采购退货、其他出入库、库存调拨、库存盘点、生产领料、生产入库、销售出库等分录物料选择均走同一个物料选择态；BOM、委外等非弹窗物料查找点要在验收报告列明当前形态。
- 物料资料列表正本：`product-master-list` 左侧显示真实物料类别分类器，右侧为共享列表表格；点击类别后总数、表体、分页和 `物料类别` 列同步变化。
- 物料选择弹窗派生：弹窗左侧分类器与物料资料列表同源，右侧表格使用共享选择器表格协议，数据查询走 `product-master-list`，不得有单据私有类别加载或单据私有商品候选表。
- 列与回填：弹窗列来自 `MasterDataDefinition.selectorColumns`，选择后回填物料编码、物料名称、规格型号、单位、净重、毛重、物料类别等标准字段，且不破坏原有跳格/键盘连续录入。
- 表格表现：物料列表和物料弹窗均不得出现真实单元格边框与背景网格线错位；列宽拖拽热区显示为 `col-resize`，拖拽后表头和表体同步生效。
- 分页与筛选：关键词、列筛选、类别筛选、页码、每页条数组合后结果一致；快速切换类别和关键词时旧请求不得覆盖新结果。
- 回归范围：至少在物料资料列表、销售报价单分录物料弹窗、销售订单分录物料弹窗、销售出库分录物料弹窗各完成一次浏览器验收。

## 参考驱动的体验验收

页面改动必须按 `docs/10-前端体验与视觉规范.md` 进行真实浏览器验证。存在可靠 JDY 参考时，验收应使用它校准术语、信息层级、表格密度、关键交互、按钮状态和阻断文案；不存在或与本项目安全/业务规则冲突时，以本项目规则为准，并在任务包或验收报告中说明差异。

必须检查：

- 字段名、按钮名、状态名和提示文案符合已确认的本项目术语；JDY 文案仅在未冲突时作为参考。
- 同族页面使用共享单据、列表、表格和选择器范式，不为单一入口复制布局或交互逻辑。
- 关键操作在目标视口有可见反馈、错误态、权限态和危险确认；截图、流程和数据结果共同构成验收证据。
- 不因缺少 JDY 截图或没有达到像素级相似度而阻断已满足业务、安全、数据和可用性门槛的功能。

## 数据一致性验收

涉及库存、资金、状态的功能必须验证：

- 单据未审核不影响库存/资金。
- 审核后影响库存/资金。
- 审核失败不会产生半截数据。
- 重复点击审核不会重复扣库存或重复生成应收应付。
- 库存不足时阻断。
- 反审核遇到下游单据时阻断。
- 操作日志记录成功和失败。

## 生命周期动作验收

涉及保存、审核、反审核、作废、关闭、反关闭、冻结、解冻、红冲、选源、下推的功能必须额外验证：

- 保存只落草稿，不产生库存、资金、源单执行量或正式下游占用等业务事实。
- 选源单必须区分正式执行量与当前单据本地分配量：后端返回正式剩余量，前端按当前草稿分录即时扣减本单已拉入数量；同一单据再次打开选源单时，不得重复选到已拉入的数量。
- 未审核源单不得被选源、下推或执行。
- 已关闭、已冻结、行关闭、行冻结的源单行不得继续被下游选择或执行。
- 关闭/反关闭、冻结/解冻只在生命周期策略允许的连续执行类单据显示；销售出库、采购入库、生产领料、产品入库等事实类单据不得显示这些按钮。
- 红冲只在生命周期策略允许的库存/执行事实类单据显示；销售订单、发货通知、采购订单、销售报价等不得显示红冲。
- 作废只允许已保存草稿，必须填写原因并用当前账号密码确认。
- 列表批量动作和单据详情动作必须使用同一份生命周期能力口径。
- 改动 `BillLifecyclePolicy`、`BillLifecycleService`、`documentLifecyclePolicy.ts`、`documentActionRules.ts`、`DataListPage.vue` 或 `StandardDocument` 时，必须跑前端 build、后端测试和至少 smoke；若影响共享列表/动作/生命周期守卫，必须跑 full 回归。

## 库存模块验收

库存相关功能至少验证：

- 其他入库审核增加库存余额。
- 其他出库审核减少库存余额。
- 库存不足时其他出库审核失败。
- 商品收发明细能追溯到来源单据。
- 库存查询显示最新余额，不从缓存读取旧值。
- 同一商品同一仓库并发扣减不能扣成负数。

## 销售模块验收

销售主链路至少验证：

- 销售订单保存、审核。
- 销售出库从销售订单生成或关联。
- 销售出库审核扣库存。
- 销售出库审核生成应收。
- 销售退货审核回补库存。
- 销售收款核销应收。
- 已有下游单据时反审核阻断。

## 采购模块验收

采购主链路至少验证：

- 采购订单保存、审核。
- 采购入库从采购订单生成或关联。
- 采购入库审核增加库存。
- 采购入库审核生成应付。
- 采购退货审核扣库存。
- 采购付款核销应付。
- 已有下游单据时反审核阻断。

## 生产模块验收

生产主链路至少验证：

- BOM 保存、审核。
- 生产任务可来源于已审核生产计划，也可手工单独创建；手工任务不得静默生成隐藏生产计划。
- 生产任务审核时按当前已审核 BOM 固化本任务用料快照，保存草稿不得被后续领料/入库视为可用任务。
- 生产领料依据生产任务用料快照，不得运行时直接读取标准 BOM。
- 生产领料审核扣材料库存。
- 材料库存不足时领料审核阻断。
- 产品入库审核增加成品库存。
- 生产任务能查看领料和入库执行状态。
- 齐套/足缺料能按 BOM、库存余额计算。

## 委外模块验收

委外主链路至少验证：

- 委外加工单保存只生成草稿，审核后才可下推。
- 委外加工单必须引用已审核且启用的当前 BOM，并保存 BOM 版本和物料快照。
- 委外发料单来源于已审核委外加工单，审核后按 BOM 子件从默认仓库扣库存。
- 委外产品入库单来源于已审核委外加工单或发料链路，审核后按母件默认仓库入库。
- 委外产品退货单、委外产品报废单来源于已审核委外产品入库单，审核后扣减对应入库母件库存。
- 所有下推和选源必须由后端计算正式剩余量并阻断跨单超量或重复占用；当前单据未保存前的本地分配量由统一选源单生命周期扣减，确认选源回填分录后必须立即提交本地分配刷新，保存草稿仍不得产生正式全局占用。

## 权限验收

权限相关至少验证：

- 无权限用户看不到菜单入口。
- 无新增权限不能新增。
- 无审核权限不能审核。
- 权限变化后重新登录生效。

第一版不缓存权限结果；如未来缓存，必须有明确失效机制。

数据权限是 P2 能力。进入对应阶段后，必须额外验证：

- 数据权限限制列表结果。
- 数据权限限制选择器结果。
- 数据权限不能只在前端过滤，后端查询也必须生效。

## 报表验收

报表简单版至少验证：

- 筛选条件有效。
- 查询结果和来源单据一致。
- 空结果状态明确。
- 导出结果与页面筛选一致。
- 大数据量分页或导出有进度反馈。

## 自动化测试门禁

后端必须有：

- 单元测试：核心状态机、库存扣减、编号生成。
- 集成测试：销售、采购、生产、库存主链路。
- 并发测试：库存扣减不能为负。

前端必须有：

- 核心页面渲染测试或 Playwright 流程测试。
- 至少覆盖登录、导航、列表查询、单据保存、审核反馈。

## 分层回归门禁（A111 起）

统一入口：

```bash
node scripts/run-regression-tier.mjs smoke
node scripts/run-regression-tier.mjs area:<module>
node scripts/run-regression-tier.mjs full
```

输出统一汇总 JSON：`verification/regression-tier-<tier>-latest.json`，字段包含 `tier / ok / total / expectedTotal / badCount / skipped / results[]`。smoke / area / full 的脚本归属统一维护在受版本控制的 `config/regression-manifest.json`；`full` 运行其中全部登记项，`area:<module>` 自动合并 `smoke`。所有 `scripts/*-regression.mjs` 必须进入 full 或登记为带原因的历史聚合豁免，执行器不得再从 ignored `verification/` 读取回归清单。

档位选择规则：

| 改动分类 | 判定口径 | 必跑门禁 |
| --- | --- | --- |
| 表现改动 | 共享 UI 的 CSS、布局、密度、列宽、图标、文案、品牌，不改变业务数据、SQL、状态、金额、库存、权限判定 | `smoke` + 人工眼验/截图核对；不必全量行为回归 |
| 行为改动 | 业务逻辑、SQL、过账、状态机、金额、库存、财务、权限判定、接口契约 | `smoke` + 对应 `area:<module>` |
| 共享核心逻辑 | `BillLifecycle`、`PostingPipeline`、库存账、税、预留、跨模块基础服务 | `full` + 后端快测 |

每批验收报告必须写明本批归类和所选档位。若表现改动触及共享组件但没有改变业务行为，以人工眼验和 smoke 为主；若同一批同时包含表现和行为，以更高档位为准。

后端快测要求：

- `BillLifecycle`：审核、反审核回 `DRAFT`、关闭、冻结、作废下游阻断。
- `PostingPipeline`：库存过账与财务过账均有毫秒级测试兜底。
- 税额计算：含税/不含税、默认税率、空值兜底。
- 发货通知预留不变式：`可用 = 即时 - 锁定`，且即时、锁定、可用均非负。

## 人工验收报告

每次阶段验收要输出 Markdown 报告，包含：

```text
验收日期
验收范围
测试账号
测试数据
通过项
失败项
阻塞项
截图路径
剩余风险
下一步
```

如果功能只达到 A1/A2，报告中必须明确不能当成完整业务闭环。
