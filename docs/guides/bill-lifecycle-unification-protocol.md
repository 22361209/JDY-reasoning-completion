# BLD 单据生命周期统一协议

本文件定义正式单据的统一生命周期口径。它是 `docs/guides/business-rules.md` 与 `docs/guides/action-button-rules.md` 的执行细则，后续新增单据必须先落到本协议，再决定页面按钮和后端业务处理。

## 核心状态

正式单据只使用三组生命周期状态：

| 状态组 | 字段 | 合法值 | 含义 |
| --- | --- | --- | --- |
| 主状态 | `status` | `DRAFT` / `AUDITED` / `VOID` / `RED_REVERSED`，历史兼容 `REVERSED` | 保存、审核、作废、红冲的主线状态；新反审核逻辑不再写入 `REVERSED` |
| 关闭状态 | `close_status` | `OPEN` / `CLOSED` | 连续执行类单据是否停止后续执行 |
| 冻结状态 | `frozen_status` | `NORMAL` / `FROZEN` | 连续执行类单据是否暂停后续使用 |

不得再新增独立的 `execution_status` 作为生命周期来源。列表上的出库状态、入库状态、已执行数量、未执行数量等只属于执行事实或展示派生值，不决定按钮是否合法。`outStatus` / `inStatus` 只能用于展示，按钮可用性和下推资格必须看未出库数量、未入库数量、可下推数量等事实字段。

`REVERSED` 只作为历史兼容/旧数据展示状态。新业务逻辑执行反审核时，统一从 `AUDITED` 回到 `DRAFT`；真正不可逆或冲销类场景走红冲/红字单，不再用 `REVERSED` 表达新状态。

## 基本转换

| 动作 | 前置条件 | 结果 | 说明 |
| --- | --- | --- | --- |
| 保存 | 未保存或草稿 | `DRAFT` | 只保存草稿，不影响库存、资金、源单执行量 |
| 审核 | `DRAFT` | `AUDITED` | 审核后才产生业务事实，由各单据 AppService 写库存、应收应付或快照 |
| 反审核 | `AUDITED` 且无下游阻断 | `DRAFT` | 反审核必须回退审核产生的业务事实；不写入 `REVERSED` |
| 作废 | 已保存草稿且单据策略允许作废 | `VOID` | 必须填写原因并用当前账号密码确认；前后端同一 `voidAllowed` 策略，后端必须强校验 |
| 关闭 | 已审核、未关闭、未冻结且单据支持关闭 | `close_status=CLOSED` | 只适用于连续执行类单据 |
| 反关闭 | 已审核、已关闭且单据支持关闭 | `close_status=OPEN` | 恢复后续执行资格 |
| 冻结 | 已审核、未关闭、未冻结且单据支持冻结 | `frozen_status=FROZEN` | 暂停后续选源、下推、执行 |
| 解冻 | 已审核、已冻结且单据支持冻结 | `frozen_status=NORMAL` | 恢复使用资格 |
| 红冲 | 已审核且单据支持红冲 | `RED_REVERSED` 或生成红字单据 | 只适用于库存/财务事实类单据 |

## 单据能力分类

| 类别 | 单据 | 关闭/冻结 | 行关闭/行冻结 | 红冲 | 作废 |
| --- | --- | --- | --- | --- | --- |
| 报价候选 | 销售报价单 | 否 | 否 | 否 | 是 |
| 连续执行承诺 | 销售订单、发货通知单、采购订单 | 是 | 是 | 否 | 是 |
| 库存/执行事实 | 销售出库单、采购入库单、生产领料单、产品入库单 | 否 | 否 | 是 | 是 |
| 普通库存事实 | 采购退货单、其他入库单、其他出库单、调拨单、盘点单、盘盈单、盘亏单 | 否 | 否 | 否 | 是 |

第一版共享 `BillLifecycleController` 只负责上表中的正式业务单据。BOM、生产计划、生产任务、采购申请、委外加工链路可以使用同样口径，但如果尚未接入共享控制器，必须在各自 AppService 中执行同样前置规则：保存只草稿，审核后才可用，未审核不得选源或下推。

当前未完整接入共享生命周期控制器的 BOM、生产计划、生产任务、采购申请、委外链路，不计入“全 ERP 生命周期 100% 完成”。它们必须按本协议继续回收：动作按钮、状态规则、列表字段、后端守卫和测试逐批补齐。

## 源单与下推

- 源单和源单行必须同时满足：主状态 `AUDITED`、关闭状态 `OPEN`、冻结状态 `NORMAL`、行关闭状态 `OPEN`、行冻结状态 `NORMAL`。
- 未审核源单不得被选源、下推或执行。
- 已关闭、已冻结、行关闭、行冻结的源单行不得继续作为可用来源。
- 下推按钮、选源弹窗和批量执行按钮不得依赖 `outStatus` / `inStatus` 这类中文展示状态。它们必须依赖未出库数量、未入库数量、可下推数量、行关闭/冻结状态等事实字段。

## 前后端责任

- 后端是最终裁判：`BillLifecyclePolicy` 负责单据能力分类，`BillLifecycleService` 负责状态转换守卫和源单可执行守卫。
- 作废必须由前后端同一策略控制。前端 `documentLifecyclePolicy.ts` 控制按钮显示，后端 `BillLifecyclePolicy.requireVoidAllowed` 必须再次校验 `voidAllowed`，不能依赖前端隐藏按钮。
- 前端只做预判和体验：`documentLifecyclePolicy.ts` 负责按钮显示、禁用和状态章文案，不能代替后端校验。
- 列表批量动作和单据详情动作必须共用同一份单据能力口径；不能出现详情页无关闭按钮、列表页却能批量关闭的情况。

## 新增单据接入步骤

1. 在后端 `BillLifecyclePolicy` 登记单据能力。
2. 如需共享生命周期 API，在 `BillLifecycleController` 登记目标表、分录表和权限模块。
3. 在前端 `documentLifecyclePolicy.ts` 登记同一份能力。
4. 单据详情页通过 `StandardDocument` / `DocumentForm` 使用统一动作按钮。
5. 列表页通过 `DataListPage` 的 `documentActionTypeByListKey` 接入同一能力。
6. 添加或更新测试，至少覆盖草稿不可关闭/冻结、未审核源单不可执行、事实类单据不显示关闭/冻结、红冲仅事实类单据可见。
