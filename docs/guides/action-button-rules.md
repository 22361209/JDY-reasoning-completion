# 动作按钮规则索引

本文件记录按钮的可见、可用和触发规则。后续权限接入时，所有按钮都应同时支持“不可见”和“可见但不可用”两种状态。

## 通用模型

- `visible` 控制按钮是否显示，由入口能力、单据类型、用户权限共同决定。
- `enabled` 控制按钮能否点击，由单据状态、锁定状态、权限、是否已保存、是否选中数据共同决定。
- 被禁用按钮应保留位置和语义，避免动作条跳动；权限要求隐藏的按钮可直接不可见。
- 所有危险动作必须有确认、结果反馈和操作日志。
- 生命周期类按钮必须先在 `docs/guides/bill-lifecycle-unification-protocol.md` 登记能力；未登记单据不得新增审核、反审核、作废、关闭、冻结、红冲、下推、选源等按钮。
- 前端按钮只做体验层预判，不得自创状态规则；后端必须再次校验单据能力、状态、权限和下游影响。
- `outStatus` / `inStatus`、已出库、已入库等展示状态不能作为按钮可用性或下推资格依据，只能作为列表展示文案。

## 单据页按钮

| 按钮 | 可见规则 | 可用规则 | 点击结果 |
| --- | --- | --- | --- |
| 新增 | 单据支持手工新增且有新增权限 | 当前页未被锁定 | 如有未保存内容先弹窗；确认后生成新草稿号和空白分录 |
| 保存 | 单据支持保存 | 当前页未锁定且草稿可编辑 | 保存草稿，不动库存和资金 |
| 审核 | 单据支持审核 | 草稿、未锁定、有审核权限 | 审核成功后触发对应业务影响 |
| 反审核 | 单据支持反审核 | 已审核、无下游阻断、无非作废红字单、有权限 | 二次确认后冲销或回退业务影响 |
| 红冲 | 生命周期策略标记为库存/执行事实类 | 已审核、无非作废红字单、不是红字单本身、有权限 | 二次确认后生成红字/退货/冲销草稿单据；红字单据审核后才产生反向业务事实 |
| 关闭/反关闭 | 生命周期策略标记为连续执行类 | 已审核且关闭状态满足转换、有权限 | 只改变关闭状态，不等同删除；销售订单反关闭只允许手动关闭状态 |
| 冻结/解冻 | 生命周期策略标记为连续执行类 | 已审核且冻结状态满足转换、有权限 | 控制后续业务使用，不等同删除 |
| 作废 | 生命周期策略允许作废 | 已保存草稿、有高风险权限、当前账号密码确认 | 二次确认后作废 |
| 删除 | 单据支持草稿删除 | 已保存草稿、未锁定、有权限 | 确认后删除草稿，编号不复用 |
| 选源单 | 单据支持源单选择 | 未锁定、有权限 | 打开源单选择弹窗并回填分录 |
| 设为有效/设为失效 | 单据支持有效性控制 | 已审核、未锁定、未过有效期、有权限 | 切换该单据是否参与后续选源单，不删除历史 |
| 下推 | 单据支持下推 | 当前单据状态和执行量允许 | 生成下游单据草稿 |
| 引出/打印 | 单据支持输出 | 有输出权限 | 导出或打印当前单据 |

### 源单入口

- 顶层“行级源单追溯”按钮废弃，任何单据页不应再显示这个按钮。
- 源单回填统一走动作条“选源单”入口；按钮文案不随源单类型改名。
- 分录行内的源单号/源行号追溯只用于查看该行来源，不作为新增回填入口。

### 源单链路

- 销售订单“选源单”选择销售报价单；销售报价单本身不显示“选源单”。
- 销售订单只能选择已审核、手工有效且未过有效期的销售报价单；直接录入商品不静默采用未引用报价。
- 发货通知单“选源单”选择销售订单。
- 销售出库单“选源单”选择发货通知单。
- 生产计划“下推”生成生产任务和采购申请；下推前必须按 BOM 版本、默认生产车间、默认供应商完成后端校验。
- 生产任务“下推”生成生产领料单；领料内容只能来自任务用料快照，不得实时读取当前 BOM。
- 生产领料单“下推”生成产品入库单；产品入库审核后才形成完工入库库存事实。
- 采购申请“下推”按分录供应商生成采购计划；缺少已审核启用供应商的行必须阻断并指出具体物料。
- 采购计划不自动生成采购订单；草稿计划不占用采购申请数量，审核后才占用，反审核后释放。
- 采购计划草稿可通过“删除”取消；删除后采购申请再次下推只重建尚无采购计划的剩余来源行，多供应商场景不得复制其他仍存在的计划。
- 采购订单“选源单”选择采购申请；采购订单仍允许手工新增。
- 采购入库单“选源单”选择采购订单。
- 在源单弹窗中按具体型号/商品搜索并勾选明细，即为行级选择。
- 在源单弹窗中按具体单号搜索后全选明细，即为整单选择。
- 源单弹窗只显示扣除已审核下游业务占用后仍有剩余数量的行；草稿不产生业务事实，不扣减正式可执行余量。
- 红字草稿不开放选源和业务事实字段编辑；红字单只允许继续走自身审核、反审核、作废或删除草稿生命周期。
- 下游反审核或作废后，源单弹窗应重新释放对应已审核占用；删除草稿不涉及业务事实释放。
- 源单本身和源单行必须同时满足已审核、未关闭、未冻结、行未关闭、行未冻结；未审核源单不得被选源、下推或执行。销售订单行关闭字段暂留兼容，销售订单行关闭 API 已禁用，新业务入口不再暴露行关闭/反关闭按钮。

## 列表页按钮

- 新增：打开对应新单据页签。
- 审核、反审核、关闭、反关闭、冻结、解冻、作废：必须根据选中行状态和生命周期策略批量判定；不满足条件时禁用或给出逐行失败原因。
- 同一单据列表的整单视图和明细视图必须使用同一套动作条按钮名称、顺序和分组；明细视图选中的是分录行，但审核、反审核、关闭、反关闭、冻结、解冻、作废仍按所属 `billNo` 汇总去重后执行单据级动作。
- 列表页和单据详情页必须使用同一份生命周期能力口径。销售报价、销售出库、采购入库、生产领料、产品入库等不支持关闭/冻结的单据，列表批量动作也不得显示关闭/冻结。
- 当前阶段不开放行关闭/反关闭按钮；销售订单行关闭 API 已禁用，其他保留行关闭字段的单据也不得因为明细视图选中分录而把单据级“关闭”解释成“行关闭”。
- 批量按钮不允许保留“确认后仅提示未接入”的假动作；显示出来的按钮必须有真实后端提交或明确不可见。
- 删除：仅对已保存草稿可用，必须确认；未保存单据不出现在列表中。
- 列设置、查询、重置、分页：属于列表工具，不参与业务权限状态机。
- 更多：只承载确实需要折叠的动作，不显示筛选标。

## 主数据页按钮

| 按钮 | 可见规则 | 可用规则 | 点击结果 |
| --- | --- | --- | --- |
| 新增 | 主数据入口支持维护且有权限 | 当前页可访问 | 打开新增主数据页签 |
| 编辑 | 只读详情页或列表选中 1 行 | 已保存资料且有维护权限 | 打开或切换到该资料唯一页签，并进入可编辑状态 |
| 复制 | 物料列表选中 1 行且有维护权限 | 选中行存在业务编码 | 新开物料草稿，复制可维护字段，不复制系统编号和物料编码 |
| 保存 | 新增/编辑主数据页 | 非只读状态，必填项通过 | 保存草稿并停留在当前页；修改已审核资料会回到草稿等待复审 |
| 审核/反审核 | 主数据支持审核 | 资料已保存且状态满足转换；已被物料等上游主档引用时不得反审核 | 审核后允许被选择器、BOM、单据和生产链引用；反审核后禁止新引用 |
| 启用/禁用 | 主数据支持启停 | 资料已保存且有权限；已被物料等上游主档引用时不得禁用 | 禁用后不进入后续选择器；历史业务继续保留快照 |
| 导入 | 八个 A143 主数据列表且有 `master.data.manage` | 当前账套有效且导入工作区可打开 | 打开或聚焦唯一“Excel 导入”页签，并预选当前资料类型；不直接写业务资料 |
| 删除 | 物料资料页或列表危险动作 | 已保存、未审核、无任何业务引用 | 物理删除物料；已有业务引用或已审核只能禁用 |

### 主数据动作路由

- 每条已保存主数据只允许一个资料页签。页签 key 必须按“主数据类型 + 业务编码”复用，不为同一条资料同时开“查看页”和“编辑页”。
- 列表点击业务编码：打开该资料只读详情页；如果同一资料页签已打开，则只聚焦既有页签，不新开第二个页签。
- 列表点击“编辑”或只读详情页点击“编辑”：进入同一资料页签的编辑态，不新开新的编辑页。
- 列表点击“复制”：新开一个未保存草稿页签。复制只带入可维护字段，系统编号、UUID、物料编码/客户编码/供应商编码/仓库编码必须清空或重新生成。
- 新增和复制属于临时草稿页签；首次保存成功后，页签身份切换为该资料的唯一已保存页签，并继续停留在页面上，方便用户继续审核、反审核或补录。
- 保存、审核、反审核、启用、禁用都不应自动关闭页签；关闭页签只能由用户明确触发。
- 审核状态的资料默认处于不可编辑状态，保存、删除、启用/禁用按状态禁用；反审核后才恢复可维护字段和保存入口。
- 页面顶部和底部的保存/删除按钮必须复用同一套状态判断和后端接口，不能出现顶部可用、底部不可用或反向不一致。

### 基础资料导入动作

- “导入”只在物料类别、计量单位、客户、供应商、仓库、员工、账户资料和物料八个列表显示；没有 `master.data.manage` 时入口不可见，前端隐藏不能替代后端类级权限校验。
- 八个入口都打开同一个 `master-data-import` 页签；重复点击只聚焦并切换预选类型，不新增同类页签、不伪造通用列表 key 或独立 catalog 入口。
- 选择 `.xlsx` 和预检不是业务提交。预检任一行错误时“确认导入”必须禁用，但错误回执仍可下载；实际写入数固定为 0。
- “确认导入”只有服务端任务仍为 `VALIDATED`、`canConfirm=true` 且未过期时可用。点击后必须二次提示“将新增 N 条草稿，任一失败整批回滚”；前端不得自行把网络失败或旧任务推断为可确认。
- 确认期间进入 `COMMITTING`：禁止重复点击、关闭页签和切换账套。确认成功保留 `COMMITTED` 结果与创建数量，重复请求只显示同一结果。
- 已选择文件或已有未提交任务时，切换资料类型、关闭页签或切换账套必须二次确认并废弃旧文件/令牌；取消确认时页面和任务选择保持原状。
- 成功导入的资料是 `DRAFT`、`version=0`，后续审核仍使用各资料既有审核动作；导入页不得增加自动审核、覆盖、跳过错误行或部分提交按钮。
- 模板下载、预检、任务查询、错误回执和确认全部服从 `master.data.manage`，按钮可见/可用规则与 `docs/guides/master-data-import-protocol.md` 保持一致。

## 权限规则

- 第一版按钮能力先按模块权限粗粒度控制。
- 后续权限细化时，不改页面交互规则，只补权限矩阵：菜单可见、按钮可见、按钮可用、数据范围。
- 后端必须再次校验权限和状态，前端禁用只作为体验层提示。
- 所有 `/api/**` 的 `POST/PUT/PATCH/DELETE` handler 必须且只能声明一种访问语义：固定 `@RequirePermission`、按单据类型的 `@RequireDocumentPermission`、请求/资源作用域权限、已认证自助写或明确公开写。未声明写接口由后端统一返回 403，不能再按“无注解即放行”处理。
- 第一版制单与审核复用现有模块级 audit 权限；保存草稿、审核、反审核、删除、关闭、冻结等后端入口必须使用同一模块权限口径。未来如需制审分离，应另立 `.edit`/`.audit` 权限批次，不在单个页面私拆。
- 生命周期和单据锁 status/acquire 必须通过单据类型解析权限；列表 preset 的个人/角色/通用作用域必须根据当前 session 和目标资源判定，不能信任请求体中的 role/user。
- 只有登录、登出和提交找回密码申请属于公开写操作；公开找回响应不得泄露账号是否存在。员工目录、密码申请处理、角色 preset 和系统设置都不是公开接口。
