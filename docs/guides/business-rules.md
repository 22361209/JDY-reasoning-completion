# 业务规则索引

本文件记录跨页面复用的业务规则。具体实现仍放在后端 application/domain；前端只做显示、预校验和交互提示。

## 云星空业务骨架优先级

本项目理解云星空业务骨架时，优先看“核心业务对象组”，不要只盯某一张表。后续建模、排期和字段取舍按以下顺序对齐：

1. 物料主数据：`T_BD_MATERIAL`、`T_BD_MATERIAL_L`、`T_BD_MATERIALBASE`；扩展到库存、采购、销售、生产、计划、质量等业务面：`T_BD_MATERIALSTOCK`、`T_BD_MATERIALPURCHASE`、`T_BD_MATERIALSALE`、`T_BD_MATERIALPRODUCE`、`T_BD_MATERIALPLAN`、`T_BD_MATERIALQUALITY`。物料是销售、采购、库存、BOM、生产、质检、MRP 的中心。
2. BOM：`T_ENG_BOM`、`T_ENG_BOMCHILD`。BOM 是产品结构，决定成品/半成品由哪些子件构成，是生产、齐套分析、MRP 的基础。本项目第一版按“一个母件只有一个当前可用 BOM”处理；BOM 修改必须形成带版本号的历史 BOM，不允许静默覆盖历史结构。
3. 销售订单：`T_SAL_ORDER`、`T_SAL_ORDERENTRY`。销售订单是需求源，会驱动发货、出库、生产、采购、应收。但本项目第一版不把“销售订单下推生产任务”作为主路径；生产任务的主要来源是自发生产计划，绝大部分情况下不会从销售订单直接下推。
4. 库存：`T_STK_INVENTORY`、`T_STK_INVENTORYLOG`。真正判断有没有货的是库存维度余额和库存流水，不是物料表。
5. 生产计划/生产任务：`T_PRD_MO`、`T_PRD_MOENTRY`。云星空里的生产订单是生产任务主线，表示要生产什么、多少、状态走到哪一步；本项目第一版以“生产计划生成生产任务”为主路径，生产计划主要自发创建，销售订单只作为需求参考或后续扩展来源。
6. 生产用料清单：`T_PRD_PPBOM`、`T_PRD_PPBOMENTRY`。它不是标准 BOM，而是某张生产任务对应的用料快照；领料应从生产用料快照走，不应直接从标准 BOM 走。
7. 生产领料/生产入库：`T_PRD_PICKMTRL`、`T_PRD_PICKMTRLDATA`、`T_PRD_INSTOCK`、`T_PRD_INSTOCKENTRY`。这些表代表生产执行结果：材料出库、成品/半成品入库。
8. 采购申请/采购订单：采购申请是生产计划分解出的采购需求，采购订单是供应承诺，后续衔接收料、入库、应付。采购订单仍允许手工单独做，但必须支持从采购申请选源单生成。

关键建模原则：物料、BOM、销售需求、库存、生产计划、生产任务、生产用料快照、生产执行、采购供应之间必须保持清晰边界。尤其是生产领料应依据生产任务生成的用料快照，而不是运行时直接读标准 BOM，否则历史生产任务会被后续 BOM 修改污染。

本项目生产链第一版采用轻量路径：自发生产计划 → 生产任务 → 审核 → 生产领料 → 产品入库。生产完成后，如焊接件需要表面处理，再进入轻量委外表面处理流程。暂不照搬云星空完整的生产汇报、工序、派工、质检、MRP 联动等复杂链路；这些只保留扩展边界，不进入第一版主流程。

A116 起生产计划升级为生产/采购任务的统一入口：新增生产计划时由后端生成计划单号；计划分录以母件物料编码为主，自动选用该母件当前唯一可用的最新 BOM，并保存 BOM 版本号、单位、计划数量、交期和在制未完工数量。生产计划下推后，按物料默认生产车间合并生成生产任务单，按物料默认供应商合并生成采购申请单；每个车间一张生产任务单，每个供应商一张采购申请单。生产任务和采购申请都必须保留生产计划来源、母件、BOM 版本和用料/采购快照。

## 业务三层方向

本项目业务建模方向确定采用类似云星空的“三层分离”思想：**基础/标准层、业务任务/承诺层、执行结果层**。三层之间允许引用和下推，但不得混成一张表或一段临时代码直接贯穿到底。

第一层是基础/标准层，用于表达相对稳定的业务定义，不直接代表某次执行结果：

- 物料主数据：一个物料，多业务面。
- BOM：标准产品结构；每个母件只有一个当前可用 BOM，所有历史结构以 BOM 版本快照保留。
- 客户、供应商、仓库等共享主数据。
- 价格资料、报价、规则参数等后续也归入此类。

第二层是业务任务/承诺层，用于表达某次业务要做什么、承诺多少、计划何时执行：

- 销售订单、采购订单属于订单承诺层。
- 生产计划、生产任务、采购申请属于任务/需求层；采购订单属于供应承诺层。
- 生产任务审核后必须形成本任务的用料快照；快照属于任务层的一部分，负责隔离后续 BOM 变更。

第三层是执行结果层，用于表达真实业务动作和库存/资金影响：

- 销售出库、采购入库、生产领料、产品入库、其他出入库、调拨、盘点盈亏等执行单据。
- 库存流水与库存余额。
- 应收、应付、收款、付款等资金/财务结果。

关键规则：

- 执行单据不应直接读取基础标准层来决定历史执行内容；必须优先读取任务/承诺层已经固化的明细或快照。
- 生产领料不得运行时直接读取标准 BOM；必须读取生产任务用料快照。
- 销售/采购下游执行单据不得绕过源单剩余量和已审核下游业务占用规则；草稿不产生正式业务事实。
- 库存事实只由审核后的执行单据写入库存流水和余额；基础资料、BOM、生产计划、销售订单本身不直接改库存。
- 第一版允许流程轻量，但不允许层次混乱。可以少做工序、汇报、MRP、质检，但不能省掉会污染历史业务的快照/承诺边界。

## 生产与委外边界

- 生产计划只负责计划和分解，不直接领料、不直接入库、不直接做委外。
- 生产计划新增时即生成计划单号；计划分录以母件为主，自动带出当前可用 BOM 与版本号。计划下推才生成生产任务和采购申请，未下推计划不直接占库存、不直接占采购订单。
- 生产任务可以由生产计划分解生成，也可以手工单独创建；手工生产任务不得为了满足表结构而静默生成隐藏生产计划。
- 生产计划下推生产任务时，按物料默认生产车间合并；无默认生产车间的自制物料必须阻断下推并提示补全物料主档。
- 生产计划下推采购申请时，按物料默认供应商合并；无默认供应商的需采购物料必须阻断下推并提示补全物料主档。
- 生产任务审核后生成任务用料快照。后续生产领料必须选生产任务或由生产任务下推，按任务用料快照领料，不直接读取当前标准 BOM。
- 生产任务下推生产领料单；生产领料单按 BOM/任务用料快照的型号分组生成，禁止运行时重新读取当前 BOM。生产领料单审核后影响库存。
- 生产领料完成后下推产品入库单；产品入库表示生产完成结果，来源是生产任务/领料闭环。领料下推产品入库时必须追溯到对应生产任务，按生产任务未完工数量生成产品入库，不能直接拿当前 BOM 或领料行倒推成品。产品入库审核后才形成库存事实。
- 委外管理第一版只做“完工后表面处理委外”记录：来源优先为已完工/产品入库结果，也允许补录物料、数量和处理供应商；不做委外请款、不做应付、不做成本核算、不参与第一版可用库存在途口径。
- 焊接件送电泳等表面处理属于生产完成后的外部处理，不是生产任务分解，也不是生产领料的一部分。

## 单据编号

- 单据编号由后端统一生成，前端不得自行拼号。
- 取号即消耗序号；被删除、放弃或未保存的新单据编号不再复用。
- 编号格式第一版采用固定前缀 + 6 位流水号，例如 `XSDD000001`、`XSCKD000001`。
- 单据编号规则页面只做总览和单据级编辑，不允许在总览表格里直接批量改全部单据规则；用户必须点开某个单据后，才能修改该单据的前缀、流水位数、当前流水和启用状态。
- 后续新增任何正式单据页面时，必须同步注册到后端编号规则注册表，让编号规则页面显示中文单据名称并可编辑；未人工编辑时使用系统默认前缀和流水规则。

## 草稿与保存

- 点击新增生成的是未保存草稿界面；未保存草稿不应落库。
- 未保存草稿不能删除，用户可关闭页签或再次新增。
- 当前单据有未保存内容时再次新增，必须弹窗提示继续新增会放弃当前内容。
- 新增单据的分录第一行默认不预填 `CP-001` 等商品/仓库/数量/价格业务数据；带交期列的单据交期默认当天。

## 删除

- 删除只允许作用于已保存的草稿单据。
- 删除前必须有确认弹窗。
- 已审核、已反审核、已红冲、已作废、已关闭或已冻结的单据不得按草稿删除逻辑删除。
- 普通单据列表默认不显示已删除草稿。
- 当前实现删除后只保留操作日志；如需高权限查看被删除单据完整内容，应另建“已删除单据归档/回收站”能力，不从普通列表混出。

## 审核与反审核

- 保存只产生草稿，不动库存、应收应付和资金。
- 审核才触发库存、应收应付等业务影响。
- BOM、生产计划、采购申请、委外加工单等“标准/计划/任务类单据”同样遵守此规则：保存只落草稿或结构快照，只有审核后的当前可用版本/单据才允许被选源、下推、生成任务或参与后续业务链。
- 反审核必须检查下游单据，存在下游占用时阻断。
- 红冲属于高风险动作，必须二次确认并保留来源关系。非作废红字单用于防止重复创建红冲流程，并阻断来源单反审核/作废/再次红冲；只有已审核/已生效红字单才参与来源单累计红冲数量、金额和剩余可冲余量计算。

## 单据统一生命周期

正式单据生命周期以三组状态为准：主状态 `status`、关闭状态 `close_status`、冻结状态 `frozen_status`。主状态只表达保存/审核/反审核/作废/红冲；关闭和冻结只表达连续执行类单据是否还能继续下推、选源或执行。列表里的出库状态、入库状态、已执行数量、未执行数量等是执行事实或展示派生值，不得作为生命周期合法性的唯一来源。

- 主状态固定为 `DRAFT`、`AUDITED`、`VOID`、`RED_REVERSED`；`REVERSED` 只作为历史兼容/旧数据展示状态，新反审核逻辑统一回 `DRAFT`。
- 作废只允许已保存草稿，必须填写原因并用当前账号密码确认；前后端都必须按生命周期策略校验 `voidAllowed`。
- 销售订单草稿分录数量允许为 `0`、不得小于 `0`；数量为 `0` 不要求原因，也不得自动写入“零数量原因”备注。审核销售订单时每行数量必须大于 `0`，否则保持草稿并返回正式业务原因。该规则不改变单价为 `0` 的既有提醒、原因选择和备注语义，也不自动扩展到其他单据类型。
- 关闭/反关闭、冻结/解冻只适用于连续执行承诺类单据；第一版只放开销售订单、发货通知单、采购订单。
- 行关闭/行冻结只适用于同一批连续执行承诺类单据的分录行；销售订单新业务先收口为整单关闭，不再把行关闭作为员工可见动作，销售订单行关闭 API 暂禁用，`line_close_status` 字段仅暂留兼容。
- 销售订单关闭状态区分未关闭、自动关闭、手动关闭和历史已关闭。全部出库后系统自动关闭；少发且客户接受不再补发时允许手动关闭整单，未出库数量必须保留真实值；用户只允许反关闭手动关闭的销售订单。
- 销售报价单不支持关闭、冻结、红冲；它的有效/失效由报价有效期和报价有效状态控制。
- 销售出库、采购入库、生产领料、产品入库属于库存/执行事实类单据；它们支持红冲，但不支持关闭/冻结。
- 红冲不是撤销原单，而是新增一笔可审计的反向事实；红字单保存仍为草稿，审核红字单后才动账并回写来源单累计红冲。红字草稿的来源行、物料、仓库、数量、单价、金额等业务事实必须保持来源单反向一致，前端只读、后端审核兜底。
- 采购退货、其他出入库、调拨、盘点、盘盈、盘亏第一版不支持关闭/冻结/红冲；如未来确有需要必须先改生命周期协议。
- 源单和源单行必须处于已审核、未关闭、未冻结、行未关闭、行未冻结状态，才允许选源、下推或执行。未审核源单不得被下游单据使用。

详细协议见 `docs/guides/bill-lifecycle-unification-protocol.md`。后续新增正式单据时，必须同步登记后端 `BillLifecyclePolicy` 与前端 `documentLifecyclePolicy.ts`，列表和详情页不得各自维护一套生命周期判断。

## 销售报价与取价

- 销售报价单用于保存客户报价，属于价格来源，不等同真实成交记录。
- 销售报价单表头必须填写报价有效期；超过有效期后自动失效，不再参与后续销售订单“选源单”。
- 销售报价单审核后默认有效；手工“设为失效”后保留历史，但不再参与后续销售订单“选源单”。已过期报价不能只靠“设为有效”复活，必须先延长有效期并重新保存。
- 销售报价单不显示“选源单”、红冲、冻结/解冻按钮。
- 销售报价单数量允许为空或 0；报价单可只表达商品和价格。
- 销售报价单是价格承诺候选，不是默认成交价。销售订单直接录入客户和商品时，不自动取未引用报价；默认取正式价格体系/历史成交价，仍无来源时回退商品默认销售价。
- 销售订单只有通过“选源单”明确引用销售报价单、由报价单下推，或未来将报价发布为正式客户价格后，才使用报价单价格。
- 分录批量填充可以手工选择“最新有效报价”，这是明确动作，不属于静默自动取价。

## 金额与税务口径

- 单据和列表的用户可见金额字段全局采用四个固定文案：`单价`、`含税单价`、`金额`、`含税金额`。
- `单价`默认表示不含税单价；用户可见列名统一显示为`单价`，不得在各页面改成`不含税单价`。如需解释含义，只能在规则文档、帮助说明或字段说明里解释。
- `含税单价`表示单位含税价格。
- `金额`默认表示不含税金额。
- `含税金额`表示含税合计金额，是旧文案`价税合计`/`税价合计`的用户可见替代文案；代码或数据库历史字段名如`priceTaxTotal`可以保留，不做无业务收益的批量字段重命名。
- 新增销售、采购、报价、出入库、生产相关页面时，字段定义层必须优先复用这些文案，不能在单个页面自造“税价合计”“价税合计”等同义文案。

## 基础资料

- 物料资料、客户、供应商、仓库是所有单据的共享主数据，不为单个业务模块维护私有副本。
- 主数据启用/禁用只影响后续选择器和新增单据引用；历史单据继续显示原编码/名称快照或关联资料。
- 主数据新增/修改后必须先处于草稿；审核后才可被 BOM、单据、生产计划、生产任务、库存和委外流程引用。禁用和未审核都不得进入选择器引用链；历史单据继续按保存时快照显示。
- 物料资料引用的物料类别、计量单位、默认仓库、默认供应商和默认生产车间必须在后端解析为已审核、已启用主数据 UUID，同时保留用户可见编码/名称快照。前端选择器只负责体验，后端必须再次校验；被物料引用的这些主数据不得直接禁用或反审核，必须先调整引用它的物料。
- 主数据列表点击业务编码应打开该资料的只读详情页；用户点击“编辑”后才进入可修改状态。同一条已保存资料只能复用一个资料页签，查看态和编辑态是同一页签的两种状态，不得为同一资料重复开查看页和编辑页。保存、审核、反审核、启用、禁用后都停留在当前页，关闭必须由用户明确触发。主数据列表“复制”用于从选中资料新建草稿，系统编号和业务编码不得复制，其他可维护字段按当前行资料带入；复制草稿首次保存后变为该新资料的唯一已保存页签，继续留页等待审核。
- 物料删除只允许已保存、未审核、且没有任何业务引用的物料。已审核物料、已有库存/BOM/单据/任务/映射等外键引用的物料不得物理删除，只能禁用；删除前必须确认，后端必须按引用关系再次校验。
- 商品/物料不是简单商品表，而是采购、库存、生产、销售、质量、计划、委外、BOM 等业务面的中心主数据。参考材料：`/Users/linzhenyue/Projects/HW-WIN2019/k3cloud-business-rules-notes.md` 第 6 节与 `output/k3cloud_material_deep_probe.out`。
- 物料类别名称不等同业务能力；真正决定能否采购、销售、入库、生产、委外的是能力开关。第一版底层应保留“一个物料，多业务面”的模型，前台创建物料保持极简。
- 物料类别和计量单位必须独立建档，不再只靠物料表上的自由文本。物料类别第一版维护类别编码、类别名称、上级类别、排序、状态和备注；计量单位第一版维护单位名称、数量小数位、排序、状态和备注，暂不做复杂多单位换算。
- 物料资料是当前主数据建设重点。第一版按云星辰骨架但进一步收敛字段：基本信息（系统编号、物料编码、物料名称、物料类别、规格型号、计量单位、净重、毛重、表面处理）、商品特性（可销售、可采购、可库存、可自制、可委外）、价格设置（采购价、参考成本、最低销售价、税率）、库存预警（最低/安全/最高库存数量）、生产信息（默认生产车间）、其他信息（默认仓库、默认供应商）、附件（1 张 PDF 图纸、最多 5 张 PNG/JPG/JPEG 图片）。
- 当前阶段明确去掉会重复干扰录入或暂无真实业务逻辑的商品类型、OE NO.、位置、默认领料仓、发料方式、销售单位、采购单位、生产/BOM 单位和备注字段。领料默认先取物料默认仓库；如果后续需要更细的发料仓，优先放到 BOM 子件行或生产任务用料快照行，而不是物料表头。参考成本暂作参考占位，不参与库存成本核算阻断。
- 物料价格设置是物料级兜底/预警资料，不是正式客户价目表或供应商报价表。未来采购取价优先级为供应商报价/协议价，其次历史采购价，最后才取物料采购价兜底；销售取价优先级为明确引用的报价单/正式客户价目表/历史成交价，物料最低销售价只做预警或审批阈值，不应静默覆盖单据价格。单据保存时继续保留价格快照。
- 主数据采用三层标识：隐藏 UUID 主键、只读系统编号、业务编码。UUID 是数据库和程序使用的真实主键，负责表关联、权限、日志、单据引用和历史追溯；系统编号是给内部人员查账、沟通、导入映射和排障用的稳定大数字；物料编码/客户编码/供应商编码/仓库编码是给用户和业务使用的可读、可搜索编码。
- 物料、客户、供应商、仓库必须显示只读系统编号；系统编号由数据库序列生成，不允许用户手工编辑，不允许替代 UUID 外键，也不允许替代业务编码。当前编号段：物料 `100000001+`，客户 `200000001+`，供应商 `300000001+`，仓库 `400000001+`。
- 单据、BOM、库存、生产、采购、销售等底层关联必须使用 UUID 主键，不得把物料编码或系统编号当外键；前台搜索、显示、打印使用业务编码/名称。历史单据应保留物料编码、名称、规格等显示快照，避免后续物料改名或改码污染历史业务。
- 物料主档自身引用其他主数据时也遵守同一原则：`md_product.product_category_id`、`unit_id`、`default_warehouse_id`、`default_supplier_id`、`default_workshop_id` 是真实关联；`category`、`unit`、`default_warehouse_code`、`default_supplier_code`、`default_workshop` 只作为显示/搜索快照。
- 计量单位是物料资料必录属性。销售、采购、库存、生产等单据分录的单位从物料资料自动带出，单据保存时保留单位快照；历史单据不因物料后续改单位而静默变化。
- 物料资料可维护净重、毛重，均为非必填，按小数点后两位展示。单据分录根据物料自动带出净重/毛重并保存快照；物料未填写时，单据对应字段保持为空，不强制补 0。
- 客户物料编码、供应商物料编码不得覆盖内部物料编码，必须通过“物料 UUID + 客户/供应商 + 对方物料编码/名称”的映射表维护；页面可辅助显示系统编号，但关系落库仍以 UUID 为准。
- 客户订单号和客户物料编码不是同一个字段：客户订单号记录客户本次交易/行项目的外部订单依据；客户物料编码记录客户对该物料的叫法。两者必须独立保存、独立展示、独立打印，不得互相覆盖。
- 销售整单列表可展示客户编码和客户名称，销售明细视图/单据分录展示客户物料编码和客户订单号；采购整单和明细列表可展示供应商编码，采购订单分录展示供应商物料编码和预计交期，不需要客户订单号列。后续按客户/供应商物料编码录入或打印时读取映射表。
- 客户资料在应收、开票、信用控制未深入前只做轻主档：客户编码、客户名称、联系人、电话、地区、地址、状态和备注。客户等级、税号、结算方式、信用额度等后置到应收应付/信用控制批次。
- 供应商资料在应付、付款、质量准入未深入前只做轻主档：供应商编码、供应商名称、联系人、电话、地址、状态和备注。供应商等级、税号、银行账号、结算方式、付款条件、质量准入等后置。
- 仓库资料第一版只做单据引用和移仓所需字段：仓库编码、仓库名称、仓库类型、仓管员、地址、状态和备注。库存策略、库位、批号、负库存配置等高级控制暂缓；真实是否允许负库存仍由后端库存守卫最终校验。

## 库存口径

- 库存查询、可用量、审核状态和单据列表不缓存，直查数据库。
- 可用库存口径：即时库存 - 已锁库数量 + 在途；第一版在途只考虑采购在途和生产在途，暂不考虑委外在途和调拨在途。
- 生产环境不提供任何绕正式单据直接调整库存的 HTTP 能力，管理员也没有例外。库存余额和流水只能由期初库存或其他入库/出库、调拨、盘点、盘盈、盘亏、采购入库、销售出库、生产领料、产品入库等正式单据按各自规则审核后写入。
- `/api/inventory/sales-out` 与 `/api/inventory/purchase-in` 历史直写路由已删除。内部 `InventoryPostingService` 只供正式 AppService 审核过账和受控测试夹具调用，不能重新包装成生产直写 Controller。
- `/api/inventory/adjustments` 只属于本地测试/回归夹具：必须同时满足有效登录、管理员级 `system.account_set.manage`、active profile 仅为 `local/test/regression`、显式开关开启、当前账套在测试 allowlist；本项目本地回归只允许 `BLD-TEST`。默认/生产式配置为关闭和空 allowlist，任一门禁不满足时不得改变库存余额、版本或流水。
- 成本价第一版可占位，不作为阻断主链路的条件。

## 源单占用与释放

- 源单业务事实占用遵守“只有审核才生效”：下游草稿、已保存未审核单据不扣减正式可执行余量。
- 如需避免多人同时编辑同一源单行，应做编辑中提示、页签锁或临时锁；这些不等同于业务事实，不得改变正式可通知量、可下推量、可入库量。
- 下游单据反审核、作废后释放对应已审核占用；删除草稿不涉及业务事实释放。
- 已审核下游单据除占用源单选择余量外，还按各业务链条更新源单执行量、发货量或入库量；查询源单剩余量时不得把“源单累计字段”和“下游明细汇总”简单相加，避免重复扣减。
- 下游单据审核时必须按源单号和源行号汇总本单分录数量，再与源单剩余量比较。这个审核汇总校验是生命周期层规则，由 `BillLifecycleService.guardSourceLineQuantities` 统一承载；不允许某张单据绕过统一守卫或私写一套不同口径。
- 当前第一版链路口径：
  - 销售报价单 → 销售订单：销售报价单第一版作为价格承诺候选，不作为数量占用来源；销售订单明确引用报价时保存报价快照。
  - 销售订单 → 发货通知单：已审核发货通知单占用销售订单行；草稿发货通知不占用可通知量，审核时按源销售订单行汇总校验，超量则审核失败。
  - 发货通知单 → 销售出库单：已审核销售出库单占用发货通知单行；草稿销售出库不占用可出库量，审核时按源发货通知行汇总校验，超量则审核失败。
  - 生产计划 → 生产任务/采购申请：生产计划下推后，生产任务占用计划分解数量；采购申请占用计划中的需采购子件需求。
  - 采购申请 → 采购订单：已审核采购订单占用采购申请行；采购订单“选源单”按供应商过滤已审核且有剩余可订数量的采购申请明细。
  - 采购订单 → 采购入库单：已审核采购入库单占用采购订单行；草稿采购入库不占用可入库量，审核时按源采购订单行汇总校验，超量则审核失败。
  - 采购入库单 → 采购退货单：已审核采购退货单占用采购入库单行；草稿采购退货不占用可退数量，审核时按源采购入库行汇总校验，超量则审核失败。

## 采购退货与采购汇总

- 采购退货单属于采购执行结果层，来源是已审核采购入库单，不直接从采购订单退货。
- 采购退货选源单时按供应商过滤可退入库明细；可退数量 = 源采购入库行数量 - 已审核采购退货行数量。
- 采购退货草稿、未审核不占用源采购入库行可退数量；审核时按源采购入库行汇总校验，合计超出可退数量则审核失败。
- 采购退货审核扣减库存并产生负向应付/退款关系；反审核补回库存并冲回对应应付影响。
- 采购汇总表用于经营统计，只统计已审核采购订单、已审核采购入库和已审核采购退货；草稿/未审核既不参与源单业务占用，也不进入汇总经营口径。
- 采购汇总数量口径：采购数量、入库数量、退货数量、未入库数量；未入库数量 = 采购数量 - 入库数量 + 退货数量。
- 采购汇总金额口径：采购金额、入库金额、退货金额、净采购金额；净采购金额 = 入库含税金额 - 退货含税金额。

## 分录行

- 单据分录通过行内加号/减号新增和删除行。
- 底部“增加明细行”按钮废弃，不作为主交互。
- 合计金额必须等于有效分录行金额之和。
- 带交期列的单据，手工新增/插入的分录行交期默认当天；从源单带入时优先沿用源单交期，源单无交期才兜底当天。
- 只有默认交期但无商品、仓库、数量、价格、备注的分录仍按空白行处理，不参与保存校验和合计。

## 共享分录表视觉交互

- 单据内分录表必须走共享表格内核和共享表头样式，不为单个单据私改列头按钮、拖宽热区、行高和输入框密度。
- 列头筛选/批量填充按钮靠右显示，标题区必须给按钮预留空间，不能与“单价”等短标题重叠。
- 列宽拖曳热区应以列边界细线为中心，不偏入左侧或右侧单元格内部。
- 批量填充图标使用更明确的“复制/套用”语义，不使用过轻的加号小框作为唯一暗示。
- 列顺序拖拽规则走共享 `useColumnReorder`：普通业务列默认可拖；系统列、序号列、选择列、行操作列等需要稳定位置的列显式标记 `locked` 或 `reorderable: false`。以后新增业务列不要维护“哪些列可拖”的白名单，避免漏配导致新列不可拖。
- 列表表格和单据分录的列头拖拽、筛选、批量填充、列宽热区必须从共享组件继承。业务模块页以 `StandardDocument` / `EntryTable` 同层组件为准，不直接使用 `TableCore`；如果两者出现视觉差异，优先删局部覆盖或补共享层，不在单个页面单独修一套。
