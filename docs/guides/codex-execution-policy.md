# Codex 执行预算与范围控制

## 目的

项目已完成 JDY 复刻骨架，后续工作以当前 ERP 的产品完整性为主。此规则防止一个批次因全历史上下文、多代理重复验证、无关回归夹具或反复 full 门禁而扩张成无上限工作。

本文件约束执行方式，不替代 `CLAUDE.md` 的业务铁律，也不改变 `effective scope`、交付状态或回归清单的职责。

## 每个任务包必须声明

`docs/12-当前批次验收清单.md` 的 frontmatter 或任务摘要必须包含：

| 字段 | 默认上限 | 说明 |
| --- | ---: | --- |
| `timeBudgetMinutes` | 300 | 从开始实现到验收的墙钟预算 |
| `goalTokenBudget` | 15000000 | 启用 Goal 模式时使用；不把 cached/raw 计数当成新的工作量 |
| `maxCommits` | 10 | 超过后必须先复盘范围 |
| `maxConcurrentSubagents` | 3 | 受 `.codex/config.toml` 同时限制 |
| `maxTotalSubagents` | 6 | 累计创建数量，含 review worker |
| `maxFullGateRuns` | 1 | 未改动时不得重复执行 |
| `outOfScopePolicy` | `record-and-stop` | 范围外失败只登记，不顺手修复 |

任务还必须写明业务目标、允许路径、明确不做事项、目标门禁和停止条件。预算需要提高时，先给出原因、已用量和替代方案，由用户确认。

## 并行与上下文

1. 只为互不写入同一文件/数据库/迁移拓扑的工作并行。
2. 默认一个主执行者；子代理优先用于只读审计、目标测试或独立 review。
3. 委派使用最小上下文：无历史或最近 2–3 轮，加上任务摘要、相关路径和验收标准。禁止完整历史 fork。
4. 共享 registry、catalog、权限、migration、docs/config 由主执行者串行合并。
5. 子代理完成一次交付后即收束；不得用轮询、重复 follow-up 或二次 review 代替明确的验收标准。

## 测试与范围外失败

- 表现改动按 `CLAUDE.md` 运行 smoke 和人工核对；行为改动运行 smoke 加目标 area；共享核心逻辑才运行 full。
- 每阶段最多一次目标门禁；最终验收最多一次 full。因代码未变而失败的同一门禁不得反复重跑。
- 当前 diff 未引入的历史夹具失败，记录复现证据、影响和建议归属后停止，不得占用当前任务预算。
- 只有用户确认的范围扩张，才能修改任务包、允许路径、预算和验收矩阵。

## 强制停止与汇报

出现任一条件时停止继续实现：

- 已用任一预算达到 70%；
- 实际时间超过原估时两倍；
- 出现 3 个范围外失败；
- 同一任务经历 3 次上下文压缩；
- 已创建 6 个子代理或已产生 10 个提交。

汇报必须包含：完成项、未完成项、实际耗时和预算、工作区/提交状态、门禁结果、范围外失败及推荐决定。用户确认后才可扩大范围或开启下一批。

## 证据保存与文档治理

- `verification/` 是本地、ignored 的运行产物目录；它可以辅助复现，但不能单独作为已交付的唯一证据。
- 每个关闭任务在 `docs/验收报告/` 留下受版本控制的结论：范围、关键门禁、已知范围外事项和最终结论。需要长期保留的截图必须使用稳定路径，并且不包含凭据、会话原值或敏感业务数据。
- 历史任务包进入 `docs/archive/`；不要为修复现行链接或措辞批量改写历史报告、历史合同或临时产物。
- 新增、删除或重命名验收报告时，同一提交必须更新 `docs/验收报告/README.md` 的数量和文件名 hash，并运行 `node scripts/docs-governance-check.mjs`。
- 该检查只验证现行文档治理，不能替代业务、迁移、浏览器、权限或 full 回归；任务包须按改动类型选择对应门禁。

## 验收

- `AGENTS.md`、本文件和当前任务包的预算一致。
- 项目 `.codex/config.toml` 保持并发不超过 3、嵌套深度不超过 1。
- 每次交付都有独立 review、相关门禁和干净工作区。
- 历史报告与生成物保持可追溯；不因执行治理而批量重写历史。
- `node scripts/docs-governance-check.mjs` 对现行链接、当前任务/交接一致性、预算、顶层编号、历史方案标记和报告索引保持 fail-closed。
