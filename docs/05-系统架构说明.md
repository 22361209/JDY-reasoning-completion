# 系统架构说明

## 总体结构

```text
Vue 3 前端
  -> REST API
Spring Boot 模块化单体
  -> PostgreSQL
  -> Redis 仅登录态
  -> 文件存储/本地附件目录
```

第一版不引入独立 MQ、不拆微服务、不缓存业务结果。

## 后端分层

每个业务模块建议采用相同结构：

```text
controller        接收 HTTP 请求，做参数适配
application       应用服务，编排业务用例
domain            领域对象、状态机、业务规则
repository        数据访问接口
infrastructure    持久化、外部系统、文件导入导出
api               模块对外契约 DTO/接口
```

禁止把审核、库存扣减、资金回写等业务规则写在 Controller。

## 前端结构

建议目录：

```text
frontend/src
  app             应用入口、路由、布局
  modules         各业务模块页面
  components      通用表格、单据、选择器、弹窗
  services        API 客户端
  stores          登录态、页签、用户偏好
  styles          全局样式和设计变量
```

复杂表格优先选成熟组件，例如 VXE Table 或 AG Grid。不要手写一个不可维护的大表格内核。

## 数据库原则

表名前缀按模块归属：

```text
md_     基础资料
sales_  销售
pur_    采购
inv_    库存
prod_   生产
out_    委外
fin_    应收应付/资金
sys_    系统设置
```

核心业务表必须有：

- `id`
- `created_at`
- `created_by`
- `updated_at`
- `updated_by`
- `version`
- `status`

单据类表还应有：

- `bill_no`
- `bill_date`
- `audit_status`
- `audited_at`
- `audited_by`
- `source_bill_type`
- `source_bill_id`

## 未来可拆服务边界

未来如果要拆微服务，优先候选：

1. `inventory-service`：库存流水、余额、库存校验。
2. `reports-service`：复杂报表、统计、导出。
3. `mrp-service`：齐套、足缺料、物料需求建议。
4. `notification-service`：消息、预警、待办。

拆服务前必须保证模块间已经通过应用服务/接口协作，而不是跨模块直接查表改表。
