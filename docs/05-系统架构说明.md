# 系统架构说明

## 总体结构

```text
Vue 3 产品前台
  -> REST API
Spring Boot 模块化单体
  -> PostgreSQL：public 平台域 + tenant_* 业务 schema
  -> Redis：会话与平台安全门禁，不缓存业务结果
  -> 本地附件目录（按账套前缀隔离）
```

应用按单一容器部署，不按账套启动多套前后端。业务请求必须由认证后的账套上下文路由到对应的 tenant schema；平台身份、账套、授权和登录入口保留在 `public` 平台域。

## 当前多账套事实与边界

- A119 已完成 schema-first 路由：共享应用容器下，业务数据按当前账套进入独立 `tenant_*` schema；切换账套刷新工作台并清除旧业务页签上下文。
- A137 将 tenant schema 的受管表、主键、唯一约束、外键和检查约束纳入版本化同步与 fail-closed 校验；账套 schema 只能唯一登记。
- 当前不是“每账套独立 PostgreSQL database”的最终部署形态；`platform_db + tenant_* database` 是未来可单独立项的架构演进，不能写成已交付能力。
- Redis 只服务登录态和登录前平台安全门禁。库存、资金、单据状态和报表结果以数据库事务与查询为准。

完整登录前/认证后边界见 `docs/07-模块契约与边界.md`；初始化、路由和恢复说明见 `docs/guides/account-set-architecture.md`。

## 后端分层

```text
controller        HTTP、参数与响应契约
application       用例编排、事务边界、权限与生命周期协作
domain            可复用业务规则与状态判断
repository        数据访问接口
infrastructure    持久化、导入导出、外部系统和文件
api               模块对外 DTO / 接口
```

审核、反审核、库存/资金影响、编号、下推与跨模块协作不得在 Controller 复制实现。跨模块写入必须调用目标模块应用服务；展示类查询可以使用只读查询服务。

## 前端结构

```text
frontend/src
  app             应用入口、路由、布局
  modules         逐入口业务模块
  components      共享单据、列表、表格、选择器与弹窗
  services        API 客户端
  stores          登录态、页签、用户偏好
  styles          设计变量与共享样式
```

复杂表格统一走原生共享内核 `TableCore`、`EntryTable` 与标准列表/单据范式；不得新引入 VXE Table、AG Grid 或第三套表格体系，除非先新增 ADR。

## 数据库原则

表名前缀按模块归属：`md_`、`sales_`、`pur_`、`inv_`、`prod_`、`out_`、`fin_`、`sys_`。tenant 业务表的约束结构以版本化同步计划为准；平台表与 tenant 表之间只能使用明确允许的边界，不能以方便为由跨域外键或直写。

单据和库存等业务事实以事务一致性为第一原则。详见 `docs/06-数据一致性与库存原则.md`、`docs/07-模块契约与边界.md` 与 ADR-012/ADR-013。
