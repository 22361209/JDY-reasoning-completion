# 前端体验与视觉规范

本文规定正式 ERP 前台的视觉和手感标准。目标不是做营销网站，也不是后台管理页，而是接近金蝶云星辰这类高密度业务系统的产品前台。

## 总原则

- 桌面端优先，适配常见办公屏幕：`1366x768`、`1440x900`、`1920x1080`。
- 页面高密度但不拥挤，优先保证员工每天重复操作的效率。
- 不使用 Django admin、Spring Boot 管理后台、低代码后台或通用 CRUD 管理页作为正式员工入口。
- 视觉克制、清楚、稳定，不做营销页式大卡片、大留白、大渐变。
- 所有关键流程必须有首屏可见入口，不允许功能藏在开发者才知道的 URL。

## 信息架构

正式前台采用：

```text
左侧模块导航
顶部全局栏
多页签工作区
列表页 / 单据页 / 报表页 / 设置页
```

左侧模块顺序以审批范围为准：

```text
首页工作台
基础资料
销售管理
采购管理
库存管理
生产管理
委外管理
应收应付/资金
系统设置
```

## 视觉基线

### 色彩

- 主色：沉稳蓝系，用于主按钮、当前导航、重要链接。
- 辅助色：绿色用于成功，橙色用于警告，红色用于错误/阻断。
- 背景：浅灰工作区 + 白色内容区。
- 表格线、分割线使用低对比度灰色，避免满屏黑线。
- 禁止使用大面积紫蓝渐变、装饰光斑、营销式背景图。

### 字体和字号

- 中文界面使用系统字体：`-apple-system, BlinkMacSystemFont, "Segoe UI", "Microsoft YaHei", sans-serif`。
- 正文默认 `13px` 或 `14px`。
- 表格内容可使用 `13px`，但不得低于 `12px`。
- 页面标题 `20px-24px`，卡片/面板标题 `15px-16px`。
- 不使用负字距；不按视口宽度缩放字体。

### 密度

ERP 是高频操作工具，不做过度松散布局。

建议尺寸：

| 元素 | 尺寸 |
| --- | --- |
| 顶部栏 | `56px-64px` |
| 左侧导航宽度 | `220px-260px` |
| 页签高度 | `32px-36px` |
| 表格行高 | `34px-42px` |
| 主按钮高度 | `32px-36px` |
| 表单控件高度 | `32px-36px` |

## 通用页面标准

### 列表页

必须包含：

- 页面标题和当前模块路径。
- 筛选区，支持展开/收起。
- 主操作按钮，例如新增、审核、反审核、导入、导出。
- 表格区，支持分页、排序、行选择。
- 空态、加载态、错误态。
- 行点击进入详情或打开页签。

列表页验收要点：

- `1366x768` 下首屏能看到筛选区、工具栏和至少 8 行表格。
- 表格横向字段多时，必须支持横向滚动或固定关键列。
- 批量按钮必须根据行选择和权限显示可用/禁用状态。
- 查询后不能整页闪烁，局部加载即可。

### 单据页

必须包含：

- 单据标题、单据编号、状态徽标。
- 顶部动作条：保存、审核、反审核、删除、打印、导入/导出或更多。
- 表头字段区。
- 分录明细表。
- 金额/数量汇总区。
- 操作日志或状态记录入口。
- 返回列表/历史单据入口。

单据页验收要点：

- 保存和审核按钮位置稳定，不随表格滚动丢失。
- 分录表格支持新增行、删除行、商品选择器、数量输入、单位和仓库回填。
- 必填错误必须定位到字段或分录行。
- 审核后字段、按钮和状态变化必须清楚。

### 选择器

商品、客户、供应商、仓库、部门等选择器必须：

- 支持关键词搜索。
- 支持编码和名称同时展示。
- 支持键盘方向键/回车选择。
- 支持空态。
- 明确展示已选值。

商品选择器至少展示：

```text
商品编码
商品名称
规格型号
单位
可用库存（在库存相关页面）
```

### 表格

复杂表格按 `docs/04` ADR-011 走原生共享表格内核。目标不是通用后台表格，而是贴近云星辰/云星空的高密度业务表格和分录手感。

必须支持：

- 固定表头。
- 行选择。
- 横向滚动。
- 基础排序。
- 列宽调整。
- 空态。
- 键盘可操作。

后续可加：

- 列设置。
- 组合排序。
- 冻结列。
- 导出当前视图。

## 交互手感

### 多页签

- 打开列表、单据、报表时进入顶部页签。
- 同一业务对象再次打开时优先激活已有页签，不重复开多个相同详情页。
- 页签过多时支持横向滚动和关闭。
- 未保存单据关闭页签时必须确认。

### 响应速度

目标：

| 操作 | 体验目标 |
| --- | --- |
| 打开普通列表 | 1 秒内出现结构，数据可继续加载 |
| 筛选查询 | 2 秒内返回常规结果 |
| 保存单据 | 明确 loading，不允许重复提交 |
| 审核单据 | 明确执行中状态，完成后刷新状态和按钮 |
| 选择器搜索 | 输入后 300ms-500ms 内响应或显示加载 |

### 状态反馈

必须有：

- 保存成功。
- 审核成功。
- 库存不足。
- 权限不足。
- 网络/服务错误。
- 表单校验失败。
- 并发冲突或单据已被他人修改。

错误提示必须说明用户下一步能做什么，不能只显示后端异常。

## 前端验收截图

每个核心页面完成时，至少保留以下截图：

- `1366x768` 首屏。
- `1920x1080` 首屏。
- 有数据状态。
- 空数据状态。
- 校验错误状态。
- 审核/保存后的状态变化。

截图放到后续工程的 `docs/screenshots/` 或测试报告目录，并在验收报告中引用。

## 不合格例子

- 只有后端接口，没有员工可用页面。
- 页面像后台表单堆叠，没有多页签和业务工具栏。
- 表格字段溢出、按钮文字被挤压、低分辨率下关键按钮不可见。
- 库存、审核、保存没有明确状态反馈。
- 操作失败只弹 `error` 或后端堆栈。
- 功能只能通过直接输入 URL 使用。
