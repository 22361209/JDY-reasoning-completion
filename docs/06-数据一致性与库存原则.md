# 数据一致性与库存原则

ERP 的核心风险不在页面，而在库存、资金和单据状态是否可信。本文是底线约束。

## 缓存原则

第一版只缓存登录态，不缓存业务结果。

库存、资金、单据状态、报表查询默认直接查数据库。后续如需加速，只能通过余额表、汇总表、索引、物化视图或异步统计解决，不能用普通缓存替代真实库存。

## 库存模型

库存至少分两类表：

```text
inv_stock_balance
inv_stock_txn
```

`inv_stock_balance` 记录当前余额，建议维度：

```text
product_id
warehouse_id
qty_on_hand
qty_available
qty_reserved
version
```

`inv_stock_txn` 记录每次库存变动：

```text
txn_type
product_id
warehouse_id
qty_delta
source_bill_type
source_bill_id
source_bill_line_id
occurred_at
```

## 第一版金额口径：库存只记数量

第一版库存只记数量，不做成本核算，理由是出库成本核算、生产成本核算、BOM 成本查询均已后置。

约束：

- `inv_stock_balance` 和 `inv_stock_txn` 的库存校验、扣减、回补只基于数量字段，不依赖任何金额。
- 余额表和流水表可以预留 `unit_cost`、`amount` 等成本字段，但第一版一律留空（NULL），不参与任何计算、单据金额或报表。
- 应收应付、收付款等资金金额来自销售/采购单据自身的价税金额，与库存成本无关，不受本约束影响。
- 待后续启用成本核算时，再决定成本字段的回填口径（移动加权 / 标准价等），届时需要数据迁移补算历史流水成本，不在第一版范围内。

## 出库和领料校验

出库、领料、调拨出库必须在数据库事务内校验库存。

示例原则：

```sql
UPDATE inv_stock_balance
SET qty_on_hand = qty_on_hand - :qty,
    qty_available = qty_available - :qty,
    version = version + 1
WHERE product_id = :product_id
  AND warehouse_id = :warehouse_id
  AND qty_available >= :qty;
```

如果更新行数为 0，表示库存不足或并发冲突，审核失败。

## 单据审核原则

第一版审核模型固定为单人直接审核，没有多级审批流：

- 单据状态机只有“草稿/未审核 -> 已审核 -> 已反审核”这一条主线，由有权限的人一步审核生效。
- 审核动作直接触发库存和资金影响，不经过审批流引擎，不挂多级节点。
- 单据状态机和审核逻辑不得依赖审批流引擎；未来接入多级审批流时，审批流只在“未审核 -> 已审核”之前增加前置流程，不改动现有状态机和库存/资金动作。

单据保存只产生草稿/未审核数据，不影响库存和资金。

单据审核才产生业务影响：

- 销售出库审核：扣库存，产生应收。
- 销售退货审核：回补库存，产生退款/冲应收关系。
- 采购入库审核：增库存，产生应付。
- 采购退货审核：扣库存，产生退款/冲应付关系。
- 生产领料审核：扣材料库存。
- 产品入库审核：增成品库存。
- 其他入库/出库审核：增减库存。

反审核必须检查下游单据和库存/资金影响，不能简单改状态。

## 并发原则

同一商品同一仓库的库存扣减必须通过数据库事务和行级约束保证，不能只靠前端提示。

同一单据审核动作必须防重复提交：

- 使用单据状态校验。
- 使用乐观锁 `version`。
- 关键动作可使用幂等键。

## 审计原则

所有影响库存、资金、状态的动作必须写操作日志：

- 谁操作
- 什么时候
- 操作对象
- 操作前状态
- 操作后状态
- 失败原因
